## 3. 任务详解

### T1 · 布局 v3 与版本协商

**红（先写失败测试）**

| 用例 | 断言 |
|---|---|
| `LayoutV3.PartitionFieldAt120` | `offsetof(indurtdb_point_t, partition) == 120` |
| `LayoutV3.SizeStill128` | `sizeof(indurtdb_point_t) == 128` |
| `LayoutV3.ExistingOffsetsUnchanged` | `name`@45 / `quality`@41 / `source_timestamp_ns`@112 逐字节不变 |
| `LayoutV3.DefaultPartitionZero` | 新建 / 配置加载的点位 `partition == 0` |
| `LayoutV3.RejectsV2Segment` | 挂载 `IRT_SHM_VERSION == 2` 的旧段**返回明确错误码**，不静默按新布局解释 |
| `HeaderV3.VersionIs3` | 新建段 `header->version == 3` |

**绿**：`reserved[0:4)` 更名为 `uint32 partition`（`reserved[4:8)` 保留）；`IRT_SHM_VERSION` 2 → 3；attach 时版本不匹配即拒绝。

**重构**：版本常量与协商逻辑集中到 `irt_layout_*()` / attach 校验处，禁止各处硬编码 `3`。

**验收**：`IRT_STATIC_ASSERT` 全绿（含 `sizeof == 128` 与全部 `offsetof`）；零警告；既有测试除「版本相关」外无回归。

### T2 · 分区化 name→id 索引

**红**

| 用例 | 断言 |
|---|---|
| `Index.SameNameDifferentPartition` | `create(0,"temp")` 与 `create(1,"temp")` 各得**不同** `point_id`，均可查到 |
| `Index.FindScopedToPartition` | `find(1,"temp")` 只解析到分区 1 的点；对分区 2 查 `"temp"` 返回 `INDURTDB_ERR_NOT_FOUND` |
| `Index.Partition0MatchesV38Semantics` | 分区 0 下注册/查找结果与 v3.8 语义一致 |
| `Index.HandlesHashCollisionAcrossPartitions` | 构造跨分区同哈希名，全部可查到 |
| `Index.FullLoadNoInfiniteProbe` | 负载打满时查找在有限步内终止（不死循环） |

**绿**：哈希输入改为 `FNV1a32(partition_le32 ‖ name)` **+ 2 步尾混**（尾混是 T2 实测修正：无尾混时负载 0.5 平均探测 0.660 / 最长 17，有尾混 0.461 / 8，理想随机基线 0.465 / 9 —— 详见方案 §3.2「尾混不可省」）；冲突比较**同时比对 `partition` 与 `name[64]`**；`irt_index_lookup/insert/remove[_locked]` 追加 `uint32 partition` 参数。槽结构（8B）与桶数公式**不变**。

**重构**：分区与 name 的复合键构造抽公共函数（`irt_index_compose_hash`）与冲突比较抽内联（`irt_index_slot_matches`），避免散落。

**验收**：负载因子 ≤0.5 时有实测冲突率数据；全量回归绿。

**T2 实施记录**

- **尾混修正**：见上「绿」与方案 §3.2。绕不过去——首版按原样的前缀式实现，`Index.ProbeStatsAtHalfLoad` 直接以最长探测 17 超限失败。
- **发现并修复既有缺陷（delete 索引槽泄漏）**：`indurtdb_h_delete_point` 原序为「先清 `p->name[0]='\0'` → 再 `irt_index_remove_locked(old)`」，而 `remove_locked` 用「槽指向点位的 `name`」判等 → 注销**静默失败**，索引槽永不置墓碑、`index_count` 虚高，最终 `insert` 提前返回 `FULL`（实测第 17 轮注册即失败，桶数 16）。已改为**先注销再清名**（全程持写锁，原子）。该缺陷此前**无任何用例覆盖**，已补 `ApiV2.DeleteReleasesIndexSlot`（红/绿均已验证：注入反序后第 16 轮报 `-3 (FULL)`，恢复后 7/7 绿）。
- **补既有路径覆盖**：`ApiV2.DeleteReleasesIndexSlot` / `ApiV2.RenameReleasesOldSlot`（原 `test_c_api_v2.cpp` 仅覆盖 open/close/find_by_name，句柄级 CRUD 完全无覆盖）。
- **Python 镜像同步**（否则迁移段整体查不到）：`tools/irt_migrate/irt_migrate/layout.py` 新增 `read_point_partition` / `compose_hash`，`name_eq` / `build_index` / `index_probe` 改为分区感知；`test_c_migration` 的 `V1ToV3RoundTrip` 正是因该漂移先红后绿。
- **契约锚点**：两侧钉同一组黄金哈希值（含 `""` 与高位分区 65535 / 65536 / 16777216 / 2³²-1），任一侧改动立即变红。
- **未纳入本任务**：`partition` 尚无对外 API（T4 提供）；`rename` 不换分区（分区固定，见方案 §3.2）。

### T3 · 策略分区限定（显式 4 段 + `*` 分区通配）

**红**

| 用例 | 断言 |
|---|---|
| `Policy.WildcardPartitionAllowed` | `<uid>:*:<min>:<max>` 对任意分区放行（区间内） |
| `Policy.PartitionScopedAllowDeny` | `<uid>:<1>:<min>:<max>` 对分区 1 放行、对分区 2 拒绝 |
| `Policy.DenyByDefault` | 未匹配任何规则仍一律拒绝 |
| `Policy.MalformedLineRejected` | 段数非法/数值非法即 fail-fast（带行号），不静默忽略 |

**绿**：行格式统一为显式 4 段 `<uid>:<partition|*>:<min_id>:<max_id>`，第 2 段 `*` 为全分区通配；判定顺序 uid → 分区 → id 区间；加载失败返回 `IRT_POLICY_ERR_*` + 行号，`rtdbd` 以 `RTDBD_EXIT_CONFIG`(2) 终止。

**重构**：行解析（分段计数 / 逐字段校验）与授权判定分离；分区通配用**显式标志位** `wildcard_partition`（区分「分区 0」与「全分区」）。`IRT_POLICY_LINE_MAX` / `IRT_POLICY_MAX_RULES` 约束维持。

**验收**：`tests/unit/test_c_policy.cpp`（直接编译 `rtdbd/src/policy.c`）四红用例绿；非法 policy 经 rtdbd 退出码 2（`RtdbdConfig.PolicyMalformedExits2`）；全量回归绿、零告警；API 计数仍 112（策略引擎非公开 API）。

**T3 实施记录**

- **格式定案改为显式 4 段**（见方案 §3.3 裁定）：确认策略**无存量部署**后，放弃「按段数多态」，改为单一语法 + `*` 通配。旧 3 段写法**被拒绝**（红用例 `Policy.ThreeFieldNowRejected`）——连带把仓库内全部旧格式来源同步为 4 段：**10 个集成测试**的 policy 生成器（`%lu:0:63` → `%lu:*:0:63`）、官方样例 `config/rtdbd/policy.conf`、`config/rtdbd/README.md`、`scripts/verify_deploy.sh`、`docs/07-部署运维/*`。
- **退出码修正**：`irt_policy_load` 失败原 `return 1`；改为 `RTDBD_EXIT_CONFIG`(2)。这不是「对上语义」而已——supervisor/systemd 仅对致命码 2/4 停止 respawn，退出码 1 会让坏策略触发**无限重启循环**。
- **解析器重写**：弃用 `sscanf`（会忽略行尾多余字段、无法可靠区分段数），改为显式按 `:` 分段计数 + 逐字段「非空 / 纯十进制 / 不溢出 uint32」校验；各段首尾空白忽略（与旧 `sscanf` 容忍度一致，避免无谓回归）。
- **行超长必须在去注释前判定**：否则被 `fgets` 截断的残段会被当作下一行解析、产生错位行号；检测到即吞掉本行剩余字节。**超长的纯注释行容忍**（中文注释按字节计，避免把运维注释头拖死）。
- **`extern "C"` 守卫**：`policy.h` 增补 C++ 链接守卫，否则 C++ 单测按 C++ 名修饰查找 C 符号而链接失败（实测踩到）。
- **测试落点**：策略是纯逻辑叶子模块 → 引擎四红用例放**单元测试**（`tests/unit/test_c_policy.cpp`，直接编译 `policy.c`，快且确定）；唯一需真进程的「退出码 2」放**集成测试**（`test_rtdbd_config.cpp`，复用其 `run_rtdbd`/`drop_segment` 助手）。未新建 `test_rtdbd_policy.cpp`——集成层放行路径已由既有 9 个写路径测试（改用 `*` 策略后）覆盖，另建文件属重复。
- **未纳入本任务**：`rtdbd` 的 5 个 `irt_policy_allows` 调用点暂固定传分区 `0u`；真正的分区值随**协议 v3** 由 T5 引入。

### T4 · API 分区重载族 + 句柄便捷 + 门禁同步

**红**

| 用例 | 断言 |
|---|---|
| `ApiV39.DefaultPartitionMatchesLegacy` | `h_find_by_name(h,"temp")` 与 v3.8 语义等价（分区 0） |
| `ApiV39.FindByNameInExplicitPartition` | `h_find_by_name_in(h,1,"temp",&id)` 解析到分区 1 |
| `ApiV39.HandleSetPartitionAffectsDefaults` | `h_set_partition(h,1)` 后，不显式传分区的名称域调用默认落在分区 1 |
| `ApiV39.ExplicitOverridesHandleDefault` | 显式形参优先于句柄默认值 |
| `ApiV39.CreateRenameDeleteScoped` | 注册/重命名/删除可限定分区（且分区创建后固定、不可移动） |
| `Gate.ApiCountMatches` | `scripts/check_api_count.py` 基准与实际导出一致 |

**绿**：新增显式分区形参族（名称域：`find_by_name_in` / `create_point_in` / `rename_point_in` / `delete_point_in`；`list` 加分区过滤）；`indurtdb_h_set_partition(h, n)`；既有函数保留为 `_in(h, 0, …)` 薄封装。**同一 commit 更新 `scripts/check_api_count.py` 与 SDK 手册计数。**

**重构**：分区默认值收敛到句柄状态（单处读取），显式/默认优先级集中实现。

**验收**：**API 计数门禁在 CI 首步绿**；旧调用零改动；零警告。

**T4 实施记录**

- **「薄封装 `_in(h,0,…)`」与 `HandleSetPartitionAffectsDefaults` 自相矛盾，按句柄默认值收口**：规划正文说既有函数保留为 `_in(h, 0, …)` 薄封装，但又要求 `set_partition(h,1)` 后**非显式**调用默认落分区 1 —— 字面 `_in(h,0,…)` 无法满足后者。裁定：**默认值跟随句柄状态**——`struct indurtdb` 新增 `uint32_t default_partition`（初始化路径 `inst_init` 显式置 0，`inst_shutdown` 的 `memset` 关闭时复位）；新增私有单处读取点 `h_default_partition(h)`；四个旧签名函数改为委托 `_in(h, h_default_partition(h), …)`。因默认初值为 0，v3.8 语义逐位等价（用例 `ApiV39.DefaultPartitionMatchesLegacy` + `ApiV39.ExplicitOverridesHandleDefault` 双证）。
- **修复复用槽位继承旧分区缺陷（`h_point_register`）**：原 `h_point_register` 只写 type/access/unit/quality/value/name，**不写 `p->partition`**；当 `create` 复用曾被其它分区占用的空槽时，点位的 `partition` 可能残留前一占用者的值，与 `(partition,name)` 索引键不一致。已改为 `h_point_register(shm, partition, id, …)` 并写入 `p->partition = partition`。**调用方清点**：全仓仅 create 路径调用（`load_config` 走自身的行内写入块，不经 `h_point_register`）——已在该行内块显式补 `p->partition = 0u`，配置点位固定落分区 0（base 配置无分区字段，不随句柄默认值）。
- **`set_partition` 只设不做 getter**：按规划仅提供 `indurtdb_h_set_partition`（无 `get_partition`）；任意 `uint32_t` 合法（Q8 无分区表）；复位即 `set_partition(h,0)`。
- **重名域随分区闭合**：`create_point_in` / `rename_point_in` 的重名检查改为 `(partition, name)` 限定 → 同名可跨分区共存；`delete_point_in` / `rename_point_in` 在点位分区与形参不符时返回 `INDURTDB_ERR_NOT_FOUND` 且**不改动任何状态**（分区创建后固定、不可移动，Q9）。delete 保持「先 `irt_index_remove_locked` 再清 `p->name`」的既有关键次序（回归用例 `ApiV2.DeleteReleasesIndexSlot` 守门）。
- **delta 回放固定分区 0**：`delta_apply` 改调显式 `_in(h, 0u, …)` 变体，使回放不受句柄默认分区影响。**保真缺口（T4 范围外，一行记录）**：delta 记录**无 partition 字段**，故分区 >0 的运行时 CRUD 经回放会落回分区 0 —— 本任务不改变 delta 记录格式/`IRT_DELTA_OP_*`，缺口留待后续版本处理。
- **范围注记**：T4 绿中「`list` 加分区过滤」指 `rtdbd` 的 `RTDBD_OP_LIST` / `do_list`（C 库**无任何列举 API**），已归 **T5**（`ProtoV3.ListFilteredByPartition`），**T4 不引入新列举 API**。
- **门禁同步（同一 commit）**：`scripts/check_api_count.py` 期望 v1=62 / v2=**55** / total=**117**；`tests/unit/CMakeLists.txt` 新增 CTest `Gate.ApiCountMatches`（用 CMake 找到的 Python 解释器跑门禁脚本，找不到解释器则禁用而非误报红）；SDK 手册首段与清单同步（并修正两处陈旧计数：47→62、43→55）。实测门禁在实现前对 v2=55 报红、同步后转绿。

## 7. T5 实施记录

### 7.1 结构体追加策略与尺寸裁定
- **追加在末尾**（保持既有字段偏移不变）：
  - `rtdbd_find_req_t`   64 → **68**  (`partition` @64)
  - `rtdbd_create_req_t` 72 → **76**  (`partition` @72)
  - `rtdbd_rename_req_t` 68 → **72**  (`partition` @68)
  - `rtdbd_delete_req_t`  4 → **8**   (`partition` @4)
  - `rtdbd_list_req_t`    8 → **12**  (`partition` @8)
  - `rtdbd_point_info_t` 72 → **76**  (`partition` @72)
- **审计条目填空洞**：`rtdbd_audit_entry_t` 原 `sizeof` 24（`point_id`@8 后有 4B 空洞，`ts_ns`@16 8 字节对齐）。新布局 `{pid, uid, point_id, partition, ts_ns}` 恰好填补空洞，**尺寸仍 24**，`ts_ns` 仍 @16。修正了文件头残留的 "20B" 注释，静态断言改为 24B。

### 7.2 协议常量
- `RTDBD_PROTO_VERSION` 2 → **3**；v2 客户端按 magic/version 不匹配直接断连（不发响应），沿用 `ProtoV2.RejectsV1Client` 先例。
- `RTDBD_OP_SELECT = 17u`（紧随 `OP_HEALTH=16`）。
- `RTDBD_PARTITION_ALL = 0xFFFFFFFFu` 作为 `OP_LIST` 的“全分区”哨兵。

### 7.3 白名单语义（fail-closed）
- `partitions` 缺省或空列表 ⇒ 任意分区值合法（v3.8 等价宽松）。
- 非空白名单 ⇒ 不在表内的分区值非法：
  - `OP_SELECT` / `CREATE` / `RENAME` / `DELETE` / `WRITE` / `SET_META` → `DENIED`（不改连接状态）。
  - `OP_FIND_BY_NAME` → `NOT_FOUND`（不泄露命名空间存在性）。
  - `OP_LIST` 指定该分区 → 空结果（`OK` + 0 条目）；`PARTITION_ALL` 哨兵不受白名单限制。
- `partition_alias` 仅解析校验（键须在白名单内），T5 无协议面，留待 T7 监控台展示。

### 7.4 `rtdbd` 迁移到句柄 API（`indurtdb_h_*`）
- 启动：`indurtdb_h_open(&g_h, instance, &cfg)` 替代 `indurtdb_initialize`。
- 关闭：`indurtdb_h_close(g_h)` 替代 `indurtdb_shutdown()`（保留段语义不变）。
- 配置加载：`indurtdb_h_load_config(g_h, path)`。
- 热路径库调用全部改用句柄版：`indurtdb_h_read_point` / `indurtdb_h_get_meta` / `indurtdb_h_set_meta` / `indurtdb_h_write_quality_ts`。
- 纯函数 `indurtdb_value_to_double` / `indurtdb_eurange_limit` / `indurtdb_get_last_error` 保持不变（无实例绑定）。

### 7.5 连接上下文与分发表重构
- `rtdbd_conn_t` 新增 `uint32_t partition`（`conn_init` 置 0）。
- 引入 `rtdbd_ctx_t` 聚合 `{h, policy, audit, conn, conns, nconns, conf, req, resp}`。
- 静态分发表 `kOps[]` 替代原 `if (opcode==…)` 链，**纯机械重构**：每个 `op_*` 的响应状态/负载/发送顺序与原实现逐字保持，对外契约不变；语义改动仅在新增分区维度处。
- 公共序言不变：读 12B 头 → magic/version 校验（不匹配 `decode_fail++`、关连接、不回包） → 零初响应头并置 magic/version。

### 7.6 各 opcode 分区语义
| Opcode | 分区来源 | 鉴权/白名单 | 审计 partition |
|--------|----------|-------------|----------------|
| `OP_SELECT` | 请求负载（4B） | 白名单 → `DENIED` 不改连接 | — |
| `OP_FIND_BY_NAME` | 请求 `f.partition` | 白名单 → `NOT_FOUND` | — |
| `OP_CREATE_POINT` | 请求 `c.partition` | policy(uid, partition, id) + 白名单 | `c.partition` |
| `OP_DELETE_POINT` | 请求 `d.partition` | policy + 白名单 | `d.partition` |
| `OP_RENAME_POINT` | 请求 `r.partition` | policy + 白名单 | `r.partition` |
| `OP_WRITE` | `conn->partition`（连接默认） | policy + 白名单 | `conn->partition` |
| `OP_SET_META` | `conn->partition` | policy + 白名单 | `conn->partition` |
| `OP_LIST` | 请求 `l.partition`（`ALL`=全部分区） | 白名单（具体分区非法→空结果） | 响应项 `e->partition = pt.partition` |

### 7.7 配置解析留在 rtdbd 侧
