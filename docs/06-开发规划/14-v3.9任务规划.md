## 3. 任务详解

### T1 · 布局 v3 与版本协商

**红（先写失败测试）**

| 用例 | 断言 |
|---|---|
| `LayoutV3.PartitionFieldAt120` | `offsetof(indurtdb_point_t, partition) == 120` |
| `LayoutV3.SizeStill128` | `sizeof(indurtdb_point_t) == 128` |
| `LayoutV3.ExistingOffsetsUnchanged` | `name`@45 / `quality`@41 / `source_timestamp_ns`@112 逐字节不变 |
| `LayoutV3.DefaultPartitionZero` | 新建 / 配置加载的点位 `partition == 0` |
| `LayoutV3.RejectsV2Segment` | 挂载 `IRT_SHM_VERSION == 2` 的旧段**返回明确错误码**，不静默按新布局解释 |
| `HeaderV3.VersionIs3` | 新建段 `header->version == 3` |

**绿**：`reserved[0:4)` 更名为 `uint32 partition`（`reserved[4:8)` 保留）；`IRT_SHM_VERSION` 2 → 3；attach 时版本不匹配即拒绝。

**重构**：版本常量与协商逻辑集中到 `irt_layout_*()` / attach 校验处，禁止各处硬编码 `3`。

**验收**：`IRT_STATIC_ASSERT` 全绿（含 `sizeof == 128` 与全部 `offsetof`）；零警告；既有测试除「版本相关」外无回归。

### T2 · 分区化 name→id 索引

**红**

| 用例 | 断言 |
|---|---|
| `Index.SameNameDifferentPartition` | `create(0,"temp")` 与 `create(1,"temp")` 各得**不同** `point_id`，均可查到 |
| `Index.FindScopedToPartition` | `find(1,"temp")` 只解析到分区 1 的点；对分区 2 查 `"temp"` 返回 `INDURTDB_ERR_NOT_FOUND` |
| `Index.Partition0MatchesV38Semantics` | 分区 0 下注册/查找结果与 v3.8 语义一致 |
| `Index.HandlesHashCollisionAcrossPartitions` | 构造跨分区同哈希名，全部可查到 |
| `Index.FullLoadNoInfiniteProbe` | 负载打满时查找在有限步内终止（不死循环） |

**绿**：哈希输入改为 `FNV1a32(partition_le32 ‖ name)`；冲突比较**同时比对 `partition` 与 `name[64]`**；`irt_index_lookup/insert/remove[_locked]` 追加 `uint32 partition` 参数。槽结构（8B）与桶数公式**不变**。

**重构**：分区与 name 的复合键构造抽公共函数（`irt_index_compose_hash`）与冲突比较抽内联（`irt_index_slot_matches`），避免散落。

**验收**：负载因子 ≤0.5 时有实测冲突率数据；全量回归绿。

### T3 · 策略分区限定（3/4 段兼容）

**红**

| 用例 | 断言 |
|---|---|
| `Policy.ThreeFieldStillWorks` | 既有 `<uid>:<min>:<max>` 行**原样生效**，作用于所有分区 |
| `Policy.FourFieldPartitionScoped` | `<uid>:<1>:<min>:<max>` 对分区 1 放行、对分区 2 拒绝 |
| `Policy.DenyByDefaultUnchanged` | 未匹配任何规则仍一律拒绝 |
| `Policy.MalformedLineRejected` | 段数非法/数值非法即 fail-fast（退出码 2），不静默忽略 |

**绿**：按**冒号分段计数**判别 3 段（区通配）与 4 段（分区限定）；判定顺序 uid → 分区 → id 区间。

**重构**：行解析与授权判定分离；分段解析集中，`IRT_POLICY_LINE_MAX` / `IRT_POLICY_MAX_RULES` 约束维持。

**验收**：既有 3 段配置**零改动**生效；4 段用例覆盖放行/拒绝两侧；fail-fast 用例绿。

### T4 · API 分区重载族 + 句柄便捷 + 门禁同步

**红**

| 用例 | 断言 |
|---|---|
| `ApiV39.DefaultPartitionMatchesLegacy` | `h_find_by_name(h,"temp")` 与 v3.8 语义等价（分区 0） |
| `ApiV39.FindByNameInExplicitPartition` | `h_find_by_name_in(h,1,"temp",&id)` 解析到分区 1 |
| `ApiV39.HandleSetPartitionAffectsDefaults` | `h_set_partition(h,1)` 后，不显式传分区的名称域调用默认落在分区 1 |
| `ApiV39.ExplicitOverridesHandleDefault` | 显式形参优先于句柄默认值 |
| `ApiV39.CreateRenameDeleteScoped` | 注册/重命名/删除可限定分区（且分区创建后固定、不可移动） |
| `Gate.ApiCountMatches` | `scripts/check_api_count.py` 基准与实际导出一致 |

**绿**：新增显式分区形参族（名称域：`find_by_name_in` / `create_point_in` / `rename_point_in` / `delete_point_in`；`list` 加分区过滤）；`indurtdb_h_set_partition(h, n)`；既有函数保留为 `_in(h, 0, …)` 薄封装。**同一 commit 更新 `scripts/check_api_count.py` 与 SDK 手册计数。**

**重构**：分区默认值收敛到句柄状态（单处读取），显式/默认优先级集中实现。

**验收**：**API 计数门禁在 CI 首步绿**；旧调用零改动；零警告。

### T5 · 协议 v3 与 `rtdbd`

**红**

| 用例 | 断言 |
|---|---|
| `ProtoV3.FindByNameWithPartition` | 经服务端按（分区, 名）查到 id |
| `ProtoV3.ListFilteredByPartition` | `LIST(partition)` 只返回该分区点位 |
| `ProtoV3.ListItemIncludesPartition` | `POINT_INFO` 含 `partition` 字段 |
| `ProtoV3.SelectSetsConnectionDefault` | `OP_SELECT` 后本连接默认分区生效 |
| `ProtoV3.RejectsV2Client` | 协议版本不匹配即断连（不静默） |
| `ProtoV3.PolicyPartitionScoped` | 管控写按（uid, 分区, id 区间）鉴权 |
| `ProtoV3.AuditRecordsPartition` | 审计记录含 `partition` |

**绿**：`RTDBD_PROTO_VERSION` 2 → 3；`OP_FIND_BY_NAME / CREATE_POINT / RENAME_POINT / DELETE_POINT / LIST` 请求体加 `uint32 partition`；`LIST` 响应 `POINT_INFO` 加 `partition`；新增 `OP_SELECT`；审计加 `partition`；`rtdbd` 配置支持可选 `partitions` 白名单与 `partition_alias`。

**重构**：opcode 分派表化（若尚未），新增操作不改核心循环；连接级分区状态封装进连接上下文。

**验收**：端到端按分区查找与列举走通；鉴权/审计用例绿。

### T6 · `irtcli` 分区支持

**红**

| 用例 | 断言 |
|---|---|
| `Cli.PartitionFlag` | `irtcli --partition 1 find temp` 解析到分区 1 |
| `Cli.SelectCommand` | `irtcli select 1` 后续命令默认落分区 1 |
| `Cli.ListPartitionFilter` | `irtcli --partition 1 list` 只列分区 1 |

**绿**：全局/命令级 `--partition N` + `select N` 子命令；与协议 v3 对齐。

**验收**：CLI 端到端用例绿；`--help` 反映新参数。

### T7 · 监控台 `partitions` 视图

**红**

| 用例 | 断言 |
|---|---|
| `Monitor.PartitionsEndpoint` | `GET /api/partitions` 返回分区列表 |
| `Monitor.PointsFilteredByPartition` | `GET /api/points?partition=1` 只返回分区 1 |
| `Monitor.ViewRenders` | 分区下拉切换后点位表随分区刷新 |

**绿**：落地已注册的 `partitions` 占位视图（`App.vue`/`api.js`）；后端 `app.py`/`rtdb_client.py` 暴露分区端点与过滤。

**验收**：前端可用 + **截图留档**；与协议 v3 契约一致。

### T8 · 迁移工具 v2→v3 与 Python 镜像同步

**红**

| 用例 | 断言 |
|---|---|
| `Migrate.V2ToV3PreservesPoints` | 点位值 / 类型 / 质量 / 时间戳 / name / `source_ts` 全量一致 |
| `Migrate.PartitionSetToZero` | 迁移后全部 `partition == 0`（默认分区） |
| `Migrate.ChecksumVerification` | 迁移前后校验（点数 / CRC / 抽样比对），不一致即报错 |
| `Migrate.RefusesWrongSourceVersion` | 源段不是 v2 时拒绝执行 |
| `Mirror.PythonLayoutMatches` | `irt_migrate/layout.py` 与 `rtdb_client.py` 的点位/协议结构与 C 侧一致（含 `partition`） |

**绿**：`tools/irt_migrate` 扩展 v2→v3（重建索引与 CRC、`partition := 0`）；同步 `irt_migrate/layout.py`（新增 `PARTITION_OFFSET=120`）、`rtdb-monitor/rtdb_client.py`（协议 v3 结构）、`irt_diag` 巡检。

**重构**：迁移逻辑与校验逻辑解耦（沿用 v3.4 Q4 裁定）。

**验收**：迁移 + 校验 + **回退演练**（重新部署 v3.8 + 清理段）全流程跑通并留记录。

## 6. 实施中需确认的问题

1. **API 计数门禁新基线**：T4 新增函数后 `check_api_count.py` 的期望值（62+N / 50+M）——须在 T4 首次提交时一并确定并登记。
2. `rtdbd` 配置键名与语义：`partitions` 白名单（为空=任意值合法）与 `partition_alias` 映射的键名、类型、校验失败退出码。
3. `OP_SELECT` 连接级默认分区的**生命周期**：连接断开即清；是否允许运行中改（允许，无持久化）。
4. 监控台分区列表来源：扫描点位区推导 vs 配置声明——倾向「扫描推导 + 配置别名覆盖显示名」。
5. 迁移工具是否需支持「只迁指定分区区间」（当前 v2 段无分区，实际无意义；记录为 n/a）。
6. `irt_diag` 巡检是否需新增按分区统计输出（低优先，可延后）。
