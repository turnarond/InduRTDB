# InduRTDB 产品化交付 实现计划

**版本：1.0**

**状态：已完成 (全部 5 任务已交付并合并 main)**
**分支：feature/v3.1-productization (已合并)**

> For agentic workers: 使用 superpowers:subagent-driven-development 逐任务实现。步骤用 `- [ ]` 复选框跟踪。

**Goal:** 交付 5 项短期产品化能力：CI 流水线、soak+故障注入测试、性能基准（x86）、测试覆盖强化、定位与边界文档。

**Architecture:** 均为围绕既有纯 C 核心库的外围交付物（测试/脚本/CI/文档），不改动共享内存布局与核心 API；性能基准与 soak 为新增独立程序/脚本。

**Tech Stack:** C11（bench）、C++17+gtest（测试）、Bash（soak/故障注入）、GitHub Actions（CI）。

## Global Constraints

- 库为纯 C11，`-Wall -Wextra -Werror` 零警告；测试 C++17+gtest。
- 注释/文档/提交信息用中文；提交遵循 conventional commits。
- 共享内存布局（128B/64B/16B、magic、shm version）与核心 API 不得改动。
- 遵循 TDD 红-绿-重构；每任务独立 commit；文档同步（规则 2）。
- 测试经 `ctest` 注册可被 CI 复用；脚本可独立运行。

### Task 2: soak 长时稳定性 + 故障注入测试

**Files:**
- Create: `tests/soak/soak_test.c`（持续读写 N 分钟，校验一致性/统计）

- Create: `scripts/run_soak.sh`（封装：编译+运行+断言，默认时长可配）

**Interfaces:**
- Consumes: `indurtdb.h`；崩溃自愈能力（v3.1.0 owner_pid + claim_ownership）
- Produces: 可独立运行的 soak/故障注入程序与脚本

- [x] soak_test.c：多进程持续读写，结束校验读写计数、数据一致、无崩溃；时长由参数控制（CI 用短时长，手动可拉长）。
- [x] fault_injection_test.c：父进程 initialize 并写入，子进程 attach；kill 父进程（SIGKILL）；子进程继续读写并断言成功（崩溃自愈生效）；覆盖写锁内崩溃（奇数 write_seq 恢复）。
- [x] run_soak.sh：编译 + 运行 + 汇总 PASS/FAIL，退出码有意义。
- [x] 运行验证全绿。
- [x] Commit（test 前缀）。

**验收**：soak 短时长通过；kill-owner 自愈场景断言通过；脚本退出码正确。
