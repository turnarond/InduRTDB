## 3. 任务详解

### T1 · Header v2 与版本协商

**红（先写失败测试）**

| 用例 | 断言 |
|---|---|
| `HeaderV2.SizeIs128` | `sizeof(irt_header_t) == 128` |
| `HeaderV2.CrcDetectsCorruption` | 篡改 Header 字节后 CRC 校验失败 |
| `HeaderV2.RejectsV1Segment` | 挂载 `version=1` 的旧段**返回明确错误码**，不静默按新布局解释 |
| `HeaderV2.SectionOffsetsConsistent` | `off_points / off_index / off_meta / off_subs` 与段大小自洽 |
| `Compat.V1LayoutStill128` | 点位 `sizeof(indurtdb_point_t) == 128` 且既有字段偏移不变 |

**绿**：Header 扩至 128B；`crc32`@44、`flags`@48、`scan_skipped`@76（保留区，避开 CRC 范围[48..71]）、`off_*`；attach 时版本不匹配即拒绝。

**重构**：段布局计算集中到 `irt_layout_*()` 内联函数，禁止各处硬算偏移。

**验收**：静态断言通过；零警告；既有 22 个测试无回归。

### T2 · name→id 索引

**红**

| 用例 | 断言 |
|---|---|
| `Index.FindByNameRoundTrip` | 注册后按名查到正确 id；未注册返回 `INDURTDB_ERR_NOT_FOUND` |
| `Index.HandlesHashCollision` | 构造同哈希的多个点位名，全部可查到 |
| `Index.TombstoneAllowsReuse` | 删除后槽位可复用；删除后立即查不到 |
| `Index.FullLoadNoInfiniteProbe` | 负载打满时查找在有限步内终止（不死循环） |
| `Index.ZeroHeapAllocation` | 索引区定长预分配，无 `malloc` |

**绿**：FNV-1a 32 + 线性探测 + 墓碑（`point_id` 哨兵值）；冲突比较复用点位内 `name[64]`。

**重构**：索引操作抽 `irt_index_*` 模块，与点位读写解耦。

**验收**：负载因子 ≤0.5 时有实测冲突率数据；全量回归绿。

### T3 · 元数据区

**红**

| 用例 | 断言 |
|---|---|
| `Meta.DefaultIsZero` | 未设置时 `eur_min/max == 0`、`deadband == 0`、`flags == 0` |
| `Meta.SetGetRoundTrip` | 设置量程与死区后读回一致 |
| `Meta.NotInHotPath` | 读写点位值**不触碰**元数据区（可用内存访问计数或偏移断言佐证） |
| `Meta.OutOfRangeIdRejected` | 越界 id 返回明确错误码 |

**绿**：`Metadata N × 32B` 区段；`indurtdb_meta_t` 与 `get/set_meta`。

**重构**：元数据结构与点位结构分离定义，避免热/冷字段混在同一结构。

**验收**：`sizeof(indurtdb_meta_t) == 32`；零警告。

### T4 · API v2 句柄化

**红**

| 用例 | 断言 |
|---|---|
| `ApiV2.MultipleInstancesInOneProcess` | **同进程可同时持有两个实例**，各自读写互不影响 |
| `ApiV2.HandleLifecycle` | `open` / `close` 成对；`close` 后句柄不可再用 |
| `ApiV2.NullHandleRejected` | 传 NULL 句柄返回参数错误，不崩溃 |
| `Deprecation.V1ApiStillWorks` | v1 的 26 个函数行为不变（既有用例全绿） |
| `Deprecation.V1UsesDefaultHandle` | v1 调用走内部默认句柄，与 v2 显式句柄指向同一实例时结果一致 |

**绿**：`indurtdb_t` 不透明句柄 + `indurtdb_h_*` 函数；v1 转调默认句柄并标 `INDURTDB_DEPRECATED`。

**重构**：外观层从"全局单例状态"改为"句柄状态 + 默认句柄"。

**验收**：多实例并发用例通过；v1 全量回归无破；文档标注 v3.5 移除 v1。

### T5 · 迁移工具与回退

**红**

| 用例 | 断言 |
|---|---|
| `Migrate.V1ToV2PreservesPoints` | 点位值 / 类型 / 质量 / 时间戳 / name 全量一致 |
| `Migrate.SourceTsPolicy` | v1 段无 `source_ts`，迁移后语义明确（置 0 = 未提供） |
| `Migrate.ChecksumVerification` | 迁移前后校验（点数 / CRC / 抽样比对），不一致即报错 |
| `Migrate.RefusesWrongSourceVersion` | 源段不是 v1 时拒绝执行 |

**绿**：`tools/irt_migrate`（Python），独立校验脚本。

**重构**：校验逻辑与迁移实现解耦（Q4 裁定要求）。

**验收**：迁移 + 校验 + **回退演练**（重新部署 v3.3 + 清理段）全流程跑通并留记录。

### T6 · 语义补齐

**红**

| 用例 | 断言 |
|---|---|
| `Quality.LayeredBitLayout` | `QUALITY_BASE/MAKE` 正确拆分基础码与量程位；高 2 位必须为 0 |
| `Quality.ExistingCodesUnchanged` | 现有 0–3 取值语义不变（`GOOD` 仍判定为可用） |
| `StatusCode.MappingRoundTrip` | `quality → StatusCode → quality` 降级路径一致 |
| `Type.Int64RoundTrip` | int64 / uint32 / float 读写一致，点位尺寸仍 128 |

**绿**：质量码常量与宏扩展；`indurtdb_quality_to_status_code()` 纯函数；类型枚举与读写 API（复用 `value` union）。

**重构**：质量判定集中到内联函数，禁止各处裸位运算。

**验收**：双向映射表用例覆盖；`sizeof == 128` 断言仍通过。

### T7 · 可靠性（issue #19）

**红**

| 用例 | 断言 |
|---|---|
| `Scan.NotStarvedByHotWriter` | **热写者自旋**下，连续 N 轮 `check_timeouts()` 的 `detected > 0`（先复现饿死 → 红） |
| `Scan.SkippedIsObservable` | `stats.scan_skipped` 正确累计被跳过的点数（可观测而非静默） |
| `Scan.NoRegressionOnIdle` | 无并发写时，扫描耗时与 v3.3 相比无显著退化 |

**绿**：L1 读重试循环连续失败后 `sched_yield()`；`write_begin` 冲突有限重试（默认 3 次）+ 退避；L2 Header 新增 `scan_skipped` 计数。

**重构**：重试/退避策略参数化并集中，避免散落魔法数。

**验收**：饿死场景用例稳定通过（多次重复运行零失败）；bench 对比数据入库。

### T8 · 诊断与工具集

**红**

| 用例 | 断言 |
|---|---|
| `Tools.InspectReportsHealth` | 巡检脚本能输出段健康状态（版本、点数、CRC、owner pid） |
| `Tools.DetectsFdLeak` | 反复启停后脚本检出 fd 增长（或确认无增长） |
| `Tools.SmokeEndToEnd` | 冒烟脚本一键完成"起服务 → 写 → 读 → 订阅 → 停"，退出码可判定 |
| `Coverage.TargetBuildsAndRuns` | `INDURTDB_ENABLE_COVERAGE=ON` 构建通过并产出覆盖率报告 |

**绿**：`tools/` Python 包（自带工程结构：模块划分 + 依赖声明 + 自测）；CMake 覆盖率目标。

**重构**：脚本规范化（统一参数、退出码、日志），可接入 CI。

**验收**：CI 中可执行；脚本可独立运行；行覆盖数据入库。

### T9 · `rtdbd` / `irtcli` 协议 v2

**红**

| 用例 | 断言 |
|---|---|
| `ProtoV2.FindByName` | 客户端经服务端按名查到 id |
| `ProtoV2.MetaWriteRequiresAuth` | 未授权 uid 写元数据被拒（`SO_PEERCRED` 鉴权生效） |
| `ProtoV2.RejectsV1Client` | 协议版本不匹配即断连（不静默） |

**绿**：`RTDBD_PROTO_VERSION` 1→2；新增 `OP_FIND_BY_NAME / OP_GET_META / OP_SET_META`；元数据写纳入鉴权与审计。

**重构**：opcode 分派表化，新增操作不改核心循环。

**验收**：端到端按名查找走通；鉴权用例绿。

## 6. 实施中需确认的问题

1. `indurtdb_cfg_t` 的字段集合（创建参数：`max_points` / `max_subs` / 是否建索引 / 是否建元数据区）。
2. 索引与元数据区在**资源受限目标板**上的内存开销是否可接受（需给出 N=10k / 100k 的段大小表）。
3. `tools/` 的 Python 版本与依赖约束（目标环境可能是精简系统）。
4. 迁移是否需要支持"部分迁移"（只迁指定点位区间）。
