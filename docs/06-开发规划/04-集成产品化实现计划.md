# InduRTDB 集成产品化 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 C/C++ 开发者在数分钟内通过 find_package / pkg-config / FetchContent 把 InduRTDB 集成进自己工程并跑通，版本可信、路径解耦、可回归。

**Architecture:** 方案 A —— CMake export 标准实践（`install(EXPORT)` + `CMakePackageConfigHelpers`）生成包配置/版本文件/命名空间目标 `InduRTDB::indurtdb`，配 pkg-config；子项目默认隔离；分三阶段交付（核心集成 → 模板工程 → CI 回归）。

**Tech Stack:** C11（库）、CMake ≥3.15、GNUInstallDirs / CMakePackageConfigHelpers、pkg-config、GoogleTest（既有测试）、Bash（回归脚本）。

## Global Constraints

- 库为纯 C11，编译 `-Wall -Wextra -Werror`，零警告（测试是 C++17 + gtest）。
- 保持 `indurtdb.h` 单头文件对外（版本宏内嵌，不新增对外头）。
- 注释、文档、提交信息用中文；提交遵循 conventional commits（feat/fix/docs/build/test/chore）。
- 文档是唯一对外接口，改功能必须同步文档（规则 2）；每个功能单元独立 commit（规则 4）。
- 共享内存布局 128B/64B/16B 与 magic/version 不得改动（兼容性红线）。
- 目标平台 Linux / SylixOS；本计划的构建/验证在 Linux 上进行。
- 依据设计文档：`docs/03-设计文档/03-集成产品化设计文档.md`。

    install(TARGETS indurtdb EXPORT InduRTDBTargets

````markdown
# InduRTDB 集成指南

> 面向把 InduRTDB 作为库引入自己 C/C++ 工程的开发者。三种方式任选其一。

## 前置：获取与安装

```bash
git clone https://github.com/turnarond/InduRTDB.git
cd InduRTDB && mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release && make -j$(nproc)
cmake --install . --prefix <你的安装前缀>
```

## 方式一：find_package（推荐，CMake 工程）

```cmake
find_package(InduRTDB REQUIRED)
target_link_libraries(app PRIVATE InduRTDB::indurtdb)
```
配置时指定安装前缀：`cmake .. -DCMAKE_PREFIX_PATH=<你的安装前缀>`。

## 方式二：pkg-config（非 CMake / Makefile 工程）

```make
CFLAGS += $(shell pkg-config --cflags indurtdb)
LDLIBS += $(shell pkg-config --libs indurtdb)
```
需 `export PKG_CONFIG_PATH=<你的安装前缀>/lib/pkgconfig`。

## 方式三：FetchContent / add_subdirectory（源码内嵌，无需安装）

```cmake
include(FetchContent)
FetchContent_Declare(indurtdb
    GIT_REPOSITORY https://github.com/turnarond/InduRTDB.git
    GIT_TAG main)
FetchContent_MakeAvailable(indurtdb)
target_link_libraries(app PRIVATE InduRTDB::indurtdb)
```
作为子项目引入时，InduRTDB 默认不构建自身 tests/examples、不安装，不污染你的工程。

## 版本检查

```c
#include <indurtdb/indurtdb.h>
/* INDURTDB_VERSION_STRING == "3.1.0" */
```

## 最小示例

```c
#include <indurtdb/indurtdb.h>
int main(void){
    indurtdb_initialize("my_app", 1024, 8);
    indurtdb_write_double(1, 25.5);
    double t; indurtdb_read_double(1, &t);
    indurtdb_shutdown();
    return 0;
}
```
````

    include(FetchContent)
    if(DEFINED INDURTDB_SOURCE_DIR)
        # 离线/本地: 直接指向 InduRTDB 源码目录

#include <stdio.h>

int main(void) {

    bool on = false;

    indurtdb_shutdown();
    printf("starter ok: temp=%.1f, on=%d\n", t, (int)on);

}

#!/usr/bin/env bash
# 外部消费回归: 在干净环境模拟外部用户两条路径消费 InduRTDB。
# 任一失败即退出非 0。可本地运行, 也可挂入 CI。

JOBS="$(nproc)"

echo "== [1/4] 构建并安装 InduRTDB -> $PREFIX =="
cmake -S "$REPO_ROOT" -B "$WORK/indurtdb-build" -DCMAKE_BUILD_TYPE=Release > /dev/null

echo "== [2/4] find_package 消费 starter =="

    -DCMAKE_PREFIX_PATH="$PREFIX" > /dev/null

"$WORK/starter-fp/starter"

echo "== [3/4] pkg-config 解析 =="
export PKG_CONFIG_PATH="$PREFIX/lib/pkgconfig"

    -DSTARTER_USE_FETCHCONTENT=ON -DINDURTDB_SOURCE_DIR="$REPO_ROOT" > /dev/null

"$WORK/starter-fc/starter"

echo "ALL CONSUMPTION PATHS OK"
