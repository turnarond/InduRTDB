# 文档一致性检查清单（Release Checklist）

**版本：1.0　|　日期：2026-09-23　|　基线：v3.2 文档治理**

> 文档是 InduRTDB 唯一的对外接口。本清单用于**防止文档腐败**：每次发布（打 tag）前逐项勾选，任一项不通过不得发布。
> 背景与逐条差异见 [`08-功能评审与下一步规划.md`](./08-功能评审与下一步规划.md)。

---

## 如何使用

| 场景 | 要求 |
|---|---|
| 修改 API / 结构体 / 行为 | 必须走完整清单（第 1–6 节） |
| 修改性能相关代码 | 至少走第 3、6 节 + 重跑 `scripts/run_bench.sh` |
| 仅修改文档 | 走第 7 节（链接与命名） |
| 版本发布 / 打 tag | 全部章节逐项勾选并留痕 |

---

## 1. 版本一致性

- [ ] `VERSION` 文件、`CMakeLists.txt` 的 `project(VERSION)`、`include/indurtdb/indurtdb.h` 版本宏、`README.md` 与 `CHANGELOG.md` **四处版本号完全一致**
- [ ] `test_c_version` 通过（版本宏一致性有测试守护）
- [ ] `CHANGELOG.md` 已补充本版本条目

## 2. API 与实现一致

- [ ] `indurtdb.h` 中的函数总数与 [`05-SDK手册/03-C-API参考手册.md`](../05-SDK手册/03-C-API参考手册.md) 收录条目**一一对应**（当前 26 个函数）
- [ ] 新增/删除/改签名 API 已同步：SDK 手册、快速入门示例、白皮书示例、`demo/`、`examples/`
- [ ] 返回值语义（0 / -1 / -2 / -3）在 API 手册中明确写出
- [ ] 结构体字段变更已评估 **ABI 影响**，必要时升级 shm 版本并配套迁移方案

## 3. 性能数据

- [ ] 文档中所有性能数字标注了**平台 + 构建配置**（如 x86_64 / Release `-O2`）
- [ ] 实测数据与"设计目标"表述分开，不用目标值冒充实测
- [ ] 性能表更新后已重跑 `bash scripts/run_bench.sh`，数据来源可复现
- [ ] ARM / SylixOS 未实测的，明确标注"未实测"，不外推

## 4. 边界与定位

- [ ] 白皮书与 README 的"做 / 不做"边界表与当前架构决策一致
- [ ] **未实现的能力不得写成卖点**（历史上出现过：集群同步、VSOA 认证/加密）
- [ ] 跨主机、持久化、北向协议等明确标注由 node-server / Bridge 承担

## 5. 已知约束（六条，与实现逐条核对）

- [ ] `peek()` 表述为**单拷贝**（线程本地缓冲，同线程下次覆盖），不得写"零拷贝"
- [ ] **单进程单例**限制已声明
- [ ] **写冲突返回 -2（busy）、不重试**语义已声明
- [ ] **`check_timeouts()` 为 best-effort**已声明
- [ ] **订阅为进程内回调、不支持跨进程通知**已声明
- [ ] **无鉴权/加密/持久化**已声明；`access` 不得描述为访问控制机制

## 6. 测试与构建佐证

- [ ] `cmake --build build 2>&1 | grep -E 'error|warning'` 无输出（`-Werror` 零警告）
- [ ] `ctest --output-on-failure` 全绿
- [ ] `bash scripts/verify_consume.sh` 通过（三条消费路径）
- [ ] `bash scripts/run_soak.sh` 通过（长稳 + 故障注入）

## 7. 文档工程规范

- [ ] 目录与文件名使用**中文**，数字前缀排序（`01-` `02-`…）
- [ ] 新增文档已登记到 [`docs/README.md`](../README.md) 或对应目录索引
- [ ] **链接有效**：归档/重命名文件后，所有交叉引用已更新（白皮书、SDK 手册、README 互链）
- [ ] 历史文档归档时已加"口径废弃"横幅并指向现行文档
- [ ] 无 AI / 插件中间目录（`.claude/`、`.omc/`、`.superpowers/`、`.codegraph/`）与构建产物入库
