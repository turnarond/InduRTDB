## 2. 主题 A：核心语义深化（死区/RBE + EURange 生效）

> **状态：✅ 已交付（v3.7.0，2026-10-06）**。T1–T4 全部落地，评审 Important 项已修复（补 EUR-crossing / 百分比死区端到端测试），32/32 ctest 全绿、`run_bench.sh` 全项 PASS 且热路径零回归。实现细节见 `2026-10-06-v3.7-themeA-implementation.md`。

### 2.1 缺口
v3.4 T3 在元数据区预留 `eur_min(8) / eur_max(8) / deadband(4) / flags(4)`（每点 32B 冷数据），但**只存未用**：
1. rtdbd 每次写都**无条件**广播 `NOTIFY`，高频小幅抖动会产生通知风暴，浪费跨进程带宽；
2. `value` 越界 `EURange` 时**不会**置 quality 量程位（v3.4 已定义 quality 分层位 bit4–5，但无写路径生效逻辑）。

这是相对 Apache IoTDB / openHistorian 缺失的「上送侧 / 变化上报」能力。

### 2.2 任务
- **T1 死区/RBE 过滤（服务端决策，零 ABI）**
  - RBE 状态（每点 `last_reported` 值）放在 **`rtdbd` 进程内存**（rtdbd 本就是写权威），**不进共享内存** → 零 ABI 变更。
  - 写值时比较 `|new - last_reported|`：超过死区（绝对模式或百分比模式，模式存于 `meta.flags`）**或**值跨越 `EURange` 边界，才发 `NOTIFY` 并刷新 `last_reported`；否则静默（值已落共享内存，订阅者轮询仍可见）。
  - 直接 shm 写者（legacy 单进程路径，不经 rtdbd）**不享受 RBE**——符合「读写分离架构下 rtdbd 是写权威」的定位。
- **T2 EURange→量程位（在 rtdbd 写权威层施加，核心写路径保持纯净）**
  - **架构约束**：核心写路径是热路径、元数据是冷数据（v3.4 T3 守护「meta 不进热路径」），故 EURange→量程位**不在核心热路径内读 meta**，而由 **rtdbd（写权威）** 在 `do_write()` 计算量程位，经新增**可选** `indurtdb_h_write_quality_ts()` 一次性落值+质量。
  - 核心默认 `indurtdb_write_*` 仍强制 `quality=GOOD`、**零 meta 读**；直接 shm 写者（legacy 路径）默认不含量程位（与「rtdbd 是写权威」一致）。
  - 跨进程直读者轮询共享内存看到由 rtdbd 写入的一致量程位；语义纯函数集中到新建 `src/core/irt_semantics.c`，被可选写入口与 rtdbd 复用，消除 `rtdbd.c` 既有 per-type 重复。详见 `2026-10-06-v3.7-themeA-implementation.md` §4–§5。
- **T3 纯函数 + 单测**
  - 抽出 `indurtdb_deadband_exceeded(mode, deadband, last, cur)` 与 `indurtdb_apply_eurange_limits(eur_min, eur_max, value, *quality)`：**无状态、可单测**，与热路径解耦。
  - 单测覆盖：绝对死区 / 百分比死区 / 跨越边界 / 关闭死区 / 双向（int64/uint32/float/double）等。
- **T4 rtdbd 改造 + 端到端测试**
  - `NOTIFY` 改为死区驱动；`tests/integration` 新增用例断言「小幅抖动不触发通知、越界触发且量程位正确、首值必通知」。

### 2.3 约束 / 验收
- 热路径零回归：`run_bench.sh` P99 仍 PASS，回归数据回填 README；
- ABI 不变（段版本仍 2，元数据布局不变）；
- RBE 状态不进共享内存；
- 死区模式默认值（关闭）保证现网行为不变（向后兼容）。

### 2.4 关键决策（已确认）
- **RBE 状态存 rtdbd 服务端**而非共享内存：换取零 ABI，代价是「经 rtdbd 写入」才享受 RBE。用户已确认该取舍。
- **EURange 量程位在 rtdbd 写权威层施加**（不在核心热路径读 meta）：守住 v3.4 T3「meta 不进热路径」不变式，避免同一语义在核心与 rtdbd 两处重复；代价是 legacy 直接 shm 写者默认不含量程位（可接受，与其定位一致）。用户已确认该取舍（架构整洁性优先）。

## 3. 主题 B：运维硬化（Observability / 稳定性）

> **状态：✅ 已交付（v3.7.0，2026-10-07）**。B1–B3 全部落地，35/35 ctest 全绿、编译零警告、
> `run_bench.sh` 全项 PASS。评审 1 项 Critical（fail-fast 退出曾 `shm_unlink` 销毁数据段）与
> 6 项 Important 均已修复并补了护栏测试。实现细节与计划偏差见
> `2026-10-06-v3.7-themeB-implementation.md` §0。
>
> 主要落地偏差：`indurtdb_detach()` 保留段、`indurtdb_validate_config` 严格性分档（残留段只告警）、
> `set_meta` 写入前校验、YAML 扩展可选语义字段、`outq_flush` 部分发送、DEGRADED 改为滑动窗口。

> 主题 B 在本次评审中重排：原 roadmap 的「实测验证 / 配置持久化 / v1 退役」保留为**延展任务 B4–B6**；新增并已评审的**稳定性核心 B1–B3**（健康计数 / 优雅退出背压 / 配置校验）为本主题 v3.7 落地重点。详细实现计划见 `2026-10-06-v3.7-themeB-implementation.md`。

### 3.1 B1 健康 / 错误计数 + 进程自检（health probe）
- rtdbd 维护**定长无堆**错误计数（decode 失败、写被拒、背压丢弃、通知发送失败、成功写/通知数），隔离到新建 `rtdbd/src/stats.c`。
- **SIGUSR1 触发 dump `/tmp/rtdbd.stats`**（supervisor systemd/SylixOS 探测用）+ 新增 **`RTDBD_OP_HEALTH` opcode**（同一 `RTDBD_PROTO_VERSION` v2，不 bump 版本，monitor 可展示）。
- 核心新增 `indurtdb_self_check()`（校验 shm 魔数/版本/可选 CRC）+ `rtdbd_self_check()`（含连接表完整性），供 supervisor 布尔探针。

### 3.2 B2 优雅退出 + 背压（慢消费者保护）
- **每连接有界环形队列**（定长无堆）：写成功→入每订阅者队列；poll `POLLOUT` 排空；满则**丢最旧 + 计数**（与"丢最旧"语义一致、保序）。杜绝慢消费者阻塞单线程服务端。
- 优雅退出：SIGTERM/SIGINT → 停收新写 → best-effort 排空出站队列（受 `RTDBD_SHUTDOWN_DELAY_SEC` 限时）→ 关 fd/释放 shm。
- **语义退出码**：0=正常 / 1=通用启动错误 / 2=配置校验失败 / 3=shm 损坏 / 4=启动自检失败；`supervise_loop` 对致命码 2/4 停止 respawn（避免坏配置无限重启）。

### 3.3 B3 配置校验 + 启动 fail-fast
- 核心纯函数 `indurtdb_validate_point_meta()` / `indurtdb_validate_config()`：校验 eur_min<eur_max、deadband≥0、百分比 deadband∈[0,100]、flags 仅已知位、type/name 合法（复用主题 A 的 `INDURTDB_META_FLAG_*`）。
- rtdbd 在 `indurtdb_initialize` 前做校验阶段：服务参数（instance/max_points/max_subs/sock_path 范围）+ 点位语义 + 启动自检；任一非法 → 明确 stderr + 退出码（2/4），**不进入半初始化**。

### 3.4 主题 B 延展（同主题后续，另立计划，不纳入本实现计划）
> **状态（2026-10-07）：B4 与 B5 已交付**，见 `2026-10-07-v3.7-B4B5-implementation.md`。
>
> B5 相对本节的**范围偏离（已评审确认）**：只迁移 `examples/` 与 `demo/`，
> **测试刻意保留 v1**——v1 到 v4.0 前是受支持公共 API，测试是其回归网；
> 整体迁移（约 500 处 / 35 文件）零行为收益却担全量 churn 风险。

- **B4 运行时配置持久化（解决 v3.6 CRUD 重启即丢）**：推荐追加写 delta 日志（`<instance>.rtdbd.delta`：op+id+name+type+access+时间戳）；启动时序 `load_config(base)` → 回放 delta → owner 接管；base 保持不可变可审计。备选回写 YAML 不推荐。**ABI 不变**。
  - 落地：`--delta-file` 显式启用（**默认关闭**，保持既有部署语义）；记录定长 80B + fsync；残片/坏记录安全停止。
- **B5 v1 API 退役（技术债）**：v1 全局函数加 `INDURTDB_DEPRECATED`；迁移 `examples/`、`demo/`、测试到 v2 句柄 API；真正删除推迟到 v4.0。
  - 落地：51 个 v1 单例封装已标注弃用；examples/demo 已迁 v2；测试/rtdbd/tools/bench 保留 v1 并用 `INDURTDB_NO_DEPRECATE_WARN` 关告警。
- **B6 SylixOS / ARM 实测验证（G4，发布级门槛）**：SylixOS 工具链交叉编译（`-Wall -Wextra -Werror` 零警告）+ 目标板基础读写/多进程/soak/fault-injection；依赖工具链到位，未就绪降级 P2 不阻塞发布。

### 3.5 关键决策（已确认）
- **协议不 bump 版本**：`RTDBD_OP_HEALTH` 加在 v2 内；v3.6 monitor 不发该 opcode 故不受影响；v3.7 monitor→v3.6 server 降级不支持（可接受）。用户已确认（不破坏已交付监控台优先）。
- **背压用每连接有界环形队列（丢最旧）**：定长无堆、保序，与"丢最旧"语义一致；非"非阻塞直发丢当前"（会丢最新值）。用户已确认。
- **配置校验范围 = 服务参数 + 点位语义都校验**：fail-fast 退出码 2/4；与主题 A flags 联动。用户已确认。
- **supervisor 区分致命退出码**：config(2)/self_check(4) 致命不 respawn，避免坏配置无限重启。
