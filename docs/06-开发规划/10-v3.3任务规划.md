## 1. 目标与范围

### 1.1 目标

把共享内存的**写**收敛到 `rtdbd` 服务进程（真鉴权、真审计、无写冲突），**读**保留 shm 零拷贝；容器进程经 `indurtdb-client` 走 RPC；`rtdbd` 不可用时控制仍可推进（fail-operational）。

### 1.2 范围边界（本次不做）

| 不做 | 归处 |
|---|---|
| 北向 OPC UA、持久化 / 历史 | node-server（IT 面） |
| quality 完整分层（量程位等）、类型扩展、CRC、诊断工具 | v3.4 |
| name→id 索引、去单例化、容量扩容 | v4.0 |
| 集群同步 | IT 侧，本版只预留事件流钩子 |

**例外**：`source_timestamp_ns` 与 `COMM_FAILURE` **提前到 v3.3**（fail-operational 依赖），见 T5。

## 4. 任务详解

### T0 · UDS 延迟原型验证（非 TDD，属技术实验）

| 项 | 内容 |
|---|---|
| 目标 | 实测本机 UDS 往返延迟，确认落在设计假设的 5–15μs |
| 做法 | 最小 C/S 程序：客户端发 16B 请求，服务端回 16B 响应；测 P50 / P99 / 吞吐 |
| 产出 | 可复现的 bench 程序 + 实测数据报告 |
| 验收 | 数据入库并回填 `05-读写分离与双通道架构设计.md` §1.1；若 P99 > 15μs，触发方案复评 |
| 备注 | 同时在目标 ARM 板各测一次（如有条件） |

**状态：✅ 已完成（PR #10，2026-09-24）**

| 报文 | P50 | P99 | 吞吐 |
|---|---|---|---|
| 16B | 11.585 μs | 18.182 μs | 79.83 K rt/s |
| 48B | 12.777 μs | 23.956 μs | 67.51 K rt/s |

- 门槛判定：**通过**。P99 超出原 15μs 假设（18–24μs），但按 1ms 周期写 10 次核算占预算 13%–24%，架构仍成立。
- 设计文档 §1.1 与 §4.4 已回填实测值，并新增**同步 / 异步写入模式**建议。
- 遗留：ARM / SylixOS 目标板复测。

### T1 · `rtdbd` 骨架

**红（先写失败测试）**

| 用例 | 断言 |
|---|---|
| `Rtdbd.WriteSerializesConcurrentClients` | 两客户端并发写同一点位，**均返回成功**，不出现 `-2 busy` |
| `Rtdbd.PeerCredResolvesUid` | `SO_PEERCRED` 正确取到对端 pid / uid / gid |
| `Rtdbd.RejectsUnauthorizedUid` | 策略表外的 uid 写被拒，返回明确错误码，点位值不变 |
| `Rtdbd.AuditRecordsPidPointTs` | 审计环形缓冲记录 `pid + uid + point_id + ts` |
| `Rtdbd.ProtocolVersionMismatchRejected` | 协议版本不匹配时拒绝连接（不静默） |

**绿（实现）**：UDS 监听、极简二进制协议（带版本号）、单线程串行写、策略表鉴权、审计定长环形缓冲。

**重构**：协议编解码抽独立模块；策略表配置化。

**验收**：`-Wall -Wextra -Werror` 零警告；用例全绿；不引入第三方依赖。

### T5 · `source_timestamp_ns` 与 `COMM_FAILURE` 落地

**红**

| 用例 | 断言 |
|---|---|
| `Layout.SourceTimestampOffsetIs112` | `offsetof(indurtdb_point_t, source_timestamp_ns) == 112`（8B 对齐） |
| `Layout.SizeStill128` | `sizeof(indurtdb_point_t) == 128`，既有字段偏移全部不变 |
| `Quality.CommFailureSemantics` | `COMM_FAILURE` 可被写入与读出，基础码位解析正确 |
| `Compat.ZeroSourceTimestampMeansUnprovided` | 全 0 段读作"未提供源时间戳"，退化为旧行为 |

**绿**：结构体字段新增、访问宏、质量码常量。

**重构**：字段访问集中到内联函数。

**验收**：静态断言通过；既有 15 单元 + 1 集成测试无回归；**ABI 仍为 v1**。

### T2 · 快速自恢复

**红**

| 用例 | 断言 |
|---|---|
| `Recovery.RestartAttachesExistingSegment` | `SIGKILL` 后重启，**attach 已有段**，数据不丢 |
| `Recovery.ReclaimsOwnershipAfterRestart` | 重启后重新 claim ownership，后续写正常 |
| `Recovery.RtoWithinBudget` | RTO 实测 ≤ **1s**（设计目标 ≤100ms） |

**绿**：supervisor / 自动重启 + 重启时 attach 而非重建 + ownership 重领。

**重构**：段生命周期状态机显式化。

**验收**：崩溃重启场景纳入 soak；RTO 数据入库。

### T3 · `indurtdb-client` 与写队列

**红**

| 用例 | 断言 |
|---|---|
| `Client.WriteQueuedWhenServiceDown` | 服务不可用时写**不阻塞**，返回 `IRT_QUEUED` |
| `Client.ReplayPreservesOrder` | 恢复后按入队顺序重放 |
| `Client.CoalescesSamePoint` | 同点位多次写**只保留最新值** |
| `Client.AlertsOnQueueFull` | 队列满（默认 256）触发告警，不静默丢弃 |
| `Client.ReplayCarriesSourceTimestamp` | 重放写入携带**原始** `source_timestamp_ns`（时间戳不失真） |
| `Client.NoFdLeakOnReconnect` | 反复断连重连无 fd 泄漏（soak 验证） |
| `Client.AsyncWriteReturnsImmediately` | **异步模式**下写入队即返回，应用可见延迟为 ns 级（不等待服务端） |
| `Client.SyncWriteWaitsAck` | **同步模式**下等待服务端确认，返回已落 shm |

**绿**：客户端库（命名空间独立，如 `irtcli_*`）+ 定长环形队列（默认 256）+ 重放 + **同步/异步两种写入模式**（见设计文档 §4.4）。

**重构**：队列与传输解耦。

**验收**：队列边界用例全绿；与 T5 的 `source_timestamp_ns` 联动正确。

### T4 · 变更通知

**红**

| 用例 | 断言 |
|---|---|
| `Notify.CrossProcessReceivesChange` | 跨进程订阅者收到变更通知（此前仅进程内回调） |
| `Notify.NoFdLeakUnderChurn` | 大量订阅/退订循环后无 fd 泄漏 |

**绿**：复用已建立的 UDS 连接广播变更。

**验收**：通知延迟实测；soak 无泄漏。

### T6 · 端到端与 CI

**红**：host 多进程（驱动 / 控制逻辑 / HMI）+ 容器模拟进程的混合读写订阅场景用例。

**绿**：补齐集成测试与脚本。

**重构**：脚本规范化，可接入 CI。

**验收**：纳入 CI（Debug / Release 双配置）；`ctest` 全绿；`scripts/` 下脚本可独立运行。

## 6. 风险与回退

| 风险 | 触发 | 回退 / 应对 |
|---|---|---|
| UDS 延迟不达标 | T0 | **停止投入**，回方案评审（可能需保留直写路径或改共享内存通知） |
| RTO 超 1s | T2 | 评估热备或缩短启动路径；先降到"告警 + 更长容忍窗口" |
| 重放时序错乱 | T3 | 依赖 `source_timestamp_ns` 携带原始时刻；加强用例 |
| ABI 意外破坏 | T5 | 静态断言 + 字节布局回归测试拦截；该任务只占 padding，回退成本低 |
| `rtdbd` 引入新单点 | T1–T3 | 三层兜底（自恢复 + 队列 + 新鲜度标记）；队列与通知均可先降级为不同步 |

## 7. 实施中需确认的问题

1. `rtdbd` / `indurtdb-client` 的**最终命名**（需符合 `irt_` / `indurtdb_` 规范）。
2. **容器场景 socket 挂载方式**：UDS 挂载路径 vs TCP loopback（影响 T1 的监听实现）。
3. 审计环形缓冲的**容量与导出方式**（文件 / syslog / 接口查询）。
4. T6 是否需要配套的 **Python 冒烟 / 巡检脚本**（按工具集约定优先 Python）。
