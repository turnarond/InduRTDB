## 1. 决策前置（2026-10-18 已裁定，逐条见 §10）

| 编号 | 决策 | 本文建议 |
|---|---|---|
| **P1** | 分区语义模型：命名空间作用于**名称**还是 **id 空间** | **作用于名称**（name 在分区内唯一；id 空间保持全局唯一稠密） |
| **P2** | 是否升**段版本**（`IRT_SHM_VERSION` 2 → 3） | **升到 3**，旧段拒绝挂载 + 迁移工具（与 v3.4「不静默解释旧段」原则一致） |
| **P3** | 分区标识形态 | **`uint32 partition_id`**（Redis db0/db1 风格）；可选字符串别名由 `rtdbd` 配置层映射 |
| **P4** | 分区选择机制 | 原语 = **显式传参**（默认 0）；便捷 = **句柄/连接级 `select`**（Redis `SELECT` 语义） |
| **P5** | 策略模型扩展 | 策略行**向后兼容**地由 3 段扩为可选 4 段 `<uid>:<partition>:<min_id>:<max_id>` |
| **P6** | 分区数量与生命周期 | **无独立分区表**：分区是点位属性，`uint32` 任意值合法、随点位存在；不做分区级增删 API |
| **P7** | 协议版本 | **`RTDBD_PROTO_VERSION` 2 → 3**，旧客户端拒绝（沿用 v3.4 先例） |
| **P8** | 分区是否为安全边界 | **否**（与 Redis 一致）；鉴权仍是 uid × id 区间（可选按分区限定），读免鉴权不变 |

**选「作用于名称」而非「独立 id 空间」的理由（须在评审中确认）**：

1. **blast radius**：若 id 空间按分区隔离，则**每一个**以 `point_id` 为参数的读写/元数据 API 都要追加分区维度，等于重写全部 API + 全部协议请求体 + 全部调用方；而名称级隔离即可交付「类 Redis db0/db1」的全部可观测行为（同名点并存在不同分区、按分区选择、按分区列举）。
2. **id 稠密寻址不可动**：现点位数组是**按 id 稠密寻址**（`off_points + id*128`），id 全局唯一是布局基石；改 id 空间会连带索引、遍历、订阅、`read_range`、per-point 统计全线重构——这与「容量在线扩容（G15，v4.0）」同属寻址级重构，**应合并到 v4.0 一次做**。
3. **白皮书的「id 空间引入分区维度」是范围警示，不是逐字契约**：其真实关切是「分区不能只是 UI 标签，必须贯通索引与策略」。本方案**索引（R2）与策略（R4）均引入分区维度**，满足该关切；id 空间维度留待 v4.0。

**选「升段版本」而非「复用保留字节偷跑」的理由**：

- `indurtdb_point_t.reserved[8]`（offset 120..127）**确未被 `static_assert` 断言为 0，也不在段头 CRC 覆盖范围内**（CRC 仅覆盖 header `[0:16)` 与 `[48:72)`），因此把分区放进保留字节**字节层面可行、`sizeof`/偏移不变**。
- 但分区进入 **name→id 索引的哈希输入**后，同名查找的语义变了：旧客户端对同一 name 会算出不同的桶而**静默查不到**（返回 `NOT_FOUND`），而非报错。这正是 `IRT_SHM_VERSION` 注释所禁止的「按新布局解释旧段」。
- 故本方案取 **Package 2**：把分区**提升为具名字段**（`reserved[0:4)` → `uint32 partition`，偏移仍 120，`sizeof` 仍 128）并 **`IRT_SHM_VERSION` 2 → 3**，旧段一律拒绝挂载，配套离线迁移工具（`tools/irt_migrate` 已有 v1→v2 先例）。
- 备选 **Package 1（不升版本）**：分区仅存保留字节、且默认分区 0 的索引哈希与旧行为逐位一致。**成本低但脆弱**（默认分区需特判、写路径须保证不清零保留字节、跨版本语义静默不一致），列为 §10 Q1 备选。

**Package 2 必须同时接受的三条代价**：

- **同一主机所有进程须同时升级**（v2 段对 v3.9 拒挂、v3 段对 v3.8 拒挂），需停机窗口；
- 需要 **v2→v3 迁移工具**与校验/回退演练；
- 触发**协议主版本 +1**与**监控台/CLI/迁移工具/Python 镜像**的连带同步。

## 2. 需求：目标与非目标

### 2.1 目标（v3.9 必须交付）

| 编号 | 需求 | 动机 |
|---|---|---|
| **R1** | 点位可归属分区：新增 `uint32 partition`（默认 0），`sizeof(indurtdb_point_t)` 与全部既有偏移**不变** | 数据模型具备分区维度 |
| **R2** | **名称在分区内唯一**：name→id 索引的哈希输入与冲突比较均含分区；同名点可在不同分区共存 | 关闭白皮书登记项；承载「类 Redis db0/db1」的核心可观测行为 |
| **R3** | **按分区选择**：按名查找 / 注册 / 重命名 / 删除 / 列举均可限定分区 | 用户可见的「选择机制」 |
| **R4** | **策略可限定分区**：策略行 3 段（全区）与 4 段（`<uid>:<partition>:<min_id>:<max_id>`）并存，向后兼容 | 让分区贯通权限模型（白皮书关切） |
| **R5** | **协议 / CLI / 监控台暴露分区**：协议 v3 携带分区，`irtcli` 支持 `--partition`/`select`，监控台 `partitions` 视图落地 | 端到端可用，非仅库内 |
| **R6** | **迁移**：`IRT_SHM_VERSION` 2 → 3；`tools/irt_migrate` 扩展 v2→v3（`partition` 默认 0）+ 迁移校验 | 升版本的必备配套 |
| **R7** | **默认分区行为等价**：`partition == 0` 的注册/查找/列举/鉴权结果与 v3.8 **语义等价**（除版本协商拒绝旧段外） | 降低既有部署的迁移心智负担 |

### 2.2 非目标（v3.9 不做）

| 项 | 归属 |
|---|---|
| 真·**独立 per-partition id 空间**（id 跨分区复用、需 `(partition,id)` 寻址） | **v4.0**（与容量在线扩容 G15 同批，皆属寻址级重构） |
| 分区作为**安全/隔离边界**（跨分区读写授权） | 不做；鉴权仍是 uid × id 区间（可选按分区限定） |
| 分区**级增删管理 API**、分区级独立 `max_points`/配额 | 不做；分区是点位属性，随点位存在 |
| 点位**跨分区"移动"** | 不做；需要则 `delete` + `create`（分区在创建时固定） |
| 分区级备份 / 持久化 / 历史 | 本库无持久化（node-server 承担） |
| 跨实例 / 跨节点分区 | 不在本库边界 |
| v1 API 移除、跨进程 Pub/Sub 正式化 | v4.0 |

### 2.3 平台

- x86_64 Linux：**必须实测**（全量回归 + 性能回归 + 迁移演练）；
- SylixOS / ARM：**尽力验证，不阻塞发布**（与既有口径一致，G4 仍为技术债）。

## 3. 总体架构

### 3.1 数据模型：分区字段落位

点位记录保持 **128B**，仅将原 `reserved[8]`（offset 120..127）**更名为具名字段**：

| 偏移 | 现（v3.8） | v3.9 | 说明 |
|---|---|---|---|
| 0–31 | `value` union | 不变 | 热数据 |
| 32–39 | `timestamp_ns` | 不变 | |
| 40 | `type` | 不变 | |
| 41 | `quality` | 不变 | |
| 42–43 | `unit` | 不变 | |
| 44 | `access` | 不变 | |
| 45–108 | `name[64]` | 不变 | **分区内唯一** |
| 109–111 | `padding[3]` | 不变 | |
| 112–119 | `source_timestamp_ns` | 不变 | |
| **120–123** | `reserved[0:4)` | **`uint32 partition`** | **新增语义**，默认 0 |
| 124–127 | `reserved[4:8)` | `uint32 reserved` | 仍保留 |

- `IRT_STATIC_ASSERT(sizeof(indurtdb_point_t) == 128)` **与全部 offsetof 断言保持通过**（字段名变化、偏移不变）。
- 元数据区 `indurtdb_meta_t`（32B）**不变**（`reserved[8]` 继续保留；分区不进冷数据面）。

```
┌──────────────────────────────────────────────────────────┐
│ Header            128B   (段版本 version 2 → 3)           │
│   magic / version=3 / max_points / max_subscribers / ...   │
│   off_points / off_index / off_meta / off_subs （不变）    │
├──────────────────────────────────────────────────────────┤
│ Points            N × 128B   (热数据面；reserved[0:4)→partition) │
├──────────────────────────────────────────────────────────┤
│ Name Index        B × 8B     (槽仍 {hash32, id32}；键变 (partition,name)) │
├──────────────────────────────────────────────────────────┤
│ Metadata          N × 32B    (不变)                        │
├──────────────────────────────────────────────────────────┤
│ Subscriber 心跳   M × 16B    (不变)                        │
└──────────────────────────────────────────────────────────┘
```

> **区段尺寸与偏移全部不变**：布局结构（header/index/meta/subs 的字节排布）与 v3.8 **逐字节相同**，变的只有 `version` 值、点位 120..123 的**语义**、以及**索引键的语义**。这使迁移工具可退化为「改 version 值 + （可选）分区清零」。

### 3.2 name→id 索引（分区维度）

| 项 | v3.8 | v3.9 |
|---|---|---|
| 槽结构 | `{ uint32 hash; uint32 point_id; }`（8B） | **不变** |
| 桶数 | `roundup_pow2(max_points*2)` | **不变** |
| 哈希输入 | `FNV1a32(name)` | **`FNV1a32(partition_le32 ‖ name)`** |
| 冲突比较 | 比对点位区 `name[64]` | 比对 **`partition` + `name[64]`** |
| 接口 | `irt_index_lookup(s, name, &id)` | 追加分区参数（`…, uint32 partition, …`） |

- 使分区 0 与旧行为**语义等价**（同名同分区解析到同一点），但哈希值必然改变（输入变长），**故仍须升段版本以拒绝旧客户端**（§1 理由）。
- 并发约定**不变**：insert/remove 走全局 seqlock 写锁（注册期集中写，非热路径），lookup 走 seqlock 读重试。复合键**不引入新的锁路径**。
- 内存**不变**（槽仍 8B；不重复存分区，分区从点位区读取比对）。

### 3.3 策略模型（策略行向后兼容扩展）

`rtdbd/src/policy.c` 现状：行格式 `<uid>:<min_id>:<max_id>`，`deny by default`，不可热重载。

| 行格式 | 段数 | 语义 |
|---|---|---|
| `<uid>:<min_id>:<max_id>` | 3 | **区通配**：该 uid 对**所有分区**中 `[min_id,max_id]` 内的 id 有效（= v3.8 行为，向后兼容） |
| `<uid>:<partition>:<min_id>:<max_id>` | 4 | **分区限定**：该 uid 仅对 `partition` 内该 id 区间有效 |

- 按**冒号分段计数**判别格式（3 vs 4），旧配置**无需改动**即继续生效。
- 判定顺序：先匹配 uid，再（若有分区段）匹配分区，再判 id 区间；分区不匹配则该行不适用。
- **读操作免鉴权不变**；分区**不是**安全边界（R8/P8）。
- 约束：行缓冲 `IRT_POLICY_LINE_MAX`、规则上限 `IRT_POLICY_MAX_RULES` 维持；超限仍 fail-fast。

### 3.4 API v2 扩展（含 **API 计数门禁**）

> ⚠️ **门禁影响**：`scripts/check_api_count.py` 是流水线**第一步**，当前基准 **112 = 62(v1) + 50(v2)**。任何新增/删除公开函数**必须同步该脚本**，否则每次 push 在 10 秒内失败（v3.7 曾因此长期红）。

候选做法（见 §10 Q4）：

| 方案 | 形态 | 评价 |
|---|---|---|
| **A（倾向）** | **追加显式分区形参的重载族**：`indurtdb_h_find_by_name_in(h, uint32 partition, const char* name, uint32_t* out)` 等；既有 `indurtdb_h_find_by_name` 保留为 `_in(h, 0, …)` 薄封装 | 旧调用零改动；语义显式；新增函数数可控（3–4 个） |
| B | 用**句柄级 `partition` 默认值**承载，不新增函数：`indurtdb_h_set_partition(h, n)` + 既有函数内部取默认 | 函数数最少；但**隐式状态**易与跨进程读者的默认值不一致 |

**倾向 A**：与 v3.4「去单例化=显式句柄」的取向一致，显式优于隐式。受影响函数（名称域）：`find_by_name` / `create_point` / `rename_point` / `delete_point` / `list`。分区选择便捷性（P4）以 **B 的 `set_partition` 便捷接口**叠加（写入 `indurtdb_t` 句柄与 `rtdbd` 连接上下文），二者**不互斥**：A 为原语、B 为便捷。

### 3.5 协议 v3 与 `rtdbd` / `irtcli` / 监控台连带变更

| 项 | 影响 |
|---|---|
| 协议版本 | `RTDBD_PROTO_VERSION` 2 → 3；v2 客户端**拒绝**（沿用 `test_rtdbd_proto_v2` 的 `RejectsV1Client` 先例） |
| 请求体 | `OP_FIND_BY_NAME` / `OP_CREATE_POINT` / `OP_RENAME_POINT` / `OP_DELETE_POINT` / `OP_LIST` 追加 `uint32 partition` 字段 |
| 响应体 | `OP_LIST` 的 `POINT_INFO` 追加 `uint32 partition`（数组项结构变） |
| 新增 opcode | `OP_SELECT`（可选，连接级设默认分区；无则客户端每请求自带分区） |
| 鉴权 | `SET_META`/`CREATE`/`DELETE`/`RENAME` 管控写**仍须鉴权**；策略判定接入分区维度 |
| 审计 | 审计记录追加 `partition` 字段 |
| 配置 | `rtdbd` 配置可选 `partitions: [0,1,2]` **白名单校验**（不设则任意值合法）+ 可选 `partition_alias: {0: "default", 1: "unitA"}` |
| `irtcli` | 新增全局/命令级 `--partition N` + `select N` 子命令 |
| 监控台 | 已注册的 `partitions` 占位视图落地：分区下拉 + 按分区过滤点位表；后端 `app.py`/`rtdb_client.py` 暴露 `GET /api/partitions`、`GET /api/points?partition=N` |

## 4. 语义补齐

- **默认分区**：`partition == 0` 为默认；未显式指定时分区分辨率为 0（等价 v3.8 行为）。
- **名称唯一性**：`(partition, name)` 唯一；同一 name 可存在于多个分区，各自独立的 `point_id` 与值。
- **解析范围**：`find_by_name(partition, name)` **仅在本分区内**解析，不跨分区回退。
- **列举**：`LIST` 可按分区过滤；`partition` 省略时列出全部（保留 v3.8 行为）。
- **删除 / 重命名**：以 `point_id` 定位（id 全局唯一），分区随点；**不提供跨分区移动**。
- **索引装载**：配置加载/注册期一次性写入复合键；运行期只读。

## 5. 可靠性

| 关注点 | 处置 |
|---|---|
| 索引并发 | 复合键**不引入新锁路径**；仍走全局 seqlock（写锁用于注册，读重试用于查找） |
| 分区字段写时序 | `partition` 在**创建时固定**，此后只读；写入路径不触碰 120..127（避免破坏分区） |
| 策略 fail-fast | 策略行解析（3/4 段）非法即拒绝启动（退出码 2），沿用既有语义退出码 |
| 迁移安全 | 迁移前后校验：点数一致、`partition` 全 0、抽样比对值/质量/时间戳、CRC 重算 |
| 兼容 | v2 段**拒绝挂载**（版本协商），绝不静默解释 |
| 性能 | 索引哈希输入由 64B 增至 68B，FNV-1a 逐字节成本**可忽略**；热读写路径**零改动**（不碰索引）；须以 bench 回归佐证 |

## 6. 迁移与兼容

| 场景 | 行为 |
|---|---|
| 新部署 | 直接建 v3 段（`version=3`，点位 `partition` 默认 0） |
| 已有 v2 段 | **拒绝挂载**（`version` 不匹配），明确错误码；不静默解释 |
| 需保留数据 | `tools/irt_migrate` 扩展 **v2→v3**：读 v2 段 → 写 v3 段（点位值/质量/时间戳/name/source_ts 全量搬运，`partition := 0`，重建索引与 CRC） |
| 升级流程 | 停机 → 迁移（或丢弃重建）→ 全进程同时升级；**不支持新旧混跑** |
| 回退 | 重新部署 v3.8 + 清理 `/dev/shm` 段；v3 段对 v3.8 不可读（版本协商拒绝） |
| 协议 | v2 客户端对 rtdbd v3 **拒绝**；升级 rtdbd 须同步升级 `irtcli`/监控台 |

> 与 `07-v3.4` §6 同一原则：**首个对外发布前冻结 ABI**；本变更在冻结前窗口内进行，仍走「一次性变更 + 迁移工具」而非永久兼容层。

1. Debug / Release 双配置**零警告**构建；

4. **默认分区等价**：`partition==0` 下注册/查找/列举/鉴权结果与 v3.8 语义等价（用例覆盖）；

10. **端到端**：`irtcli --partition` 与监控台分区视图可用并有留档；
11. 文档按 `09-文档一致性检查清单.md` 逐项勾选并留痕；

## 10. 评审裁定（2026-10-18，**已全部裁定**）

| # | 问题 | 备选 | **裁定** |
|---|---|---|---|
| **Q1** | 分区语义模型与段版本 | A 名称级 + 升版本 / B 名称级 + 不升版本(保留字节偷跑) / C 真 id 空间(→v4.0) | **A**：名称级分区 + **`IRT_SHM_VERSION` 2 → 3** + 旧段拒挂 + 迁移工具 |
| **Q2** | 分区字段落位 | 具名字段 `uint32 partition`,偏移 120 / 继续用 `reserved[0:4)` 不具名 | **具名字段 `uint32 partition`**（偏移 120，`sizeof` 与其余偏移不变；`reserved[4:8)` 保留） |
| **Q3** | 分区标识形态 | `uint32` 数字 / 字符串名 / 两者并存 | **`uint32` 数字**（db0/db1 风格）；字符串别名仅在 `rtdbd` 配置层映射，不入 shm |
| **Q4** | API 形态 | A 显式重载族 / B 句柄默认值 / A+B 并存 | **A+B 并存**：原语 = 显式分区形参；便捷 = 句柄级 `set_partition` |
| **Q5** | 分区选择机制 | 仅显式传参 / 显式 + 句柄·连接级 `select` / 仅 `select` | **显式 + `set_partition`/`select`** 并存（显式优先，句柄/连接为默认值） |
| **Q6** | 协议是否加 `OP_SELECT` | 加 / 不加(仅显式) | **加 `OP_SELECT`**（连接级设默认分区） |
| **Q7** | 分区是否安全边界 | 否 / 是 | **否**：鉴权仍 uid × id 区间（可选按分区限定），读免鉴权不变；分区非隔离边界 |
| **Q8** | 分区上限与生命周期 | 无表·随点位·无增删 API / 需独立分区表与管理 API | **无分区表**：分区为点位属性，`uint32` 任意值合法、随点位存在，不做增删 API |
| **Q9** | 是否提供点位跨分区移动 | 否, delete+create / 提供 move | **否**：分区在创建时固定，需要移动则 `delete` + `create` |

**评审意见**（2026-10-18）：评审人**全部采纳建议值**——Q1 取 A（名称级分区 + 升段版本 v3），Q4/Q5 取 A+B 并存，其余七项按各条建议值执行。**本文自即日起生效，进入 §7 任务分解与实施。**
