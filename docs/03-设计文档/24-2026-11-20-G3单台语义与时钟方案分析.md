> **边界**：本文区分「单台可证伪事实」「需 F4 整机重启」「需 F2 多节点」三层；不改对外平台口径、不填 B 段 `fields`、不宣告 F2/F3a/F4 就绪、发布门仍 FAIL 8、不打 tag/合 main；实测需设备重启授权，实现须另立变更卡。

## 1 问题与目标

SylixOS 适配 G0/G1/G2 已完成（核心库交叉编译 + atomic64 修复 + rtdbd VSOA 主路径板上 `E2E PASS 5/5`）。下一阶段 G3 要在板上判定 **IR6 两态（进程重启不触发全量 / 整机重启触发全量）** 与 **IR7 epoch 隔离** 的物理前置。但源码调研发现一个必须先讲清的事实：**核心库没有 boot_id/digest/epoch 的持久化判定**——"进程重启 vs 整机重启"的摘要续传语义目前只在设计文档（13 号:198），代码未实现（`src/` 下 `boot_id/digest/snapshot_epoch` 0 命中；`boot_id` 仅存在于 `rtdbd/` 的进程级生成与注释，见 §2.2/§2.3）。

**目标**：把 G3 切成可证伪的三层——① 单台板上可观测的**事实与探针**（进程重启段存活/owner 接管/seqlock 恢复/单调钟连续性/boot_id 进程级变化）；② 需 F4（整机重启）才能取的 IR6 真值；③ 需 F2（6 节点）才能取的 IR7 真值。给出单台可立即准备的 harness 方案、判据与边界，避免把"未实现的摘要续传"误当已实现或误填 B 段数字。

## 2 事实基础（源码逐行核对）

### 2.1 shm 进程重启语义（已实现，单台可证伪）

- 段命名：`src/core/irt_shm.h:16` `IRT_SHM_PREFIX "/indurtdb_"`；`irt_shm.c:82-86` `snprintf("%s%s")`。
- 映射：`src/osal/posix/irt_osal_posix.c:49-82` / `src/osal/sylixos/irt_osal_sylixos.c:56-89`——`shm_open(O_CREAT|O_EXCL)` 成功即 owner，`EEXIST` 则 attach 既有段。
- 销毁：仅 owner unmap 时 `shm_unlink`（posix:84-99 / sylixos:91-106）；`indurtdb_detach()`（`src/api/indurtdb.c:1009-1017`）先置 owner=false 再 close，保留段数据。
- 崩溃恢复：`irt_shm.c:134-153`——`kill(stored_pid,0)` 非 0 则 `claim_ownership()` 改写 owner_pid（:137-145）；奇数 `write_seq` 原子 +1 释放遗留写锁（:148-153）。
- 段头：`src/internal/irt_types.h:20-72` 128B，字段 magic@0/version@4/write_seq@16/owner_pid@24/stats@28/crc32@44/off_*@56-68；**无 boot_id/digest/epoch 字段**。CRC 范围刻意排除 write_seq/owner_pid/stats（`irt_shm.c:35-55`）。

**结论**：同机"进程重启（段仍在）"的存活/接管/写锁恢复逻辑在源码中**已实现**（`irt_shm.c:116-153`），但"板上可测"有前置：其中 `kill(pid,0)` 存活探测在 G1 因 SylixOS 无 fork 标 **N/A 未验证**（21 号:125,170），且探针需两进程协作（无 fork 下须独立可执行 + PID 传递，见 §3.2/§5）。故准确表述为"源码已实现、板上可测性待前置验证"，不预设板上必过。它 ≠ IR6 的 `proc_restart_no_fullsync`（集群摘要续传语义，需多节点 + 摘要判定）。

### 2.2 整机重启与摘要续传（设计有、代码无）

- 设计（13 号:198）：boot_id 不落盘，换 id 先校验结构 hash + 值摘要，一致续传、不一致全量；整机重启段丢失 → 从字典序最大可达节点拉全量。
- 代码现状：整机重启段丢失走 `O_EXCL` 全新段（`irt_osal_sylixos.c:56-63`），不读任何持久化 boot_id/摘要；`struct_hash`/`value_digest`/`digest_match` 全仓 `.c/.h/.cpp` 0 命中；IR6 两数字 `proc_restart_no_fullsync`/`machine_restart_pull_full` 仅文档占位（14 号:272-273、19 号:191-192、20 号:27,73），`test_vsoa_restart.cpp` 不存在。

**结论**：IR6 两态**未实现**，是真实行为缺口（与 G2 的订阅重建同类）。代码中仅在 3 处注释提及该名字作为设计意图（`rtdbd_peers_global.c:42`、`.h:29`、`rtdbd.c:2206`，描述 boot_id 用于 IR6 判定），**无数据全量拉实现、无数字落库字段、无 `test_vsoa_restart.cpp`**。需澄清：确有 `RTDBD_DEFER_TRIGGER_FULLSYNC`（`rtdbd_session.h:144`、`rtdbd.c:2169-2191`、`rtdbd_peers_apply.c:46`），但它仅做 JOINING→ACTIVE 成员接纳状态机推进（`rtdbd.c:2166-2168` 明注"不声称已做数据同步传输"），**非 IR6 的数据全量拉/摘要续传**，不得据此认为 IR6 已实现。G3 单台不能取 IR6 真值，只能取"段是否跨进程存活"等物理前置事实。

### 2.3 boot_id 与单调钟

- boot_id：`rtdbd/src/cluster/rtdbd_peers_global.c:15-16,43-69` 进程级静态，`:58` 用 `clock_gettime(CLOCK_MONOTONIC)`，`:66-68` `sec<<32|nsec ^ rand()<<16`，注释 :53-54 明"仅用于 IR6 是否首次启动判定、非密码学随机、每次启动高概率不同"——**非保证唯一**。唯一调用点 `rtdbd.c:2205-2207` main 入口。
- boot_id 用途边界：仅线格式透传（`rtdbd_peer_table.c:53`、`protocol.h:303-313`），**无代码比较本地/对端 boot_id 决定全量**。
- 单调钟 OSAL 差异：POSIX `irt_osal_posix.c:20-29` 首选 `CLOCK_MONOTONIC_RAW`、失败退化 REALTIME；SylixOS `irt_osal_sylixos.c:27-36` 首选 `CLOCK_MONOTONIC`、失败退化 REALTIME。`irt_time_realtime_ns()` 两边用 `CLOCK_REALTIME`。**rtdbd 主路径绕过 OSAL 直接读 `CLOCK_MONOTONIC`**（`rtdbd.c:158-163,205-210`）；`rtdbd.c:2207` 是 `rtdbd_boot_id_generate()` 调用、钟读取发生在其内部（`rtdbd_peers_global.c:58`），非主路径直接读钟。
- 上电起点：SylixOS `CLOCK_MONOTONIC` 上电起点**未验证**（21 号:145）；G2 已实测 RTC=2000（22 号），墙钟不可信已被印证。进程重启后单调值是否连续、boot_id 是否变化，是 G3 单台可测的物理事实。

### 2.4 epoch / IR7

- 已实现仅 session 身份字段 `service_id`+`uint64_t epoch`（`rtdbd_session.h:80-83`，初始化 0 于 `rtdbd_session.c:39`），但**未参与裁决**（v3.12-M3-IR证据.md:852-858）。
- 未实现：`snapshot_epoch`/`terminal_hash`/`dict_max_snapshot_match`（13 号:443、14 号:261,272、19 号:191,200），代码 0 命中。
- G3 单台只能覆盖物理前置（段存活、无 epoch 持久化、单调钟连续性、boot_id 变化），**不能**覆盖"同 epoch 双写冲突 → 终态等于字典序最大节点快照"（需 F2）。

## 3 G3 三层切分与单台 harness 方案

### 3.1 三层边界

| 层 | 内容 | 条件 | G3 本轮动作 |
|---|---|---|---|
| L1 单台可证伪事实 | 段跨进程存活/owner 接管/seqlock 恢复、单调钟进程重启连续性、boot_id 进程级变化、段头无 epoch/摘要字段 | 单台 + 设备重启授权（仅进程重启，非整机） | 设计 harness + 探针（本方案），实现另立变更卡 |
| L2 IR6 两态真值 | `proc_restart_no_fullsync`、`machine_restart_pull_full` | 需实现摘要续传 + F4 整机重启 + 多节点比对 | 只登记为缺口，不取数、不填字段 |
| L3 IR7 epoch 隔离 | `terminal_hash == dict_max_snapshot_match`、同 epoch 双写收敛 | 需 F2 六节点 + epoch 裁决实现 | 只登记为缺口，不取数 |

### 3.2 单台 harness 探针设计（L1，供后续实现）

仿 `sylixos_smoke` 注册范式（顶层 CMake SylixOS 条件 target），新增 `sylixos_semantics_probe`（G3 实现阶段产出，不在本方案落地）。**无 fork 编排前置**：SylixOS 无 fork（21 号:125、22 号:122/158），探针须做成分离的可执行（owner-writer / attach-reader 两个 program + PID 传递 + 时序握手），不得依赖 fork；`kill(pid,0)` 在板上尚未验证（G1 标 N/A），探针若依赖它须把"板上 kill(pid,0) 语义"作为先决验证项，FAIL 即如实记录、不伪造。

1. **段存活/owner 接管探针（依赖 kill(pid,0)，前置验证）**：owner-writer 用 instance `g3probe` 注册点位/写值后 SIGKILL（不走 detach，避免 unlink）；attach-reader 同 instance attach，断言段仍在、值仍在、`owner_pid` 改写为 reader 的 pid。依据 `irt_shm.c:116-145`。**板上 kill(pid,0) 未验（21 号:125,170），本探针结论受此前置约束**。
2. **seqlock 写锁修复探针（确定性注入，与上条分离）**：SIGKILL 命中时刻不确定、无法保证恰好停在写锁内，故不把"奇数 write_seq +1"挂在探针 1 的 SIGKILL 之后；改为复用 `tests/soak/fault_injection_test.c:73,286` 的手动 `corrupt_write_seq_odd()` 手法**确定性制造奇数态**，再 attach 断言 `irt_shm.c:148-153` 的 +1 修复。两类证据分开标注来源（SIGKILL 真实崩溃 / 手动 corruption 注入）。
   - 注意：真实头 128B（`irt_types.h:59`），**不要沿用** `fault_injection_test.c:58` 的 `HEADER_SIZE 64`。
3. **单调钟/boot_id 探针（观测为主）**：进程启动/退出各打印 `clock_gettime(CLOCK_MONOTONIC)`、`CLOCK_REALTIME`、`irt_time_now_ns()`、`rtdbd_boot_id_generate()`；单调值跨进程重启递增可作断言，但 **boot_id 由 `sec<<32|nsec ^ rand()<<16` 生成、仅"高概率不同"（`rtdbd_peers_global.c:66-68`），降为观测项、不作 PASS/FAIL 硬断言**，避免偶发 FAIL。依据 `rtdbd_peers_global.c:55-69`。
4. **段头字段只读 dump**：打印 magic/version/write_seq/owner_pid/crc32/off_*，断言无 epoch/digest 字段可读写（证明 L2/L3 判定缺物理载体）。可用 `indurtdb_h_self_check()`（只校验 magic/version，不校验 CRC/owner，需注明覆盖边界）。
5. **整机掉电语义**：本轮不测（需 F4）；仅用 `shm_unlink` 逻辑注入证明 O_EXCL 新段分支，明确标注"逻辑分支证据 ≠ 掉电真值"。

**退出判定**：每类探针 `[G3-n] PASS/FAIL` 打印 + 总 `G3_RESULT: PASS/FAIL` + exit code（沿用 G2 harness 证据纪律：断言 + 退出码，纯回显不算）。

## 4 验收判据（方案退出门）

1. 三层边界清晰：L1 单台可做、L2 需 F4 + 摘要续传实现、L3 需 F2；无把 L2/L3 误标为单台可做。
2. 每条事实判定有源码行号证据（irt_shm.c:116-153、irt_types.h:20-72、rtdbd_peers_global.c:55-69、OSAL 时钟 :20-36 等），可机械复核。
3. 明确"IR6 两态/IR7 epoch 均未实现、仅文档占位"，不把设计当实现、不填 B 段 `fields`。
4. 单台 harness 探针设计给出可证伪断言与退出码纪律，标注真实头 128B 与 self_check 覆盖边界。
5. 边界守住：不改对外口径/发布门 FAIL 8/冻结用例名，不宣告 F2/F3a/F4 就绪，实现另立变更卡 + 设备重启授权。
6. 独立评审通过（fresh context + 源码行号回核 + 三层边界核对）。

## 5 风险与开放问题

| 风险 | 处置 |
|---|---|
| SIGKILL owner 后段残留 | 探针结束须清理段/进程，失败回滚；不碰生产数据 |
| **无 fork 两进程编排 + kill(pid,0) 板上未验（P1）** | SylixOS 无 fork（21 号:125、22 号:122/158），探针须做成分离可执行 + PID 传递 + 时序握手；`kill(pid,0)` G1 标 N/A 未验（21 号:170），作为探针 1 先决验证项，FAIL 即如实记录 |
| **seqlock 修复 SIGKILL 触发不确定（P1）** | 不把奇数 write_seq +1 挂在 SIGKILL 之后；改用 `fault_injection_test.c:73,286` 手动 corruption 确定性制造奇数态，两类证据分开标注来源 |
| boot_id "高概率不同"非唯一 | 不把 boot_id 变化当 IR6 真值，仅作观测项、不作 PASS/FAIL 硬断言（§3.2 探针 3） |
| 单调钟上电起点未验 | 单台只测进程重启连续性；上电起点留 F4 实测 |
| 段头无 epoch/摘要字段 | 明示 L2/L3 判定缺物理载体，需实现阶段补设计（另立 SDD） |
| 设备操作需授权 | 进程重启探针也涉及板上进程 SIGKILL，须设备操作授权；整机重启不在本轮 |

**开放问题（待用户/评审裁决）**：
- r-A：G3 是否按本方案只做「单台 L1 事实探针 + L2/L3 缺口登记」，还是要求本轮就设计 L2 摘要续传的实现方案？（建议：本轮只做 L1 事实与缺口登记，L2/L3 实现另立 SDD，因依赖 F4/F2 且是真实行为缺口）
- r-B：单台 L1 探针是否需要现在就进入实现（变更卡 + 设备操作授权），还是先冻结方案、待用户另行授权？（建议：先冻结方案、本方案不授权开工）
