## 3 重点争议项：请独立裁定 `check_api_count.py` 的等价闭环

**复评原话**（复评第二签整改项 1）：「`check_api_count.py` 基准同步 56/118 并说明 D8」，理由「§9.1 已冻结新增 `indurtdb_h_wait_sync()`，改的是期望常量与说明文字，零 `rtdbd` 实现依赖」。

**实施方的技术异议（如实提请，不擅自豁免）**：
- 实测 `grep -rn wait_sync include/ src/ rtdbd/ client/` 为**空**——该 API 在 §6「不得开工写代码」禁令下尚未实现，头文件实际仍是 **55** 个 v2 函数。
- 若机械改 `EXPECTED_V2=56`，则 `check_api_count.py` 每次运行都会因「实际 55 ≠ 期望 56」而 FAIL，Stage 0.5 恒红，全量门禁 `ALL GREEN` 不再可能。用常量造假既不是闭环，也违反「门禁必须可证伪、不允许恒红或恒绿」。
- 采用的等价方案：保持当前基准与实现一致的 **55/117**；`PLANNED_V2_APIS` 台账显式登记 D8 增量，`--json` 暴露目标 **56/118**（机械可核验），SDK 手册首段同步说明；并加「计划 API 已落地但基准未同步 → FAIL」约束，防止实现期静默漂移（`--self-test` 第 4 项验证）。

**请复评人裁定**（二选一或给第三条路）：
- **A**：认可等价闭环，`HC1` 可置 `closed=true`；
- **B**：坚持字面要求，则须先解除 §6 禁令实现该 API（属于开工写代码，超出本次复验范围），`HC1` 保持 `false` 并说明理由。
