## 风险点

- 【防自审自批判据失效·HC3】`release_gate.check_conditions()` 对 `closed=true` 的 `verified_by` 只做 `_resolve(vb,root).is_file()`（存在性），未复用 `check_review_evidence.py --require-second` 校验其内容确为 `ai-independent`/`independent` 的独立复验证据；`verified_at` 仅 `re.fullmatch(r"\d{4}-\d{2}-\d{2}")`。提请单 §1 明文以「`verified_by` 机械强制」担保「实现者不得自置 closed」，13 号 §11.3 与 RED 证据 §5 亦承诺「必须指向独立复验证据文件，否则视为无效」。实测坏样本：`verified_by` 指向 `/etc/hostname` 或 /tmp 临时文件、以及 `verified_at=9999-99-99` 均被放行（findings=0）；`test_checkers.py` 中名为 `bogus independent-review evidence rejected` 的用例实际只断言「指向不存在文件」，用例名与断言不符。当前因 B 段 7 项 pending + IR 0 个，发布门仍 FAIL 12 条，此洞暂不导致放行；但一旦实现期 B 段转 measured、IR 注册齐备，实现者可自置 closed 并令 `verified_by` 指向任意存在文件而通过这一关，历史「有条件通过」的第二签又不会重新校验本轮 HC 闭环——属面向实现期的真实缺口。
- 【门禁金丝雀覆盖不全·HC1】`gate_canary.guard_alive()` 是 7 个文本标记（`can't open file`/`No such file or directory`/`Traceback`/`ModuleNotFoundError`/`ImportError`/`SyntaxError`/`FileNotFoundError`）的启发式黑名单，源码注释却称「任何崩溃特征一律视为守卫失活」。实测 `guard_alive("Segmentation fault (core dumped)")=True`、`guard_alive("")=True`、`guard_alive("guard exit 2 (custom msg, no marker)")=True`；构造「坏样本返回非 0 但输出不含上述标记」的假守卫，`main()` 判为可证伪并 exit 0。RED 证据 §3 所述具体缺陷（脚本不存在 → python 返回 2 被误判）确已修复，针对当前 8 个守卫的「脚本缺失」这一类有效；但「排除所有脚本缺失/崩溃型假绿」是过度宣称，不能据此认定判据完备。
- 【等价闭环的程序性风险·HC1】api_count 由「基准 56/118」改写为「当前基准 55/117 + `target_*` 目标 56/118 台账」，技术异议成立且方案可证伪性不降反升（增加落地漂移防护），**不是**规避复评要求；但判据文本是被评审方在提请单 §2 自行改写、并在 13 号 §10.3/§382（实现方所写）标为「实现已闭环」，第二签原文把等价性裁定权明确留给独立复验。若不把这次改写书面留痕为「经独立复验确认的判据等价替换」，易被后续复验误读为「基准已同步 56/118」，也为「以等价为名自行放宽硬条件」开了先例。
- 【文档数字与实测不符】13 号 §10.3 表格/§384、变更卡第 61 行的「FAIL 7 条原因 / 日志缺失」、台账 HC1 note「canary 4→7 项」均为陈旧或夸大描述（实测 12 条 / 日志实存 / 8 项）；变更卡验收判据第 29 行仍以「UDS 写 P99 ≤ 10 μs 不退化」作回归目标，与 13 号 §10 表把该项移入 B 段的口径存在张力。这些不影响「发布门 FAIL」的结论方向，但削弱裁决单一真源的可信度。
- 【IR 注册/门禁日志判据是静态文本、可与真实 ctest 脱节·HC3 纵深】`check_conditions()` 对 `ir_snapshot` 只判「7 个 IR 名字是否出现在文件内容里」（`release_gate.py:120-129`），不实时调用 `ctest --test-dir build -N`；对 `full_gate_log` 只查含 `ALL GREEN`、不含 `[SKIP] canary`（:131-147），不校验日志新鲜度或产物对应关系。实测：本人在 /tmp 构造的台账把 `ir_snapshot` 手写为含 7 个 IR 名字、`gate_log` 写 `ALL GREEN`、B 段 7 项全 measured 后，`check_conditions()` 返回 `findings=0`（放行），而同一时刻真实 `ctest -N` 的 IR 用例数为 **0**。13 号 §11.2/台账 note 已声明「判据只认内容不认时间戳」，属已知设计选择，当前快照诚实（0 个 IR）且发布门因 B 段 pending 仍 FAIL，故不据此返工；但复评硬条件 3「IR1–IR7 出现在 ctest -N」的核心判据在实现期可被手写快照绕过，须在 H-2 收紧。
