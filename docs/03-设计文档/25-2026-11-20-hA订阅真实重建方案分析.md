## 1 问题与目标

VSOA 写入 + 定向 NOTIFY 最短闭环已在 Linux 与 SylixOS 板上通过（G2 `E2E 5/5`）。当前客户端断链重连后订阅不会恢复：UDS 与 VSOA 两侧断链都不产生 `RECONNECT`/`REBUILD_SUBS`/`CLOSE` 入队，`on_reconnect`/`on_rebuild_subs` 执行器只会把订阅安装为空集，断链前没有任何订阅快照，重连后必须客户端重新发 hello + `/subscription/add` 才能恢复通知。

**关键前提（s-0，已裁决）**：源码 `rtdbd.c:2137-2139` 原有意裁决"重连即新连接、无历史订阅可重建、装空集是可证伪的正确结果（VSOA 重建属 M3.3+）"；**用户 2026-11-20 书面裁决 s-0=必须自动重建，推翻该既有立场**（见 §5.1）。22 号原仅"另立变更卡"未定需求，本轮补齐需求裁决。

**目标（s-0 已定为"必须"）**：设计一套"断链入队 + 旧订阅真实快照/恢复 + 端到端验证"的机制，双通道共用队列与快照抽象、执行器按 transport 分离，给出可证伪判据；按 s-A 裁决，服务端只自动重放点集、**客户端仍须重新 hello** 建立身份。不改 opcode/ABI，可单台开发测试。

## 2 事实基础（源码逐行核对）

### 2.1 缺口是"两层同时缺"，不是单层

- **defer 框架已具备**：动作枚举 `rtdbd_defer_kind_t`（`rtdbd_session.h:138-147`：RECONNECT/CLOSE/REBUILD_SUBS/TRIGGER_FULLSYNC/PEER_ADD/PEER_DEL）、队列 256 + dropped 计数（`session.c:187-218`）、drain + generation stale 检查（`rtdbd_defer_actions.c:13-41,58-92`）、主循环每轮尾调用 `drain_deferred_actions()`（`rtdbd.c:2866`）。
- **但入队点只有 peer 变更**：生产代码唯一 `rtdbd_defer_push*` 调用在 `rtdbd_peers_apply.c:39-50`（PEER_ADD/TRIGGER_FULLSYNC/PEER_DEL）；UDS 断链的两条主路径（`rtdbd.c:2813-2821` outq_flush 失败、`:2842-2847` handle_request 失败，后者含 `recv_all==0` 对端关闭子情况 `rtdbd.c:1865`）都走 `close→conn_discard_outq→conn_init`，VSOA 断链（`vsoa_adapter.c:115-121` 的 `session_free`）亦**不入队**任何会话动作。
- **执行器只装空集**：`defer_on_rebuild_subs`（`rtdbd.c:2135-2144`）执行 `rtdbd_session_install_subs(&c->session, NULL, 0)`，`on_reconnect` 直接复用（`:2192-2196`），没有读旧订阅、没有 service_id 快照。

**既有设计裁决（已被用户裁决推翻）**：`rtdbd.c:2137-2139` 注释原声明"UDS 侧重连即新连接，没有历史订阅可重建；显式替换为空集是**可证伪的正确结果**，不假装有历史订阅（VSOA 侧按 session.sub 重建属 M3.3+）"，即"装空集"原是有意为之的设计。**用户 2026-11-20 s-0 裁决"必须自动重建"，明确推翻该立场**——本方案据此把"装空集"视为待修补的行为缺口（实现阶段须同步订正该注释口径，避免代码注释与新设计矛盾）。

**结论**：s-0 已定为"必须自动重建"：单纯补入队不够（执行器无重建语义）、单纯改执行器也不够（无入队触发），必须两层一起补。

### 2.2 订阅真源与持久性

- 订阅状态在 `rtdbd_conn_t.session`（`rtdbd.c:234-255`），操作委托 `rtdbd_session_*`（`session.c:79-141`）；`generation` 每次 `conn_init` 递增，用于 stale 防误伤。
- VSOA 订阅写入链：`vsoa_on_cmd`（`vsoa_adapter.c:315-520`）→ opcode（`/subscription/add`=4，`rtdbd_dispatch.c:20-50`）→ `rtdbd_dispatch_subscribe_authz` → `rtdbd_session_subs_add`（`:454-462`）。`/subscription/set`(op18) 实际未实现（落 `vsoa_main_handler`→`rtdbd_dispatch` 返回 NOT_IMPLEMENTED）。
- **断链即丢失**：UDS `conn_init()` 清 `nsubs`/`sub`（`rtdbd.c:285-309`），VSOA `session_free()` 整体释放（`vsoa_adapter.c:115-121`）；`conn_discard_outq`/`session_reset` 都不保存订阅点集。无 `service_id→点集` 映射。
- service_id 现状：来自 hello token 表（`vsoa_adapter.c:125-190`，写入 `sess->service_id`），当前**唯一生产用途是审计参数**（`:489-493`，且生产 main 未注入 audit）。UDS session 的 service_id 恒空（`rtdbd_session.h:80-84`）。

### 2.3 执行器是 UDS 绑定，不能直接给 VSOA 用

- `rtdbd.c:2180-2200` 注入的四个执行器全基于 `g_conns`：`defer_session_generation`/`defer_session_alive`（`:2107-2121`）查 UDS 槽；`defer_on_rebuild_subs` 对 `g_conns[sid]` 装空集。注释明写"VSOA 会话不映射 g_conns，RECONNECT 仅对 UDS 有效"（`:2192-2196`）。
- 若 VSOA 断链直接入队现有 RECONNECT，`sid` 会落到 UDS 槽 → **无效或误伤**。defer 队列/drain/快照抽象可共用，**执行器必须 transport 化**（sid 命名空间、会话定位、generation 来源、快照重放分离）。

### 2.4 service_id 重放的串台风险

- service_id 可被多连接共用（测试中 A/B 同为 `plc-line-1`，`test_vsoa_notify.cpp:638-640`）；仅以 service_id 为快照键会串台。快照键须再含连接身份（VSOA `vsoa_cli_id_t`/cli 槽）或 epoch/generation，并重放时校验 token 身份（uid/partition/role）。
- epoch 字段在 session 声明但全仓无生产读写（`rtdbd_session.h:83`、`session.c:39`），不能依赖现有 epoch 做隔离；generation 是现成的 stale 防线（`rtdbd_session.h:149-170`）。

### 2.5 测试现状

- `tests/integration/test_vsoa_reconnect.cpp` **不存在**；IR3_DeferredQueue 是纯逻辑 spy 测试（`IR3_DeferredQueue.cpp:76-95,193-216`，断言 callback_reconnect_attempts=0、只验执行器框架，不碰真实订阅表/service_id）。
- `sub_rebuild_ok` 全仓仅设计文档（13 号:439），源码与测试 0 命中；无任何 ctest 能因"断链后订阅未恢复"而 FAIL。`test_vsoa_notify.cpp`/`test_vsoa_e2e.cpp` 均无断链/重连用例。

## 3 方案设计

### 3.1 总体结构（共用机制 + transport 执行器分离）

| 层 | 共用/分离 | 内容 |
|---|---|---|
| defer 队列 + drain + generation stale | **共用** | 复用 `rtdbd_session.c` push/pop、`rtdbd_defer_actions.c` drain，不新增队列 |
| 订阅快照 | **共用抽象** | 新增"会话订阅快照"结构（点 id 集合 + 身份/partition + generation/epoch），断链时保存、重连时重放 |
| 断链入队触发点 | **分离实现** | UDS 断链路径（`rtdbd.c:2813-2847`）、VSOA `vsoa_on_cli` disconnect（`:115-121`）各加入队 |
| 执行器 | **分离实现** | UDS 执行器走 `g_conns[sid]`；VSOA 执行器走 `cli[]` 槽 + service_id 重放校验， sid 命名空间隔离防误伤 |

### 3.2 断链入队

1. UDS：在 `recv_all==0`/`handle_request` 失败/`outq_flush` 失败的三条断链路径（`:2813-2847`），于 `conn_init` 之前 push `RECONNECT`（或 `REBUILD_SUBS`），携带 slot idx + generation；注意 `conn_init` 会递增 generation，须保证快照按旧 generation 保存、入队 action 的 `target_generation` 指向新槽位预期值。
2. VSOA：在 `vsoa_on_cli` disconnect（`:115-121`），`session_free` 之前保存快照并 push `REBUILD_SUBS`，携带 cli 槽 + service_id + generation；SDK 回调内只入队、不做重连（遵守 `vsoa_client_connect` 不得在回调内调用的约束，靠循环尾 drain 满足）。
3. 入队失败（队列满 dropped）需计数可观测（`session.c` 已有 dropped 计数），不静默。

### 3.3 订阅快照与重放

- 快照内容：`point_id[]`（`subs[]` 有序视图）、连接身份（UDS: slot+generation；VSOA: cli 槽+service_id+uid/partition/role）、绑定 generation/epoch。
- 存储：进程内定长结构（上限 `RTDBD_SUB_MAX`），零动态分配或受控分配（与 session 现有风格一致），按 transport 分表或带 transport tag，防 sid 串台。
- 重放：执行器 `defer_on_rebuild_subs` 改造为 transport 感知——UDS 分支装到 `g_conns[sid].session`，VSOA 分支按 service_id + cli 槽找回/新建 session、校验 token 身份后 `rtdbd_session_install_subs`。**不新增 opcode、不改 ABI**，订阅语义仍是既有 `SET_SUBS`/`/subscription/add` 的 install。
- service_id 串台防护：快照键 = transport + 连接身份（cli 槽或 slot）+ generation；重放时校验身份一致，不一致 no-op + 计数（沿用 stale 语义）。

### 3.4 与 UDS 写裁撤（q-B）的关系

q-B 裁决"SylixOS 上 UDS 不承载写、身份走 VSOA hello"发生在 G2；h-A 的订阅重建属**读侧通知语义**，不碰写通道，**与 q-B 不冲突**（Linux UDS 写/读行为保持，VSOA 侧重建走 service_id、不免除 hello）。边界澄清：SylixOS 侧随 q-B 裁 UDS 写通道后，UDS 订阅（读侧）是否在 SylixOS 保留取决于部署形态——G2 已使 rtdbd 在 SylixOS 以 VSOA 单通道跑通；本方案的 UDS 重建执行器为通用能力、Linux 侧启用，SylixOS 侧若 UDS 通道不启用则该分支自然无连接可重建，不影响 VSOA 分支。本方案不改任何平台写通道口径。

### 3.5 测试策略（单台可完成，不依赖 F2/F3a/F4）

- 沿用 13 号 §11.1 已冻结的载体文件 `tests/integration/test_vsoa_reconnect.cpp` 与 ctest 名 `IR3_DeferredQueue`（**不改名、不新增 opcode/用例名**）：三阶段——① 建连+hello+订阅点位 P，写点收 NOTIFY（基线）；② 模拟断链（VSOA 断开/UDS close），断言 defer 队列收到 REBUILD_SUBS、callback 不在 SDK 回调内立即执行（callback_reconnect_attempts=0 口径保留）；③ 重连（新 cli 槽/同 service_id），drain 后断言订阅自动恢复、写点再收 NOTIFY——`sub_rebuild_ok` 是 B 段**数字落库字段**（13 号:439，载体 `v3.12-B段数字落库.json`），由该用例**产生并写入已有字段**（非新 ctest 名；本方案不改字段、不填数字，填写留 P5 真机取证）。
- 负例：service_id 不匹配/身份不一致 → 不重放（no-op + 计数）；generation 陈旧 → stale no-op。
- UDS 侧对称用例：断链→同 instance 重连→订阅恢复（可用单进程多连接模拟，无需多节点）。

## 5 风险与开放问题

| 风险 | 处置 |
|---|---|
| 快照内存/容量（RTDBD_SUB_MAX 上限、多连接） | 定长 + 上限 + dropped 计数可观测，沿用 session 现有风格 |
| generation 时序（conn_init 递增与入队先后） | 入队在 conn_init 前保存旧快照、action target_generation 指向新槽预期，重放时 stale 校验 |
| **VSOA 侧 generation 来源未定（P2）** | UDS generation 来自 `conn_init` 递增（`rtdbd.c:288`），VSOA 不映射 g_conns、epoch 无生产读写——实现阶段须定义 VSOA generation 来源（cli 槽身份 + 服务端独立计数或新增 session 字段）；注意 generation 只防"槽位复用误动作"，service_id 串台靠 §3.3 连接身份键 + 重放校验防，两者不混为一谈 |
| service_id 多连接串台 | 快照键含 cli 槽 + generation，重放校验身份，不按 service_id 单键 |
| VSOA SDK 回调内不可重连 | 入队与重放分离，靠循环尾 drain 执行（vsoa_client_connect 约束） |
| 不改 opcode/ABI 前提下恢复订阅 | 复用既有 install_subs/SET_SUBS 语义，仅内部触发，不新增线协议 |
| 客户端须重新 hello | 重连后 service_id 需新 hello 建立身份；本方案的"自动重建"指服务端保存的点集在新会话建立后重放，不免除 hello（见开放问题） |
