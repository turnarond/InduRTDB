## 3. 关键设计裁决

### 3.1 跨进程取证通道：mmap 共享页 + seqlock + `__atomic_*` builtins（闭环复评 B-1 / m-4）

**问题**：`run_server()` 在 fork 子进程内创建 adapter（`test_vsoa_e2e.cpp:114`），父进程拿不到子进程内计数；ready pipe 仅回传 `uint16_t port`。v1「第二根 pipe + SIGTERM 前写回」不成立；v2「普通 `snap_seq` 轮询」在 C++ 跨进程内存模型下是 data race（UB，可被优化成死循环、32B 快照撕裂），且 seq 与「本次 write 的刷新」无绑定（超时轮也推进 seq）。

**同步原语裁决**：**只用 GCC `__atomic_*` builtins**（`__atomic_load_n` / `__atomic_store_n` / `__atomic_fetch_add`），**不用 `_Atomic` / `stdatomic.h`**——本仓 `CODEBUDDY.md` 明定「只用 `__atomic_*` builtins，禁用 `stdatomic.h`（SylixOS 支持不完整）」，复评建议的 `_Atomic uint32_t` 不得照抄。测试 TU 为 C++17/GCC，builtins 直接可用。

**共享页结构**（fork 前 `mmap(NULL, sizeof(notify_probe_t), PROT_READ|PROT_WRITE, MAP_SHARED|MAP_ANONYMOUS, -1, 0)`；`MAP_ANONYMOUS` 页内核已清零）：

```
uint32_t magic;        // 原子，0x4E4F5449：标记「子进程已完成初始化」，非「防未初始化页」
uint32_t child_fail;   // 原子，子进程内断言失败计数
uint32_t seq;          // 原子，seqlock 序号：奇数=写中，偶数=稳定（本仓 irt_seqlock.h 范式）
uint32_t snap_seq;     // 原子，仅诊断量（不再作为屏障，v2 的主要错误）
rtdbd_notify_counters_t init_snap;  // 子进程 create adapter 后、任何写之前
rtdbd_notify_counters_t last_snap;  // 每轮「有输入事件」后刷新
```

- 测试 TU 内补 `_Static_assert(sizeof(rtdbd_notify_counters_t) == 32, ...)`（防未来 padding 漂移使「初始全 0」判据失真）。
- **子进程写**（仅当 `select` 返回 `r > 0`、`vsoa_adapter_input()` 返回后；**超时轮不刷新、不推进 `snap_seq`**，消除 v2「无关轮次提前满足条件」）：
  1. `__atomic_store_n(&seq, seq0+1, __ATOMIC_RELEASE)`（奇数，写中）
  2. `last_snap = rtdbd_vsoa_adapter_notify_counters(adapter)`（32B 普通拷贝，被 seqlock 保护）
  3. `__atomic_store_n(&snap_seq, ++v, __ATOMIC_RELEASE)`（诊断）
  4. `__atomic_store_n(&seq, seq0+2, __ATOMIC_RELEASE)`（偶数，发布）
- create adapter 后先在 seqlock 写临界区写 `init_snap`，最后 `__atomic_store_n(&magic, 0x4E4F5449, __ATOMIC_RELEASE)` 发布「初始化完成」。
- **父进程稳定读**（`seqlock_read`）：`s0 = __atomic_load_n(&seq, __ATOMIC_ACQUIRE)`；若奇数则重试；读 `init_snap`/`last_snap`；`__atomic_thread_fence(__ATOMIC_ACQUIRE)`；`s1 = __atomic_load_n(&seq, __ATOMIC_ACQUIRE)`；`s0 != s1` 则重试 → 消除撕裂。这正是本仓 `irt_seqlock.h` 的既有范式。
- **主屏障（取代 v2 的 `snap_seq >= 写前+1`）**：父进程先等 `magic == 0x4E4F5449`（acquire 原子 load，1ms 轮询、上限 2s、超时 FAIL），稳定读 `init_snap` → 发 write RPC 等 reply（`vsoa_adapter.c:496` dispatch 同步先于 `:518` cli_reply，reply 到达即「门控已执行」屏障）→ 等 A 收到 datagram → **原子轮询稳定读 `last_snap.hits >= expected`（`expected = init_snap.hits + 1`），1ms 间隔、上限 2s、超时 FAIL**；随后**断言 `last_snap.hits == expected` 精确相等**（若门控坏→hits 不增长→超时 FAIL；若多发→hits>expected→精确断言 FAIL，保留证伪力）。`snap_seq` 降为诊断量，不承担屏障职责。
- **读取时序**：**所有共享页读取都在 `kill(SIGTERM)` 之前完成**；`kill` 后只取 `wstatus`（避免子进程恰在写中途被杀的窗口）。
- **无** signal handler、短读、EINTR、EOF、SIGTERM 竞态；改动仅限测试 TU，不新增 opcode/URL、不改协议契约。方案 B（新增 `/stats` URL）违反 §9.3 URL 清单，方案 C（单进程 fake session）丢失真实 `static vsoa_notify_dispatch` 门控循环，均否决。
- **落地切片 4「ON 侧 getter 冒烟」**：getter 在真实 ON 进程首次实跑，覆盖「初始全 0 / `NULL → 全 0` / 写后精确增量」；getter 冒烟**只在 `test_vsoa_notify.cpp` 中实跑**（adapter 属 VSOA 条件块内目标），纯逻辑层不链接 adapter（复评 m-5）。
- **门控接线自动化回归：仅部分覆盖，不过度声称**：三类会话 + 计数快照 + `quick==false` + M-5a（订阅门禁行为回归，非顺序不变量独立守卫，见 §3.3 第二签 I-1）构成行为级回归，但**无法逐字段观察 subtab 状态是否被未订阅会话消耗**；该部分如实留白并登记切片 5 之后待办，**不写「不再只靠人工读码」**。

**用例隔离（闭环复评 M-2）**：`a->notify_counters` 是 adapter **全局累计**（`vsoa_adapter.c:249,286`，`calloc` 全 0）。本方案四类用例（主判据 / 死区 / M-5a / 反向验证注入版）**每个用例独立 `fork()` + 独立 `mmap` 页 + 三类会话拓扑重建**，`init_snap` 取自该用例自己的 server；或共用一个 server 时每用例显式 `rtdbd_notify_counters_reset` 并重新取 `init_snap`。**v3 采用前者**（每 `TEST` 独立 fork，避免全局累计串扰使 `hits == 1` 恒红）。

### 3.2 可证伪判据（闭环复评 B-1/B-2、M-3）

**`peer_notify_leak` 真实语义**（`rtdbd_session.c:302`）：「非订阅者 / sync_peer **差点收包 → 记泄露并绝不外发**」，不是「实际发出的次数」。`deliver_guard` 仅对 `gate == HIT` 会话调用（`vsoa_adapter.c:253-256`），正常路径非法会话分支不可达 → **`leak == 0` 与客户端是否收到无因果关系，降级为辅助观测**。

**正向判据**：
- ① A 收到 1 帧定向 NOTIFY，`point_id=5`、值正确、`quick == false`；
- ② **确定性负向观察窗（闭环 B-2）**：同步点（write RPC reply 到达 + A 收到 datagram）之后，对 **B、C 各自**执行 `N >= 300` 轮（N 不小于 A 观察窗 `test_vsoa_e2e.cpp:696-707`）的 `select(10ms)` + `vsoa_client_input_fds`，**窗内持续 `ASSERT_FALSE(received)`**。三个 client 各有独立 `fd_set`，`pump_client`（`:210-225`）只等 RPC reply、不能替代 datagram 泵。同步点之前另对 B/C 的连接、`/notify` URL 订阅、hello、pump 成功逐项 `ASSERT`（正向保证）。
- ③ `init_snap` 全 0；`last_snap.hits - init_snap.hits == 1`（精确增量）；
- ④ 死区用例 `rbe_gate_misses` 增量 == 1 且 A 不再收（§3.3）；
- ⑤ `peer_notify_leak == 0`（辅助观测）、`child_fail == 0`、`wstatus` 正常（判据见下）。

**`wstatus` 与子进程断言失败控制流（闭环复评 M-1）**：
- 「正常」= `WIFSIGNALED(wstatus) && WTERMSIG(wstatus) == SIGTERM`；**`WIFEXITED` 任意退出码（含 0）均判 FAIL**（现有范式 `test_vsoa_e2e.cpp:714-716` 是 `kill(SIGTERM)` + `waitpid` 且从不检查 wstatus）。
- 测试 TU 定义 `CHILD_ASSERT(cond)`：失败时 `__atomic_fetch_add(&child_fail, 1, __ATOMIC_RELEASE)` + `_exit(2)`（不再继续跑 `[[noreturn]]` 循环），使父进程可归因；`child_fail` 亦须由父进程稳定读后断言为 0。
- `kill` 之前先 `waitpid(pid, &st, WNOHANG)` 判定子进程是否已提前退出（提前退出即 FAIL）。

**反向验证：两个中和点、两次 RED、精确注入行（闭环复评 M-3）**
