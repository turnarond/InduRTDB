## 1 问题与目标

h-C 目标是在 SylixOS 裁 UDS 主路径后保住外部 PC 监控台。27 号方案发现 P0：外部 PC 直连 rtdbd 在 hello 阶段被 `rtdbd_authz.c:19-26` 的 loopback 约束 DENIED；用户裁决 u-0=**设备侧代理**——设备上本地代理以 127/8 连 rtdbd（hello 合规），把"外部来源"转为"设备本地来源"，不改核心鉴权模型。

**目标**：给出设备侧代理（新组件）的可实施方案——进程形态（VSOA server 对外 + 2 条 loopback client）、URL 中转与 rtdbd 侧依赖、N:2 聚合下的 **NOTIFY/RBE 语义适配**、身份映射、部署与测试路径，给出可证伪判据与用户裁决点。**本文是 SDD 第一步，实现另立变更卡**。

## 2 事实基础（源码逐行核对）

### 2.1 身份/鉴权链路（决定双 token）

- rtdbd VSOA server 只绑 loopback：`vsoa_adapter.c:771` `INADDR_LOOPBACK` + `:773 vsoa_server_start`；hello 用 `vsoa_server_cli_address`（`:174-179`）取对端 + `rtdbd_authz_source_allowed`（`rtdbd_authz.c:15-26`）要求 PLC/sync_admin 落 127/8。
- **role→URL 白名单互斥**（`rtdbd_authz.c:47-58`）：`plc` 放行所有非 `/sync/*`（可读 `/point/*`、`/logs`、13 镜像），**不能** `/sync/peers/get`；`sync_admin` **仅** `/sync/peers/{set,get}`。一 token 一 role（`rtdbd.c:105-137`）。**u-A 要同时含 GET_PEERS + 4 只读 URL → 代理必须维护 2 条 loopback client 会话（plc + sync_admin）**。
- **为何不能单 token + 代理自实现 peers get**（评审 P1-3）：peer 表权威在 rtdbd 进程内存（`rtdbd_authz.c:66-76` 成员表、`vsoa_adapter.c:369-372` 读全局 peer table），代理无权威数据源；自实现会与 rtdbd 真实成员表不一致，违反 13 号 §7.4"两前端同一语义"。故双 token 是唯一合规路径。
- **按点鉴权的正确机制**（评审 P1-4，纠正 v1 误引 RBE）：`rtdbd_authz_url_allowed`（定义 `rtdbd_authz.c:38-64`，调用点 `vsoa_adapter.c:524-527`，role→URL）与 `irt_policy_allows`（13 号 §8.3-4，按点 allow/deny）。RBE（`rtdbd_session.c:260-289` 的 `rtdbd_session_notify_gate`）是**变化抑制**，不是访问控制——d-C 安全论证须用前者。
- 代理对外 PC 端：SDK 唯一鉴权是 `vsoa_server_passwd` 连接级共享口令（`vsoa_server.h:142-143`，SDK 安全文档 `:3-5`；SDK 头未入库、行号不可机械复核，论断方向与 13 号 §8.3-4 一致）；`vsoa_server_cli_set_authed` 只控 publish 订阅、非 RPC 门禁（`:211-218`）。rtdbd token 校验是 adapter 内静态 `vsoa_hello`（`:148`）+ 纯逻辑，无组件可复用。

### 2.2 URL 中转现状（决定 rtdbd 侧依赖）

- rtdbd VSOA 前端只实现 13 镜像 URL（`rtdbd_dispatch.c:20-40`）+ `/hello`、`/session/rebind`、`/sync/peers/{set,get}`（`vsoa_adapter.c:676-747`）；未知 URL 不处理不回错误（`:514-517`）。
- u-A 落地：`GET_PEERS(24)`→`/sync/peers/get` **已实现**（handler `vsoa_peers_admin` `:346-377`、注册 `:713-728`、4104B `rtdbd_peers_resp_t`）；`list(11)`/`find_by_name(7)`/`meta(8)`/`logs(15)` opcode 已定义（`protocol.h:41-57`）但 **VSOA 前端未实现**。
- **4 URL 依赖 rtdbd 补齐（评审 P1-3 补充 UDS 替代路径评估）**：这 4 个 opcode 在 UDS 前端已实现（op_* 函数），但 q-B 裁决已确定 SylixOS 裁 UDS 主路径——代理在板上**无 UDS 前端可用**；且即便 Linux 开发期有 UDS，走 UDS 直读会绕过 VSOA 两前端一致真源（13 号 §7.4）。故结论成立：代理只能透传 rtdbd 已注册 VSOA URL，4 URL 须 rtdbd 侧补 handler（h-B health 镜像范式），**代理不能独立交付**。
- 透传形态：请求 `payload.data` 原样放、`status=0x80|RTDBD_ST_*`（`vsoa_adapter.c:401-406,504-510`），POD 零序列化。
- NOTIFY 必须转发：rtdbd 用 `vsoa_server_cli_datagram` 定向推 `rtdbd_notify_t`（`:285-325`，禁 publish/quick），客户端须先订阅 URL + `/subscription/add`；桥接 `vsoa_client_on_datagram`→按 listener 点位集扇出→`vsoa_server_cli_datagram`。`/snapshot_done` 生产定向路径未接线、恒 0（`vsoa_adapter.h:67-74`）。

### 2.3 部署/构建（复用 G2 先例）

- 交叉 toolchain（q-C，不入库）：`TC=.../eao_framework/script/sylixos_build/sylixos.toolchain.cmake`、`BASE=.../base_ecs_multi/base`、`ARM64_A55`（G0G1 卡 :17-34）；产物 AArch64 ELF（G2 报告 :50-54）。
- 新 target 仿 `sylixos_vsoa_e2e`（顶层 `CMakeLists.txt:172-188`，条件 `SylixOS AND INDURTDB_IS_TOP_LEVEL AND INDURTDB_ENABLE_VSOA`），链 4 个 VSOA .so；运行期需 5 个（含 `libvsoa-position.so`，G2 报告 :61），可与 rtdbd 同目录/同 SDK 1.9.1。
- LD_LIBRARY_PATH：telnet 会话内赋值（未加载 /etc/profile、无 export/VAR=val cmd 语法，报告 :76/:105-107），未碰 /lib。
- 启动：SylixOS 无 fork/systemd（G2 supervisor 已 #ifdef 隔离），G2 用 telnet 双会话；仓内无启动脚本先例（**新增风险：代理与 rtdbd 启动顺序 / 晚启动重连未覆盖**）。VSOA 评估版 license "1h 退出"（报告 :78）——长驻代理须正式 license。
- 端口：rtdbd 用 `--vsoa-port 0` + port-file 回读（`rtdbd.c:2730-2733`，监控台读 `RTDBD_VSOA_PORT_FILE` `app.py:237-254`）；**代理 port-file 须用独立文件名/环境变量，避免与 rtdbd 语义混淆**（评审 P2-5 落到方案：如 `RTDBD_AGENT_PORT_FILE`）。

### 2.4 容量与会话模型（N:2 聚合 + RBE 适配）

- 硬边界：`RTDBD_VSOA_MAX_CLI=32`（`vsoa_adapter.h:130`）、满时静默丢弃（`vsoa_adapter.c:110-117`）；u-E listener≤16。
- **1:1 会话耗尽推导**（评审 P2-3 说明 strawman 性质）：最坏假设 16 listener × 2 身份 = 32 占满；实际 peers get 是服务级（非每 listener 都需 sync_admin），故正常远低于 32，但为防最坏仍采用 N:2 聚合。
- **N:2 聚合**：对外每 PC 网关 1 条 server 会话；代理→rtdbd 2 条 client（plc 只读 + sync_admin peers get）；代理维护每个外部 listener 的订阅集，在 `on_datagram` 二次过滤/扇出。
- **同进程双角色无先例**：SDK 按对象创建、无全局 init（server.h/client.h 未入库，行号不可机械复核），仓内/SDK 无双角色文件（检索 0）。单线程可把 server+2 client fd_set 合一次 poll；回调在 `input_fds` 线程，reconnect/close 走延迟队列。双角色回调重入风险（server 回调内调 client call/datagram）须 spike 验证，失败 fallback：改双进程（代理 server 进程 + 独立 client 进程经本地 IPC）或多线程（每角色独立 input_fds 线程 + 队列），不阻塞主循环。

## 3 方案设计

### 3.1 总体结构（N:2 聚合两跳代理）

```
外部 PC 瘦网关 (u-B Linux, UDS→VSOA) ──VSOA──> [设备侧代理]
   ├─ VSOA server（对外绑管理网卡/IP，passwd 连接级准入）
   ├─ VSOA client #1（127.0.0.1→rtdbd，plc token：13 镜像 + 4 只读 URL）
   ├─ VSOA client #2（127.0.0.1→rtdbd，sync_admin token：仅 /sync/peers/get）
   └─ 单线程 poll(server+2 client fds) + 延迟动作队列 + RBE 语义适配层(§3.4)
                    │ 127.0.0.1 loopback（hello 合规）
                    ▼                rtdbd（VSOA server, 127.0.0.1）
```

- 对外 server：按 d-A 裁决绑**指定管理网卡 IP**（现场确认 192.168.30.x 段、不用 `0.0.0.0`），独立 port-file（`RTDBD_AGENT_PORT_FILE`）；按 d-C 裁决 passwd 连接级准入。
- 对内 2 client：均 127.0.0.1 hello；#1 plc 覆盖点位类 + `/logs` + 13 镜像；#2 sync_admin 仅 `/sync/peers/get`。u-C：代理 server 端不注册/显式拒绝 `/sync/peers/set`。
- 身份：u-D 单只读服务身份——外部 PC 不传用户 token，rtdbd 见代理身份。**与 t-B 的张力（评审 P1-5）**：t-B（26 号）审计要求可追溯，但 u-D 下审计全归代理服务身份，无法追溯到具体监控台用户——这是"来源转换"的既定代价，本轮接受（只读场景、按点鉴权仍在），若未来需用户级追溯须改身份模型（另议）。

### 3.2 rtdbd 侧 URL 补齐依赖（代理不可独立交付）

代理只透传已注册 URL。u-A 的 `list(11)`/`find_by_name(7)`/`meta(8)`/`logs(15)` 须 rtdbd VSOA adapter 补 handler（h-B 范式），否则监控台点位清单/元数据/日志/按名查询仍失效。**前置依赖，另立变更卡**；本文界定不实现。

### 3.3 会话模型：N:2 聚合（对 27 号的修订）

- 对外每 PC 网关 1 条 server 会话；代理→rtdbd 2 条 client（plc + sync_admin）。
- 请求按 URL 路由：点位类→client#1，`/sync/peers/get`→client#2；`vsoa_client_call` 异步转发、回调回写 server reply。
- **防串扰**：代理维护 per-listener 的 `session_t`（订阅集 + 路由表），NOTIFY datagram 从 client 收后按 listener 订阅集二次过滤扇出——替代 27 号"每 listener 独立 client 会话"的隔离机制（评审 P1-2：这是实质修订，等价性由 §3.4 RBE 适配保证）。

### 3.4 NOTIFY/RBE 语义适配层（评审 P1-1，功能正确性核心）

rtdbd 的 RBE 门控是 **per-session subtab**（`rtdbd_session.c:260-289`）：退订清 RBE 状态保证重新订阅首值必发（`:105-106`）。N:2 聚合下代理单条 client 会话的 subtab 被所有 listener 共享，直接转发会有两类错误：① listener B 后订阅已订阅点 P 时 rtdbd 不再发首值（B 丢首值）；② A 退订而 B 仍订阅时代理不能向 rtdbd 退订（否则 B 也收不到）。

**适配方案**（代理应用层维护，与 rtdbd per-session 语义等价）：
- **per-point 引用计数**：代理为每个点位维护 `refcnt` = 订阅该点的 listener 数。首个 listener 订阅点 P → 向 rtdbd `/subscription/add(P)`（触发 rtdbd RBE 首值）；最后一个 listener 退订 P → 向 rtdbd `/subscription/remove(P)`（清 RBE 状态）。中间 listener 的订阅/退订只改本地引用计数与 per-listener 订阅集，**不打扰 rtdbd 会话**。
- **首值缓存**：对共享 client 会话已消耗过 RBE 的点 P，代理保存最近一次 NOTIFY 值；新 listener 订阅 P 时，**主动把缓存首值推给该 listener**（模拟 rtdbd"重新订阅首值必发"语义），不等下一次变化。缓存容量按点数有界（沿用 `RTDBD_SUB_MAX` 量级），满则淘汰最旧并计数。
- **二次过滤扇出**：`on_datagram` 收到点 P 的 NOTIFY → 查 per-listener 订阅集 → 仅对订阅 P 的 listener 调 `vsoa_server_cli_datagram`，避免串扰。
- **RBE 判定归属**：rtdbd client 会话侧 RBE 照常（变化抑制）；代理侧首值缓存 + 引用计数只补"per-listener 订阅语义"，不重复做 RBE 死区判定（避免与 rtdbd 双重抑制）。
- **可证伪判据**：单测构造 A/B 两 listener 订阅同点 P、A 退订 B 仍订阅、B 新订阅 P 收首值，断言扇出正确、无串扰、首值不丢。

### 3.5 失败/超时/背压映射（d-D 已裁决）

- rtdbd reply status `0x80|RTDBD_ST_*` 原样透传（含 DENIED/NOT_FOUND）。
- RPC 超时上限 **3s（d-D 裁决、阈值固定）**、在途 RPC 数有界、超时回 `RTDBD_ST_INTERNAL`；NOTIFY 慢消费者 per-listener 有界队列（满即丢并计数，对齐 rtdbd outq 背压）。
- `/snapshot_done` 生产恒 0：本轮不转发其 datagram（或透传标注恒 0），待 rtdbd 接线。

### 3.6 测试路径

- **Linux 单机先开发**：loopback 起 rtdbd + 代理双角色 + 模拟外部 PC client，验证 hello 合规、URL 透传、NOTIFY 扇出（含 §3.4 A/B/首值三例）、N:2 会话；复用 G2 OFF/ON 零回归。
- **板上三跳 e2e**：新增「外部 PC 模拟网关 → 代理对外端点 → 代理 loopback client → rtdbd」harness（现有 `sylixos_vsoa_e2e.c` 只做 client→rtdbd，不覆盖对外 bind 与外部来源）；上板前重确认设备连通/写入探针。
- **另一跳归属（评审 P1-7，d-F 已裁决）**：外部 PC 瘦网关（UDS→VSOA）同样是新组件，**不在本文范围**——本文只细化设备侧代理一跳；按 d-F 裁决瘦网关**另立 SDD**。

6. 边界守住：不改核心鉴权模型/opcode/ABI/对外口径/发布门 FAIL 8/B 段数字，不宣告 F2/F3a/F4 就绪，实现另立变更卡 + 开工授权。
