# InduRTDB 集成产品化设计文档

**版本：1.0**
**日期：2026-08-09**
**状态：已批准**
**关联目标：让 InduRTDB 成为"别人能方便地用起来、集成进去"的产品**

---

## 一、背景与目标

InduRTDB 的 API 与文档已具备良好的"易学易用"基础（单头文件 26 函数、SDK 手册、示例），但**交付与集成环节存在缺口**：无 `install()`/打包、无 `find_package`/pkg-config、示例绑定源码树相对路径、无版本宏、缺消费者集成文档。这使它停留在"自己仓库里的好库"，而非"别人能顺手拿走集成的产品"。

**目标**：让一个 C/C++ 开发者能在数分钟内，把 InduRTDB 集成进自己的工程并编译运行成功，且版本可信、路径解耦、长期可回归。

**主要集成形态**（已确认）：C/C++ 项目把 InduRTDB 作为库引用。
**引用方式**（已确认）：同时支持 ① 安装后 `find_package`/pkg-config 引用，② `add_subdirectory`/FetchContent 源码内嵌引用。

## 二、方案选择

**采用方案 A：CMake export 标准实践 + 分阶段交付。**
- 机制：CMake 官方导出（`install(EXPORT)` + `CMakePackageConfigHelpers`），生成包配置/版本文件/命名空间目标 `InduRTDB::indurtdb`，并配 pkg-config。
- 交付：分三阶段（核心集成 → 模板工程 → CI 回归），每阶段独立可验证、可合并。
- 否决：方案 B（一次性交付，改动过大）、方案 C（手写 Config 模板，易错难维护）。

**子项目隔离**（已确认）：当 InduRTDB 被 `add_subdirectory`/FetchContent 引入时，**默认**不构建 tests/examples/demo、不执行 install，避免污染消费方工程；仅当它是顶层项目时才构建。可用选项覆盖。

## 三、总体架构

两条消费路径，统一目标名 `InduRTDB::indurtdb`：

```
                 InduRTDB 源码仓
                       │
        ┌──────────────┴──────────────┐
        │  路径①  安装后引用            │  路径②  源码内嵌引用
        │  cmake --install <prefix>    │  add_subdirectory / FetchContent
        │  find_package(InduRTDB)      │         │
        │  或 pkg-config indurtdb      │         │
        └──────────────┬──────────────┘
                       ▼
        target_link_libraries(app PRIVATE InduRTDB::indurtdb)
```

顶层检测：
```cmake
if(CMAKE_CURRENT_SOURCE_DIR STREQUAL CMAKE_SOURCE_DIR)
    set(INDURTDB_IS_TOP_LEVEL TRUE)
else()
    set(INDURTDB_IS_TOP_LEVEL FALSE)
endif()
option(INDURTDB_BUILD_TESTS    "Build InduRTDB tests"    ${INDURTDB_IS_TOP_LEVEL})
option(INDURTDB_BUILD_EXAMPLES "Build InduRTDB examples" ${INDURTDB_IS_TOP_LEVEL})
```

命名空间目标 + 别名（两条路径同名）：
```cmake
add_library(indurtdb STATIC ${IRT_CORE_SRC})
add_library(InduRTDB::indurtdb ALIAS indurtdb)
```

## 四、阶段一：核心集成能力

| 改动 | 内容 |
|------|------|
| 根 `CMakeLists.txt` | 顶层检测 + 选项门控 tests/examples；版本升级（见第七节）；`install(TARGETS ... EXPORT)` |
| `cmake/InduRTDBConfig.cmake.in` | 包配置模板 |
| `cmake/indurtdb.pc.in` | pkg-config 模板（Libs 含 `-lrt -lpthread`） |
| 导出目标 | `install(EXPORT ... NAMESPACE InduRTDB::)` + `configure_package_config_file` + `write_basic_package_version_file` |
| 版本宏 | `indurtdb.h` 增加 `INDURTDB_VERSION_MAJOR/MINOR/PATCH/STRING`（保持单头文件卖点） |
| 消费者文档 | `docs/05-SDK手册/04-集成指南.md`：find_package / pkg-config / FetchContent 三法 |
| `demo/` 升级 | 改为对**已安装库**编译，真实模拟外部消费 |

关键 CMake（节选）：
```cmake
include(GNUInstallDirs)
include(CMakePackageConfigHelpers)

install(TARGETS indurtdb EXPORT InduRTDBTargets
    ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR})
install(DIRECTORY include/indurtdb DESTINATION ${CMAKE_INSTALL_INCLUDEDIR})

install(EXPORT InduRTDBTargets
    FILE InduRTDBTargets.cmake
    NAMESPACE InduRTDB::
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/InduRTDB)

configure_package_config_file(cmake/InduRTDBConfig.cmake.in
    ${CMAKE_CURRENT_BINARY_DIR}/InduRTDBConfig.cmake
    INSTALL_DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/InduRTDB)
write_basic_package_version_file(
    ${CMAKE_CURRENT_BINARY_DIR}/InduRTDBConfigVersion.cmake
    VERSION ${PROJECT_VERSION} COMPATIBILITY SameMajorVersion)
install(FILES
    ${CMAKE_CURRENT_BINARY_DIR}/InduRTDBConfig.cmake
    ${CMAKE_CURRENT_BINARY_DIR}/InduRTDBConfigVersion.cmake
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/InduRTDB)

configure_file(cmake/indurtdb.pc.in ${CMAKE_CURRENT_BINARY_DIR}/indurtdb.pc @ONLY)
install(FILES ${CMAKE_CURRENT_BINARY_DIR}/indurtdb.pc
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/pkgconfig)
```

`indurtdb.pc.in`：
```
prefix=@CMAKE_INSTALL_PREFIX@
libdir=${prefix}/@CMAKE_INSTALL_LIBDIR@
includedir=${prefix}/@CMAKE_INSTALL_INCLUDEDIR@

Name: InduRTDB
Description: Industrial real-time database (pure C11)
Version: @PROJECT_VERSION@
Libs: -L${libdir} -lindurtdb
Libs.private: -lrt -lpthread
Cflags: -I${includedir}
```

消费方用法（路径①）：
```cmake
find_package(InduRTDB REQUIRED)
target_link_libraries(app PRIVATE InduRTDB::indurtdb)
```

## 五、阶段二：开箱即用模板工程

`templates/indurtdb-starter/`：可直接复制的最小工程。
```
templates/indurtdb-starter/
├── CMakeLists.txt     # 注释切换 find_package / FetchContent 两种引用
├── main.c             # 最小读写示例
└── README.md          # 三步跑通
```

## 六、阶段三：CI 外部消费回归

`scripts/verify_consume.sh`：在干净目录中分别执行
1. `cmake --install` → 用 `find_package` 配置并编译 starter；
2. 用 FetchContent 拉本仓并编译 starter。

任一失败即退出非 0。脚本可本地运行，也可挂入 CI。

## 七、版本策略（已确认：统一到 3.1.0）

现状 `VERSION`=3.0.0、代码=3.1.0、`project(VERSION)`=3.0.0 不一致。对外产品化需诚实一致，故三者统一为 **3.1.0**：
- `VERSION` 文件 → `3.1.0`
- `project(InduRTDB VERSION 3.1.0 ...)`
- `indurtdb.h` 版本宏 → `3.1.0`
- `CHANGELOG.md` 中该版本由"内部迭代"转正

这等效于正式发布 3.1.0（含崩溃恢复、Seqlock 奇数恢复、owner_pid 等特性）。

## 八、验收标准

1. 新用户按集成指南，用 **find_package** 或 **FetchContent** 在独立工程编译运行 starter，一次成功。
2. `pkg-config --cflags --libs indurtdb` 输出正确的 include/lib/依赖。
3. 作为子项目引入时不污染消费方（无多余 target、无 install）。
4. 顶层构建仍零警告、既有测试全绿。
5. `scripts/verify_consume.sh` 退出码 0。

## 九、范围外（YAGNI，本轮不做）

- Python/Rust/Go 等 FFI 语言绑定与示例（主要形态为 C/C++ 引用）。
- 预编译二进制发布、SylixOS/ARM 交叉编译交付。
- header-only / amalgamation 单文件分发。

以上能力如有需要，另立需求单独设计。
