## 3 S1 摘要与 epoch 地基（纯逻辑、单台可验）

- 新增 `rtdbd/src/cluster/rtdbd_digest.c/.h`：结构 hash（点位 id/name/type/partition 确定性排序）+ 值摘要（value_bits+ts+quality 累积），输出 `terminal_hash`/`digest`。
- ~~`rtdbd_session_t` 加 `uint64_t epoch`（服务端分配）~~ **2026-11-25 S1 评审修正**：`session.epoch` 是会话级、reset 归零，不能用于跨会话/节点的字典序裁决（13 号:256）；改为**进程级全局 epoch 模块** `rtdbd/src/cluster/rtdbd_epoch.{c,h}`（next/current/is_stale/advance_to/epoch_key），session 字段保留但不参与裁决。写路径带全局 epoch，接收侧 `epoch < current` 拒绝（陈旧帧）。
- 验证：纯逻辑单测（相同点集不同插入顺序 → 同 hash；改一点 → hash 变；旧 epoch 被拒）。

## 4 S2 同步通道（VSOA URL 扩展、不新增 UDS opcode）

- `/sync/hello`（交换 epoch+digest+node_id）、`/sync/snapshot`（分页 ~128KB）、`/sync/delta`（批次 200 条/20ms、reply 带 applied_offset）、`/sync/wait`（可选 N-1 ack、50ms 超时）。
- peer connector：每节点以 `sync_peer` 角色连其他 N-1 节点；`--peers-file` 预置成员 + `sync_self_addr` + 双 token。
- 验证：Linux 两进程 loopback 真握手 + 增量/全量传输 + ack 计数；单测 mock peer。

## 5 S3 终态裁决与原子切换

- 接收端维护 `snapshot_epoch`，全量到达后原子切换 + backlog 去重重放；终态取 `(epoch, node_id)` 字典序最大可达节点快照 → `dict_max_snapshot_match`。
- 验证：注入同 epoch 双写 → 终态收敛到最大 node_id；断开节点恢复后从最大可达节点拉全量。

## 6 S4 notify 延迟埋点（外部打点、不改 POD）

- 写路径记 `t0`（CLOCK_MONOTONIC）到旁路环，NOTIFY 发出取 `t1`，输出 `notify_latency_ns=t1-t0` 到统计出口（仿 h-B sid 环）。
- 验证：单台写点 → 读统计出口得非零延迟；`rtdbd_notify_t` 32B POD 不变（ABI 冻结）。
