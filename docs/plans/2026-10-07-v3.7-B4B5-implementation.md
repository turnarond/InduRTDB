## 1. 目标与不变式

1. **B4 运行时配置持久化**：解决「v3.6 CRUD 重启即丢」——经 `CREATE_POINT` / `DELETE_POINT` /
   `RENAME_POINT` 运行时注册的点位，在 rtdbd 重启后应仍然存在。
2. **B5 v1 API 退役（技术债）**：把 v1 全局函数正式标注弃用，迁移用户可见样例到 v2 句柄 API，
   为 v4.0 真正删除做准备。

**关键约束**
- **ABI 不变**：不改动 Header / 点位 / 元数据布局；delta 日志是**独立文件**，不进共享内存。
- **base 配置不可变**：`load_config` 读取的 YAML 保持只读、可审计；持久化通过**追加 delta 日志**实现，
  而非回写 YAML（回写会破坏审计性且并发不安全）。
- **热路径零回归**：B4 只影响启动回放与 CRUD 管控写路径，不触碰读写热路径；`run_bench.sh` 必须仍 PASS。
- **零堆**：delta 记录定长，缓冲区编译期定长。
- **嵌入式友好**：追加写 + 定长记录；不依赖 SQLite / 第三方库。

## 2. 现状基线（事实）

- 运行时 CRUD：`indurtdb_h_create_point/delete_point/rename_point`（v3.6 落地），作用于共享内存内
  点位表与 name→id 索引；**进程退出后随之消失**（段随 owner unlink，且无人回写配置）。
- 配置加载：`indurtdb_load_config(config_path)` 由 rtdbd 在 `indurtdb_initialize` 之后调用
  （`rtdbd.c`），一次性把 YAML 点位写入点位表与索引。
- rtdbd 退出：`indurtdb_shutdown()`（owner 会 unlink 段）或 `indurtdb_detach()`（保留段，v3.7 B3 新增）。
- v1 API：`indurtdb_*` 全局函数 = `g_default` 句柄的薄封装（`src/api/indurtdb.c`），与
  `indurtdb_h_*` 签名同构。
- 使用面：**tests 约 500 处调用 / 35 个文件**；`examples/` 5 处；`demo/` 5 处。
- `INDURTDB_DEPRECATED` 宏**尚未定义**（仅在 `indurtdb.h:399` 注释中被提及）。
- 测试目标**未开启** `-Werror`（已确认 `tests/unit`、`tests/integration` 均无 `-Wall/-Wextra/-Werror`）。

## 3. B4 运行时配置持久化（delta 日志）

### 3.1 设计

**文件**：`<instance>.rtdbd.delta`，路径由 rtdbd 新增 `--delta-file <path>` 指定；
未指定时**默认关闭**（向后兼容，不改变既有部署行为）。

**记录格式（定长 80B，小端无关，POD）**

```c
#define IRT_DELTA_MAGIC   0x444C5441u   /* "DLTA" */
#define IRT_DELTA_VERSION 1u
#define IRT_DELTA_OP_CREATE 1u
#define IRT_DELTA_OP_DELETE 2u
#define IRT_DELTA_OP_RENAME 3u

typedef struct {
    uint32_t magic;      /* IRT_DELTA_MAGIC */
    uint16_t version;    /* IRT_DELTA_VERSION */
    uint16_t op;         /* IRT_DELTA_OP_*   */
    uint32_t point_id;
    uint8_t  type;
    uint8_t  access;
    uint8_t  reserved[2];
    char     name[64];   /* CREATE/RENAME 用新名；DELETE 忽略 */
} irt_delta_rec_t;       /* 80B，静态断言锁死 */
```

**语义**
- **追加写**：每次成功的 `CREATE/DELETE/RENAME` 追加一条记录；写完 `fsync`。
- **启动时序**：`load_config(base)` → **回放 delta**（按记录顺序重放）→ 继续后续校验与服务。
  即 base 为地基、delta 为增量，二者顺序叠加。
- **幂等性**：回放是确定性的同名同参重放；重复回放同一序列结果一致（rename 会覆盖旧名索引）。

**崩溃安全**
- 记录定长；回放时若**末尾存在不足 80B 的残片**（写到一半崩溃），丢弃该残片，回放其前的完整记录。
- 每条记录带 `magic` + `version`：非预期值即停止回放并记 WARN（避免把垃圾当记录解释）。

**容量治理**
- 日志只增不减，长期运行会增长。v3.7 提供 `--delta-file` 与文档说明，**压缩/轮转留到后续**
  （可在 rtdbd 启动时提示条数超阈值；不做自动重写，避免复杂化）。

### 3.2 任务

- **T1 纯函数层**：`irt_delta`（`src/core/irt_delta.c` + `internal` 头）
  - `irt_delta_append(fd, const irt_delta_rec_t*)`：定长写 + fsync；失败返回错误码。
  - `irt_delta_replay(path, replay_cb, ctx)`：逐条解析并回调；遇残片/坏 magic 停止并返回状态。
  - 纯解析可单测（用临时文件喂入各类字节序列）。
- **T2 核心接入**：`indurtdb_h_create_point/delete_point/rename_point` 在成功后，
  若已启用 delta（`indurtdb_enable_delta(path)`），追加记录。
  - 启用函数放在核心，rtdbd 启动时调用；未启用时行为完全不变。
- **T3 rtdbd 接入**：新增 `--delta-file`；启动顺序 `load_config` → `indurtdb_delta_replay()`；
  回放失败（非法记录）→ 明确 stderr + 退出码（复用 B3 的 `RTDBD_EXIT_CONFIG` = 2）。
- **T4 测试**
  - 单测 `tests/unit/test_c_delta.cpp`：记录布局静态断言、残片丢弃、坏 magic 停止、
    create/delete/rename 序列回放后点位表与索引一致。
  - 集成 `tests/integration/test_rtdbd_delta.cpp`：
    启动 → CREATE 点位 → SIGTERM → 重启（同 delta 文件）→ 点位仍存在且可 GET；
    DELETE / RENAME 同理；残片文件可容忍；未指定 `--delta-file` 时行为同现状（重启即丢）。

## 4. B5 v1 API 退役

### 4.1 设计（**不含删除**）

1. 在 `indurtdb.h` 定义并启用弃用宏：
   ```c
   #if defined(__GNUC__) || defined(__clang__)
   #  define INDURTDB_DEPRECATED __attribute__((deprecated))
   #else
   #  define INDURTDB_DEPRECATED
   #endif
   ```
2. 为全部 v1 全局函数标注 `INDURTDB_DEPRECATED`（注释写明 v4.0 删除 + 迁移到 `indurtdb_h_*`）。
3. 迁移 `examples/` 与 `demo/` 到 v2 句柄 API（用户可见样例应展示推荐用法）。
4. 为测试目标显式关闭弃用告警（`-Wno-deprecated-declarations`），**保留测试继续使用 v1**。

### 4.2 为何不建议把测试整体迁到 v2（对 roadmap 的偏离）

roadmap §3.4 写的是「迁移 `examples/`、`demo/`、测试到 v2 句柄 API」。**建议只迁移 examples/demo，
测试保持 v1**，理由：

- **v1 API 到 v4.0 之前都是受支持的公共 API**，必须有回归网覆盖它。测试整体迁到 v2 会**减少**
  对 v1 的覆盖——恰恰是在"标注弃用但仍在支持"的窗口期最不能丢的东西。
- 迁移量约 **500 处调用 / 35 个文件**，纯机械改动、零行为变更，却要承担全量 churn 的回归风险。
- 成本收益不对称：收益是"消除编译告警"（可用一行 `-Wno-deprecated-declarations` 达成），
  成本是 35 个测试文件的改写风险。

> 若评审坚持全量迁移，建议拆成独立后续任务（v4.0 真正删除 v1 前统一做），不在本次改动。

### 4.3 任务

- **T5** 定义 `INDURTDB_DEPRECATED` 并标注全部 v1 函数；头文件注释写明"v4.0 移除"。
- **T6** 迁移 `examples/basic_example.c`、`demo/demo.c` 到 v2；确认其仍能构建运行。
- **T7** 测试目标加 `-Wno-deprecated-declarations`（并注释说明是刻意保留 v1 覆盖）。
- **T8** 验证：`examples`/`demo` 无弃用告警；全量 ctest 全绿；库仍零警告。

## 5. 验收与风险

### 5.1 验收
- 全量 `ctest` 绿；`run_bench.sh` P99 仍 PASS（B4/B5 不触碰热路径）。
- ABI 不变；`IRT_SHM_VERSION` 仍 2。
- B4：重启后运行时点位仍在；未启用 delta 时行为与现状完全一致（默认关闭）。
- B5：库零警告；examples/demo 用 v2 且无弃用告警；v1 仍可用（仅告警）。

### 5.2 风险与回退
| 风险 | 缓解 / 回退 |
|---|---|
| delta 日志无限增长 | 文档说明 + 条数提示；压缩轮转留后续；可随时不用 `--delta-file` 关闭 |
| 回放与 base 冲突（base 改了） | base 与 delta 顺序叠加；若 base 已删该点，delta 的 rename 会作用于不存在点 → 回放时记 WARN 跳过，不致命 |
| 残片/损坏 | 定长 + magic 校验；残片丢弃、坏 magic 停止回放 |
| 弃用告警噪音 | 测试目标统一关闭；用户迁移文档给出 `indurtdb_h_*` 对照 |
| **B5 偏离 roadmap** | **需评审确认**：测试是否也迁 v2（本计划建议否） |
