**日期：2026-10-06**

## 0. 实施状态（2026-10-07 已完成）

B1（健康/自检）、B2（背压/优雅退出）、B3（配置校验/fail-fast）三项全部落地并通过 TDD：**35/35 ctest 全绿、编译零警告、`run_bench.sh` 全项 PASS 且热路径零回归**。

**相对初版计划的设计修正（均已实现并验证）**

- `stats.h` 实际位于 `rtdbd/src/stats.h`（与 `rbe.h` 同目录），非 `rtdbd/include/rtdbd/`。
- `indurtdb_validate_config` 改为**带输出参数**（`err_code` / `err_field` / `err_reason`）并新增
  `indurtdb_cfg_error_reason()`，否则调用方只拿到点 id、无法打印原因。
- `indurtdb_validate_config` **无条件调用**，但未给 `--config` 时判为**告警而非致命**——
  段内 meta 可能来自 v3.6 时代经 `SET_META` 写入的历史值，致命化会把旧部署「砖化」。
- **新增 `indurtdb_detach()`**：fail-fast 退出用它**保留共享内存段**。原实现调
  `indurtdb_shutdown()`，因 owner 语义会 `shm_unlink` 整段，把「配置写错」升级为「数据销毁」。
- `indurtdb_h_set_meta()` **增加写入前语义校验**：否则非法 meta 落盘后下次启动必 fail-fast。
- YAML 点位配置**扩展可选语义字段** `eur_min` / `eur_max` / `deadband` / `flags`
  （`irt_point_meta_t` 加 `has_meta`）：初版配置无法表达语义，该校验在生产上无从触发。
- `outq_flush` 用 `MSG_DONTWAIT` + `outq_sent` 做**部分发送**：`POLLOUT` 就绪只保证缓冲有
  *部分*空间，沿用阻塞 `send_all` 会在嵌入式小缓冲下卡死整个单线程服务端。
- 健康 `DEGRADED` 用 **60s 滑动窗口**判定（累计计数只增不减会永久锁存，导致告警疲劳）。

**已撤销的过度约束（评审复盘）**：一度把「置了百分比死区就必须启用量程」做成致命校验，
结果拒绝了合法配置（主题A 的 `NotifyDeadbandPercent` 用例失败）。百分比死区只是**借用**
`eur_min/eur_max` 作跨度基准，与「是否在 quality 上置量程位」**正交**，故撤除致命校验，
改为非致命谓词 `indurtdb_meta_pct_without_range()` + 启动 WARN。

**第二轮复审（针对修复本身）补记**

- **部分发送帧混合（Critical）**：队列满时若淘汰"已部分上线"的队首（`outq_sent > 0`），
  下轮会用新帧从旧偏移续发 → 线上出现「旧帧前缀 + 新帧后缀」的混合帧（长度仍 44B）。
  修复：队首已部分发送时**禁止淘汰**，改丢弃本次新通知。
  *注：该缺陷需「发送缓冲剩余空间 >0 且 <44B」窄窗口才能触发，集成测试无法确定性复现
  （已实测回退修复后新增用例仍通过），修复由代码评审确认。*
- **supervisor 留活 worker（Critical）**：`recv_all()` 的 EINTR 分支 `continue` 重试 recv、
  不检查 `g_stop`，故阻塞在 recv 的 worker 无法被 SIGTERM 终止。修复：
  `terminate_and_reap()` 用 SIGKILL 兜底；且内层 waitpid 重试在 EINTR 且 `g_stop` 时
  改为主动终止回收（否则 supervisor 自身卡死在 waitpid）。已加有效护栏用例
  （回退修复后该用例挂死，可证）。
- **API 契约修正**：`indurtdb_validate_config` 改为「返回状态码 + 输出 `bad_id`」，
  因原契约用 `0` 表示全部合法，而点 id 0 是合法点，非法点若为 id 0 会绕过 fail-fast。
- 另修：优雅退出超时路径丢弃记账、config 数值严格解析（拒 NaN/畸形/溢出）、
  CLI 数值参数严格解析与 `--max-points` 上界、supervisor fatal 路径清理 socket、
  supervisor 注册 SIGUSR1。

## 1. 目标与不变式

把"单测全绿但线上偶发"的隐患堵上，分三项：

1. **B1 健康 / 错误计数 + 进程自检**：可观测 rtdbd 内部错误（decode 失败、写被拒、背压丢弃、通知发送失败），供 supervisor（systemd/SylixOS）做布尔健康探测、供监控台展示。
2. **B2 优雅退出 + 背压**：慢消费者不拖垮服务端；进程退出语义清晰、可被测。
3. **B3 配置校验 + fail-fast**：非法配置（服务参数 / 点位语义）启动即明确报错退出，不进入"半初始化"状态。

**关键约束**
- 无共享内存布局变更 → 零 ABI 风险。
- **协议不 bump 版本**：`RTDBD_OP_HEALTH` 加在 v2 内；v3.6 monitor 从不发 HEALTH，故兼容；v3.7 monitor→v3.6 server 的降级路径不在 v3.7 支持范围（可接受）。
- 热路径零堆：计数器（固定数组）、每连接出站队列（定长环形）均无 `malloc`。
- 信号安全：handler 仅置标志；实际 dump / flush 在主循环内执行。
- 与主题 A 联动：B3 校验复用主题 A 在 `indurtdb.h` 定义的 EUR/deadband flags 位。

## 2. 现状基线（`rtdbd.c` 事实）

**已有**
- `on_signal()` 置 `g_stop`；主循环 `poll(...,500)` 检测 `g_stop` 后关 fd、unlink sock、`indurtdb_shutdown()`（基础退出框架）。
- `irt_logbuf` 运行日志、`irt_audit` 审计、`supervise_loop`（fork/exec 自拉起）。
- 每连接订阅表 `rtdbd_conn_t.subs[]`（定长）。

**缺失**（本计划补齐）
- 无错误计数、无 `rtdbd_self_check`、无 stats 导出（仅有 log/audit）。
- `notify_broadcast()` 内联**阻塞直发** `send_all`，无队列、无背压计数；`RTDBD_SHUTDOWN_DELAY_SEC` 已定义但 unused。
- 退出码恒 0（仅 init 失败返 1）；无语义退出码。
- `indurtdb_load_config` 失败仅告警继续（非 fail-fast）；CLI 参数（max_points/max_subs/instance）无范围校验。

## 3. B1 健康 / 错误计数 + 进程自检

**新建 `rtdbd/src/stats.c` + `rtdbd/include/rtdbd/stats.h`**，隔离计数器与自检 glue（类比主题 A 的 `rbe.c`）：

```c
typedef struct {
    uint64_t n_writes;        /* 成功写次数 */
    uint64_t n_notifies;      /* 入队/广播通知数 */
    uint64_t decode_fail;     /* 请求解析失败（payload 长度不符等） */
    uint64_t write_rejected;  /* 鉴权 deny */
    uint64_t write_error;     /* do_write 返回非 0（非 -99 类型不支持） */
    uint64_t notify_drop;     /* 背压丢弃（队列满丢最旧） */
    uint64_t notify_send_fail;/* 出站发送失败 */
    uint64_t uptime_ns;       /* 进程启动至今 */
    int      self_check;      /* 最近一次 self_check 结果枚举 */
} rtdbd_stats_t;
extern rtdbd_stats_t g_stats;            /* 单例，定长无堆 */
void rtdbd_stats_dump(FILE* fp);         /* 文本化导出 */
```
- **埋点**：`handle_request` 各失败返回前 `g_stats.decode_fail++`；policy deny 分支 `write_rejected++`；`do_write` 返回非 0（且非 -99）`write_error++`；notify 入队/发送路径 `n_notifies++` / `notify_drop++` / `notify_send_fail++`；写成功 `n_writes++`。

**自检**
- 核心新增 `indurtdb_self_check()`（读 shm 头，纯函数式）：校验 `magic==IRT_SHM_MAGIC`、`version==IRT_SHM_VERSION`，可选 meta 区 CRC（v3.7 先做 magic+version，CRC 留接口）。返回 `OK/DEGRADED/UNHEALTHY`。
- `rtdbd_self_check()`：`indurtdb_self_check()` + 连接表完整性（无悬空 fd、subs 下标不越界），结果写入 `g_stats.self_check`。供 supervisor 探测。
- **SIGUSR1 触发 dump**：`on_signal` 扩展置 `g_dump_stats=1`；主循环检测后 dump `RTDBD_STATS_FILE`（默认 `/tmp/rtdbd.stats`，`--stats-file` 可配）含 counters + self_check 结果 + 连接摘要。handler 只置标志，dump 在主循环（信号安全）。

**in-protocol `RTDBD_OP_HEALTH`**（协议 v2 内，不 bump）
- `protocol.h` 新增 `RTDBD_OP_HEALTH` 与 `rtdbd_health_t`（含上面 counters + status 枚举）。
- `handle_request` 免鉴权处理（observability）；返回快照。`rtdbd_self_check()` 在返回前刷新。

**TDD 红（集成）**：`tests/integration/test_rtdbd_health.cpp`
- 启动 → 发 SIGUSR1 → `/tmp/rtdbd.stats` 存在且含 `n_writes` 等字段；
- `RTDBD_OP_HEALTH` 返回 status=OK 且 counters 合理；
- 注入 policy deny（写被拒）→ 再次 HEALTH：`write_rejected>0` 且 status∈{DEGRADED}；
- `indurtdb_self_check` 故障注入（魔数错）→ HEALTH 返回 UNHEALTHY。

## 4. B2 优雅退出 + 背压（每连接有界环形队列）

**每连接出站队列**（定长、无堆）
```c
/* rtdbd_conn_t 增加 */
#define RTDBD_OUTQ_CAP 64u
rtdbd_notify_t outq[RTDBD_OUTQ_CAP];
uint16_t       outq_head, outq_tail, outq_count;
```

**写成功 → 入队而非直发**：`notify_broadcast()` 改为构建一次 `nt` 后，对每个订阅者 conn：
- 若 `outq_count==RTDBD_OUTQ_CAP` → 丢最旧（`outq_head` 前进）+ `g_stats.notify_drop++`；
- 否则入队（`g_stats.n_notifies++`）。
- 保留"丢最旧"语义（与 roadmap 一致、保序），定长无堆。

**poll 循环增加 POLLOUT**
- 构造 `pollfd` 时：若 conn `outq_count>0` 置 `POLLOUT`。
- poll 返回后：先对该 conn **flush**（按序 `send_all` 队列项；失败 → 清空该 conn outq 并关闭/标记）；再处理 `POLLIN` 读请求。

**优雅退出序列**（SIGTERM/SIGINT → `g_stop`）
- 主循环退出后：停收新连接（已停）→ **best-effort 排空所有 conn 出站队列**（受 `RTDBD_SHUTDOWN_DELAY_SEC` 限时轮询 flush，超时不阻塞强退）→ 关 fd、unlink sock、`indurtdb_shutdown()`。
- `RTDBD_SHUTDOWN_DELAY_SEC` 本任务正式启用。

**语义退出码**
| code | 含义 |
|---|---|
| 0 | 正常退出 |
| 1 | 通用 / 启动错误（参数解析、policy 加载失败等） |
| 2 | 配置校验失败（B3 fail-fast） |
| 3 | 共享内存损坏 / 初始化失败 |
| 4 | 启动自检失败 |

**supervisor 区分致命退出码**：`supervise_loop` 中，子进程以 **2（配置）/4（自检）** 退出视为致命 → supervisor 停止 respawn（避免坏配置无限重启）；其余（含 3 shm）按原策略 respawn。supervisor 透传子进程退出码给 systemd。

**TDD 红（集成）**：`tests/integration/test_rtdbd_backpressure.cpp`
- 慢消费者（测试客户端订阅但不读）→ 连续写触发 outq 填满 → server `notify_drop>0` 且**另一正常客户端读写不受影响**（无 head-of-line 阻塞）；
- `tests/integration/test_rtdbd_graceful.cpp`：SIGTERM → exit 0；shm 损坏场景 → exit 3；config 错误 → exit 2；supervisor 对 config 错误不再 respawn。

## 5. B3 配置校验 + fail-fast

**核心纯函数（可单测）**
```c
/* src/core：点位元数据语义校验，不触 shm */
int indurtdb_validate_point_meta(const indurtdb_meta_t* m, uint32_t* err_field);
/* 遍历已加载点位，返回首个非法点 id（0 表示全合法） */
uint32_t indurtdb_validate_config(void);
```
- `indurtdb_validate_point_meta`：EUR 启用时 `eur_min < eur_max`；`deadband >= 0`；百分比死区模式下 `deadband ∈ [0,100]`；`flags` 仅含已知位；`type` 合法；`name[0] != '\0'`。返回错误码 + 出错字段。
- 复用主题 A 的 `INDURTDB_META_FLAG_*` 定义（同 `indurtdb.h`）。

**rtdbd main 校验阶段（在 `indurtdb_initialize` 之前）**
1. **服务参数**：`instance` 非空且字符合法；`max_points ∈ [1, IRT_MAX_POINTS]`；`max_subs ∈ [1, RTDBD_SUB_MAX]`；`sock_path` 非空且 `< sizeof(sun_path)`。非法 → exit 1（打印明确错误）。
2. **点位配置语义**：`indurtdb_load_config` 失败 → exit 2（明确错误）；成功 → `indurtdb_validate_config()` 返回非法点 id → exit 2（打印 `point <id> 原因`）。
3. **启动自检**：`indurtdb_self_check()` 失败 → exit 4。
- 任一非法 → 清晰 stderr + log 后立即 exit（fail-fast，不进入半初始化）。

**TDD 红**
- 单元 `tests/unit/test_c_config.cpp`：`indurtdb_validate_point_meta` 各非法/合法场景（eur 反、deadband 负、pct>100、未知 flags、非法 type、空 name）。
- 集成 `tests/integration/test_rtdbd_config.cpp`：`eur_min>eur_max` 的 config → rtdbd exit 2 且 stderr 有明确错误；合法 config 正常启动。

## 7. 风险与回退

| 风险 | 缓解 / 回退 |
|---|---|
| 协议兼容性 | HEALTH 加在 v2 内；v3.6 monitor 不发故兼容；v3.7 monitor→v3.6 server 降级不支持（可接受）。未知 opcode 当前 `return 1` 关连接——可改为 `BAD_REQUEST` 不关以提升前向兼容（标注可选，本任务不强求） |
| 背压队列内存 | 每连接 `RTDBD_OUTQ_CAP` 定长（默认 64），总数 = `RTDBD_MAX_CLIENTS*CAP`，可控；可按目标板调小 |
| fail-fast 与 supervisor 冲突 | exit 2/4 致命码不 respawn（已实现区分），避免坏配置无限重启；supervisor 透传退出码 |
| 优雅退出排空超时 | `RTDBD_SHUTDOWN_DELAY_SEC` 限流；超时不阻塞强退 |
| 信号安全 | handler 仅置 `volatile sig_atomic_t` 标志；dump/flush 在主循环 |
| 嵌入式 CRC 成本 | v3.7 自检先做 magic+version；CRC 留接口，按需后续启用 |

## 9. 架构整洁性说明（相对朴素方案）

- **计数/健康隔离 `stats.c`**（类比主题 A `rbe.c`）：rtdbd.c 派发循环不膨胀，计数器单例定长无堆。
- **背压用定长环形队列而非动态队列**：与嵌入式"热路径零堆"约束一致，保留"丢最旧"语义。
- **配置校验纯函数化**：`indurtdb_validate_point_meta` 可单测、不触 shm，复用主题 A flags 定义，避免校验逻辑散落。
- **协议不 bump 版本**：新增 opcode 在 v2 内，守住"不破坏 v3.6 monitor"——这是本主题最关键的边界决策。
- **自检/校验为纯函数式**：同一份逻辑供 supervisor 探测与 monitor 展示共用，不重复。
