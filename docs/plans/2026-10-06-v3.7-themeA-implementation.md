**日期：2026-10-06**
**依赖设计：`docs/plans/2026-10-06-v3.7-roadmap.md` §2（已与用户确认）**
**ABI 不变式**：共享内存段版本仍 `IRT_SHM_VERSION = 2`；`indurtdb_meta_t`（32B）、`indurtdb_point_t`（128B）、`rtdbd_notify_t` 布局与偏移锁死；新增公共纯函数不改动既有结构。

> 本计划遵循 TDD 红-绿-重构：每个任务先写失败用例（红），再实现（绿），最后清理。
> **架构约束（v3.4 T3 守护）**：核心写路径保持纯净——元数据是冷数据，**刻意不进读写热路径**；语义在 **rtdbd 写权威**层施加，不在核心热路径内读 meta。

## 1. 目标与不变式

补齐「上送侧」语义，对标 IoTDB / openHistorian：
1. **死区/RBE 过滤**：rtdbd 写值时，仅当变化超过死区（绝对/百分比）或跨越 EURange 边界才广播 `NOTIFY`，抑制高频小幅抖动的通知风暴。
2. **EURange→量程位**：写值时按元数据 `eur_min/eur_max` 计算 quality 分层量程位（bit4–5），使跨进程直读者看到一致语义。

**关键约束**
- RBE 状态（每点 `last_reported`）**只存在于 rtdbd 进程内存**，不进共享内存 → 零 ABI 变更（已确认）。
- **核心写路径纯净**：默认 `indurtdb_write_*` 仍强制 `quality=GOOD`、**热路径零 meta 读**；EURange 量程位由 **rtdbd（写权威）** 在写入时施加，直接 shm 写者（legacy 路径）默认不含量程位（与其 legacy 定位一致）。
- 热路径零回归：改动后 `run_bench.sh` P99 仍 PASS，回归数据回填 README 表格。
- 向后兼容：元数据 `flags` 默认 = 0 → rtdbd 行为等同现状（每次写都通知、quality 由核心置 GOOD）；现有用例不破。
- 直接 shm 写者（`indurtdb_write_*`）不经 rtdbd，本就不触发 `NOTIFY`；量程位也不由其施加（legacy 路径）。

## 2. 元数据 flags 扩展（`include/indurtdb/indurtdb.h`）

`indurtdb_meta_t.flags` 现有 0/1 位，补充**百分比死区模式位**，并在头文件给出宏：

```c
/* indurtdb.h: indurtdb_meta_t.flags 位定义（落点：现有注释 bit0=eur, bit1=deadband 之后） */
#define INDURTDB_META_FLAG_EUR          (1u << 0)  /* 启用量程检查 */
#define INDURTDB_META_FLAG_DEADBAND     (1u << 1)  /* 启用绝对死区 */
#define INDURTDB_META_FLAG_DEADBAND_PCT (1u << 2)  /* 死区为百分比模式（相对 eur 量程） */
```
- 仅新增位定义与注释，**结构体布局不变**（32B 静态断言继续成立）。
- `deadband` 字段语义保持：绝对模式下为绝对阈值（与值同量纲）；百分比模式下为 0–100 的百分数，实际阈值 = `deadband% × (eur_max − eur_min)`。

## 3. 语义纯函数集中模块（新建 `src/core/irt_semantics.c` + 内部头）

为消除重复并单一化「值→语义」逻辑，新建语义模块，收口所有纯函数（供核心可选写入口与 rtdbd 复用，避免散落）：

```c
/* 类型值→double 归一化（消除 rtdbd.c:188-217 / :230-238 两处 per-type memcpy 重复） */
double irt_value_to_double(uint8_t type, const void* value_bits);

/* 死区是否越过：mode_abs=绝对, 否则(百分比)阈值=deadband%*(eur_max-eur_min)。
 * last/cur 归一化为 double 比较；int64 超 2^53 精度损失的边界在文档标注。 */
bool indurtdb_deadband_exceeded(bool abs_mode, double deadband,
                                double eur_min, double eur_max,
                                double last, double cur);

/* 计算量程位：< eur_min → LOW(1), > eur_max → HIGH(2), 区间内 → 0。
 * 仅当 eur_enabled 时调用；返回 0/1/2。 */
uint8_t indurtdb_eurange_limit(bool eur_enabled,
                               double eur_min, double eur_max, double value);
```

- 公共 API：`indurtdb_deadband_exceeded` / `indurtdb_eurange_limit`（纯函数，无需句柄），在 `include/indurtdb/indurtdb.h` 声明；`irt_value_to_double` 为内部 static/内部头，不入公共 API。
- `irt_value_to_double` 复用 `indurtdb_point_t.value` 的 union 解析（bool/int32/uint32/int64/float/double → double；string 不适用，RBE 仅对数值类型生效）。

**TDD 红**：`tests/unit/test_c_rbe.cpp`（新建）覆盖：绝对死区边界（含等号不触发）、百分比死区、eur 区间内/越下界/越上界、eur 未启用返回 0、双向（int32/uint32/float/double/int64）归一化、percent 模式 `eur_max==eur_min` 除零保护、`irt_value_to_double` 各类型映射。

## 4. 核心可选 quality-aware 写入口（核心写路径保持纯净）

**文件**：`src/core/irt_point_manager.c` 的 `pm_write_impl`（当前 `:61` 设 `p->quality = INDURTDB_QUALITY_GOOD;`）。

为让 rtdbd（写权威）在**一次 seqlock 写**内同时落值 + 量程位，新增可选写入口，而**默认公共写入口不变**：

```c
/* 内部：quality 由调用方提供（已含量程位等语义层结果） */
static int pm_write_impl_q(irt_pm_t* pm, uint32_t id, uint8_t type,
                           const void* value, uint64_t source_ts_ns, uint8_t quality);

/* 公共 v2：写权威使用 —— 一次写入值 + 调用方计算好的 quality */
int indurtdb_h_write_quality_ts(indurtdb_t* h, uint32_t id, uint8_t type,
                                const void* value, uint64_t source_ts_ns, uint8_t quality);
/* 公共 v1 薄封装：indurtdb_write_quality_ts(...) */

/* 默认公共写入口保持原样：内部以 INDURTDB_QUALITY_GOOD 调 pm_write_impl_q，
 * 热路径零 meta 读，行为等同现状 */
```
- `pm_write_impl` 内部改为 `pm_write_impl_q(..., INDURTDB_QUALITY_GOOD)`，默认路径**完全不变**（无 meta 读、quality=GOOD），守护「meta 不进热路径」不变式。
- `indurtdb_h_write_quality_ts` 是新增可选入口，**仅 rtdbd 使用**；直接写者仍走默认 `indurtdb_write_*` → 不含量程位（legacy 行为，符合架构）。
- **无 ABI 变更**：仅新增函数；既有符号/布局不变。

## 5. T2 EURange→量程位（在 rtdbd 写权威层施加）

**文件**：`rtdbd/src/rtdbd.c` 的 `do_write()`（`:188`）。rtdbd 是写权威，在此计算质量并调用可选写入口：

```c
static int do_write(const rtdbd_write_req_t* w)
{
    /* 1) 取该点 meta（rtdbd attach 后可缓存快照，set_meta 时失效；首版可直接 indurtdb_get_meta） */
    indurtdb_meta_t m; indurtdb_get_meta(w->point_id, &m);
    /* 2) 计算量程位（仅当 flags 开启 eur） */
    double v = irt_value_to_double(w->type, &w->value_bits);
    uint8_t lim = indurtdb_eurange_limit(m.flags & INDURTDB_META_FLAG_EUR,
                                         m.eur_min, m.eur_max, v);
    uint8_t q = INDURTDB_QUALITY_MAKE(INDURTDB_QUALITY_GOOD, lim);
    /* 3) 依类型解包值，调用 quality-aware 写入口（一次 seqlock 落值+质量） */
    ...
    return indurtdb_h_write_quality_ts(g_h, w->point_id, w->type, &val, w->source_ts_ns, q);
}
```
- 量程位在**写权威**统一计算，跨进程直读者（轮询 shm）看到一致语义。
- 直接 shm 写者（legacy）不走此处 → 默认不含量程位（与其定位一致，可接受）。
- **核心写路径零改动、零 meta 读**，守住 v3.4 T3 不变式。

**TDD 红（集成）**：`tests/integration/test_rtdbd_proto_v2.cpp` 新增 `EurangeLimitOnWrite`：经 `irtcli_set_meta(eur on, 0..100)` 后 `irtcli_write_int32(150)` → 读回 `quality` 量程位 == HIGH；写 50 → 0；越下界同理。

## 6. T1 死区/RBE 过滤（rtdbd 服务端，独立子模块）

**新增 `rtdbd/src/rbe.c` + `rtdbd/include/rtdbd/rbe.h`**，隔离 RBE 状态与判定，保持 `rtdbd.c` 派发循环干净。

### 6.1 RBE 状态
```c
typedef struct { bool valid; double last; } rtdbd_rbe_t;
rtdbd_rbe_t* rbe_create(uint32_t max_points);   /* attach 后按 max_points 分配 */
void         rbe_destroy(rtdbd_rbe_t*);
```
- 状态仅存 rtdbd 进程内存，**不进共享内存**，零 ABI 变更。
- 重启重新 attach → valid 全 0 → 首写必通知（合理：进程内存不持久）。

### 6.2 写处理门控（`rtdbd.c:345` 处改为条件广播）
```c
/* 写成功后，依死区/RBE 决定是否广播；判定交给独立子模块 */
indurtdb_meta_t m; indurtdb_get_meta(w->point_id, &m);
double v = irt_value_to_double(w->type, &w->value_bits);
if (rbe_decide(g_rbe, w->point_id, &m, v)) {
    notify_broadcast(conns, nconns, &w);
}
```
`rbe_decide()`（在 `rbe.c`）：
1. `g_rbe[id].valid == false` → 返回 true（首值必通知），置 valid、last=v。
2. 若 `flags & DEADBAND`：
   - 绝对：`indurtdb_deadband_exceeded(true, m.deadband, … , last, cur)`；
   - 百分比：`indurtdb_deadband_exceeded(false, m.deadband, m.eur_min, m.eur_max, last, cur)`。
3. 若 `flags & EUR`：量程位变化（`eurange_limit(last) != eurange_limit(cur)`）→ 通知。
4. 任一为真 → 通知并更新 `last = v`；否则抑制（last 不变）。
5. **flags 全 0（默认）→ 直接返回 true**，行为等同现状（每次写都通知），保证默认零行为变更。

### 6.3 TDD 红（集成）
`tests/integration/test_rtdbd_proto_v2.cpp` 新增：
- `NotifyDeadbandSuppressed`：对某点 `set_meta(deadband on, abs=5)`；连续写 1→2→3（Δ<5）经 `irtcli_write` 后，**订阅端不应收到**对应 `NOTIFY`；写 1→10（Δ≥5）应收到。
- `NotifyEurCrossing`：`set_meta(eur 0..100 on)`；写 50→150 跨上界应收到通知（且量程位变化）。
- `NotifyFirstWriteAlways`：首写必通知（valid 初始 0）。
- `NotifyDefaultUnchanged`：flags=0 时每次写都通知（回归现状）。

## 8. 风险与回退

| 风险 | 缓解 / 回退 |
|---|---|
| 热路径开销 | 核心默认写路径**零 meta 读**；rtdbd 侧读 meta 可缓存快照（set_meta 失效），首版直接 `indurtdb_get_meta`；压测验证 P99 不退化 |
| int64 归一化 double 精度损失 | 死区判定在 >2^53 整数域误差 ≤1 ULP，文档标注；现场整型点位量程通常远小于 2^53 |
| RBE 状态进程内存不持久 | 设计如此（rtdbd 重启首写必通知）；如未来需持久，可在主题 B 的 delta 日志中记录 last_reported（v3.7 不做） |
| 直接写者不含量程位 | 与「rtdbd 是写权威」一致；legacy 单进程路径本就不经语义层，可接受；如需覆盖可后续让其调 quality-aware 入口（无需改 ABI） |
| rtdbd 缓存 meta 与 set_meta 一致性 | 首版直接 `indurtdb_get_meta` 每写一次读（无缓存一致性风险）；后续如需缓存再评估失效机制 |

## 11. 架构整洁性说明（相对初版计划的修正）

初版计划曾把 EURange→量程位直接塞进核心热路径 `pm_write_impl:61` 并热路径读 meta。经架构评审，这违反 v3.4 T3「meta 不进热路径」不变式，且会让同一语义在核心与 rtdbd 两处重复。本版修正：

- **语义在写权威（rtdbd）层施加**，核心写路径保持纯净（默认入口仍 GOOD、零 meta 读）；
- **纯函数集中**到 `irt_semantics.c`，并被核心可选写入口与 rtdbd 复用，消除 `rtdbd.c` 两处 per-type 重复；
- **RBE 隔离**到独立 `rbe.c` 子模块，rtdbd 派发循环不膨胀；
- 新增**可选** quality-aware 写入口（非默认），既不破坏热路径也不强制直接写者改变行为。

即「轻量修正、把语义放对层」，而非大规模重构。
