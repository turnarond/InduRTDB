# S5 现场取证指令（F2 / F3a / F4）

> 状态：执行指令，由用户现场执行；我建工具 + 核数据一致性，执行者对真实性负责，独立工程师复核签名。
> **凭证不入本文档**：所有 token/密码以 `<占位符>` 表示，由执行者现场填入并自行保管。
> **发布门不因此绿**：P10 全场 + P11 `machine_restart_pull_full` 产品实现不足，保持 pending；本轮不填 measured、不放行、不打 tag。

## 0. 现场条件与部署清单

- 六板 SylixOS ARM64：`192.168.30.220 / 223 / 224 / 225 / 226 / 227`（telnet/ftp）。
- 每板部署目录 `/root/indurtdb_s5/`（ftp 上传）：
  - `rtdbd`（S1–S4 构建产物）、VSOA `.so` 共 5 个（`libvsoa-server/client/parser/json/position`，显式链前 4 个）。
  - `policy.conf`、`tokens.txt`（**含双角色条目**：`<plc-token> <uid> <partition> <plc-service-id> plc` 与 `<admin-token> <uid> <partition> <admin-service-id> sync_admin`）。
  - `s5_forensics`（交叉编译 AArch64 ELF，随附 `libc.so` 依赖由 toolchain 提供）。
- 评估版 VSOA license 约 1 h 退出；F4 整机重启两态须在 license 有效期内完成，或由用户提供正式 license。

## 1. 通用启动（每板，telnet 会话 1）

```
cd /root/indurtdb_s5
LD_LIBRARY_PATH=/root/indurtdb_s5:/lib ./rtdbd --vsoa-port <port> --peers-file ./peers.txt --sync-self-addr <板IP> --sync-node-id <node_id> --token-file ./tokens.txt
```
- SylixOS shell 无 `export` / `VAR=val cmd` 通用语法——`LD_LIBRARY_PATH` 在同一命令行前置赋值（若该 shell 不支持，按 G2 报告 §3 的会话内赋值法）。
- `peers.txt`：每行 `<其他5板IP> <node_id>`（`#` 注释、空行忽略；自地址会被拒绝，勿写本机）。
- 期望回显：rtdbd 启动日志含 VSOA 服务名与端口；会话保持不退出。

## 2. F2 六节点采集（telnet 会话 2，每板）

```
./s5_forensics f2 <port> <plc-token> <plc-service-id> <admin-token> <admin-service-id> /root/indurtdb_s5/f2_<板IP>_<时间戳>.json <instance_id>
```
- **S5b 11 参数**：`<f2|f3a|f4-before|f4-after> <port> <plc-tok> <plc-svc> <admin-tok> <admin-svc> <peer-tok> <peer-svc> <self-addr> <out.json> <instance>`；其中 `<self-addr>` 必须与 rtdbd 启动的 `--sync-self-addr <板IP>` **同值**（`reject_self` 负例依赖服务端该参数）。
- **四类 client**：PLC（`/stats/notify` body→延迟、写 1 点触发 NOTIFY、错 token hello）、sync_admin loopback（`/sync/peers/{get,set}` 真值与负例）、sync_peer（写 DENIED/datagram 观察）、bad-token（独立错 token hello）。
- 期望回显：`[S5] dual-role hello OK (mode=f2)` → `[S5-f2] wrote ... (N fields)` → `S5_RESULT: PASS`。
- ftp `get` 回传 JSON 与会话回显日志到主机约定目录（命名带板 IP + 时间戳）；六板齐后交给核验脚本。

## 3. F3a 分区注入与观测（每板或选定对）

- **注入手段**：由执行者现场决定（拔网线 / 交换机 ACL / 防火墙），并在回传日志中记录：注入板 IP、开始/结束时刻（墙钟）、持续秒数（1 / 6 / 30）、具体物理动作。
- 每档注入期间/恢复后运行：
```
./s5_forensics f3a <port> <plc-token> <plc-service-id> <admin-token> <admin-service-id> /root/indurtdb_s5/f3a_<板IP>_<秒数>_<时间戳>.json <instance_id>
```
- **重要**：`partition_duration_s` 与 `stale_epoch_rejected` 在 JSON 中为 `null` + `unavailable` reason（仓内无注入工具、采集程序无伪造 epoch 帧能力）；执行者须在回显日志中手工记录注入时长与观察，作为行为级证据，**不得把 null 改成数值冒充 on-site**。
- 三档"可区分"判定由执行者与独立工程师现场签字确认，不由脚本自动判定。

## 4. F4 整机重启两态（每板）

- 重启前：运行 `s5_forensics f4-before ...`（argv 同 §2，mode 改 f4-before），ftp 回传 `f4_before_<板IP>_<时间戳>.json` 到主机。
- 执行整机重启（**需用户单独授权**；在 license 有效期内）。
- 重启后：rtdbd 按 §1 启动，再运行 `s5_forensics f4-after ...`，回传 `f4_after_<板IP>_<时间戳>.json`。
- **主机侧比对**（S5b，不依赖板上 `/root` 跨重启持久）：主机用 `s5_f4_compare`（unit 已覆盖）比对两份 JSON 的 digest/peers → 产出 `digest_match`/`peers_restored` on-site；`epoch_before/after`（sync_peer `/sync/hello` 门禁 after 态不含 127.0.0.1）、`subs_restored`、`machine_restart_pull_full` 为 `unavailable` + reason，**不得填 measured**。

## 5. 回传与核验

- 回传物：每板 `f2_*.json` / `f3a_*.json` / `f4_*_{before,after}_*.json` + 对应 telnet 会话回显日志（txt）。
- 主机侧我运行 `python3 scripts/check_s5_capture.py <json...>` 核验（字段齐全/来源合法/unavailable 有 reason/P10 字段标 unavailable），出核验报告。
- 台账回填：仅 `on-site` 字段按 `v3.12-S5-capture-schema.md` 映射填入；P10/P11 项保持 pending、note 写"现场不可得"；独立工程师复核签名。
