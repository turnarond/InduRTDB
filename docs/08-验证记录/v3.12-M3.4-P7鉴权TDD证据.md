## 2 真实缺口（先分析后开工）

`rtdbd/src/vsoa/vsoa_adapter.c` 接线前：
- `/hello` 握手有 token 表比对、`service_id` 一致性、`plc`/`sync_admin` 的 loopback 来源校验；
- `/sync/peers/{set,get}` 有 `cred_ok` + `role==sync_admin` + loopback 三重校验；
- **但 13 个镜像能力的公共分派路径没有任何 role→URL 约束** → §8.3-4 要求的
  「sync_peer 仅同步前缀 URL / sync_admin 只做成员管控」只在前两处局部生效。

## 3 实现（GREEN）

新增传输无关纯逻辑 `rtdbd/src/session/rtdbd_authz.{h,c}`（零 fd/socket/poll/vsoa_* 符号，
地址以主机序 uint32 传入，不引平台头）：
- `rtdbd_authz_source_allowed(role, is_ipv4, addr_host)`：
  plc / sync_admin 仅 127/8；sync_peer 显式 `NOT_IMPLEMENTED`；其余 DENIED。
- `rtdbd_authz_url_allowed(role, bare_url)`：deny-by-default 矩阵
  （`/hello` 放行；PLC 禁同步前缀；SYNC_ADMIN 仅 `/sync/peers/set|get`；
  SYNC_PEER 仅同步前缀；UNKNOWN/空 URL 拒绝）。

接线三处：
1. `rtdbd/CMakeLists.txt` 及两个直接编译 adapter 的测试目标加入 `rtdbd_authz.c`；
2. `vsoa_hello` 内联的 loopback 校验改为调用 `rtdbd_authz_source_allowed`（消除重复判据，
   使现场才有的非 loopback 条件可由构造地址验证）；
3. `vsoa_on_cmd` 在 `rtdbd_opcode_from_url` 之后、镜像 dispatch 之前加 role→URL 门禁，
   命中拒绝即回 `0x80 + RTDBD_ST_DENIED`。仅对**真握手**会话（role 由 token 表赋值、
   非 UNKNOWN）生效；`allow_unauthenticated + default_uid` 的联调会话沿用既有判据，
   避免误伤既有 e2e 用例。
