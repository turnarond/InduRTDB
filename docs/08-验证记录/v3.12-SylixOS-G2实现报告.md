## 2 代码侧完成证据

### 2.1 SDK 符号硬门修复（`check_vsoa_sdk.py`）

- **P0-3 修复**：`pool_config` 由子串匹配改为精确符号匹配 `re.search(r"\s[TW]\s+pool_config$", out, re.M)`——SylixOS 库导出 `vsoa_mem_pool_config`/`vsoa_server_pool_config` 不再误判 FATAL。
- 参数化 `--lib-subdir`/`--nm`；符号集扩展为 server 11 + client 8（harness 订阅者所需）+ `REQUIRED_LIBS` 补 parser/json。
- 实跑结果：Linux 默认文件级 OK；Linux 符号级 19 符号全导出、pool_config 不误判；SylixOS 交叉 nm 符号级 OK。
- 配套：`scripts/test_checkers.py` 的 `make_sdk` 白样本补 parser/json 库（改实现后白盒测试同步，非伪造）。

### 2.2 CMake 接入

- `CMakeLists.txt`：VSOA 探测块 `Linux OR SylixOS`、平台化 `VSOA_LIB_SUBDIR`（SylixOS 默认 `lib/sylixos/aarch64`）、透传 `--lib-subdir`/`--nm`（`${CMAKE_NM}` 派生交叉 nm、不硬编码）；rtdbd 在 SylixOS 可显式 `-DINDURTDB_BUILD_RTDBD=ON` 构建（默认 OFF）；新增 `sylixos_vsoa_e2e` target。
- `rtdbd/CMakeLists.txt`：`--disable-new-dtags`/`BUILD_RPATH` 加 Linux 守卫（SylixOS 用 toolchain rpath 或部署期 LD_LIBRARY_PATH）。
- SylixOS configure 实跑通过：`SDK 探测通过 ... (lib/sylixos/aarch64)`。

### 2.3 rtdbd legacy 逐块隔离（编译错误驱动）

变更卡评审 P0-1/P0-2 修正为"逐块隔离 + 编译错误驱动"而非脆弱行区间。实际交叉编译两轮收敛：

| 轮次 | 错误 | 处置 |
|---|---|---|
| 1 | `AF_INET` 未定义（`rtdbd_peer_table.c`）；`supervise`/`pidfile` set-but-unused | 补 `<netinet/in.h>`；`#ifndef INDURTDB_OS_LINUX` 下 `(void)` 抑制 |
| 2 | 零错误 | supervisor 段（`:1889-2054`）+ 调用点（`:2391-2393`）`#ifdef INDURTDB_OS_LINUX` 隔离完成 |

SylixOS POSIX 兼容层足够完整（socket/AF_UNIX/getopt_long/poll/SO_PEERCRED 均能编译），实际隔离面小于评审预估。交叉编译产物验证：

```
build-g2a/rtdbd/rtdbd: ELF 64-bit LSB shared object, ARM aarch64, dynamically linked
build-g2a/sylixos_vsoa_e2e: ELF 64-bit LSB shared object, ARM aarch64, dynamically linked
```

`nm` 确认无 `supervise_loop`/`execv`/`write_pidfile` 符号（隔离成功）；`nm -D` 确认 `vsoa_server_start`/`vsoa_server_cli_datagram` 为 UND 动态链接（SDK .so，符合预期）。

### 2.4 端到端 harness（`tests/sylixos/sylixos_vsoa_e2e.c`）

- 拓扑：单进程内 3 个 `vsoa_client`（writer 写点位 5 / sub 订阅收 NOTIFY / nonsub 不订阅作对照），共享 `select` + `vsoa_client_input_fds` 事件循环；rtdbd 独立进程先启动。
- 5 项断言：3 client hello+subscribe、订阅成功、write RPC accepted、订阅者收 NOTIFY、非订阅者未收（定向门控）。
- 编译期修正：datagram/rpc 回调签名、`RTDBD_TYPE_INT32`、删除未用变量——最终交叉编译成功、AArch64 ELF。

## 3 板上端到端（G2.3）— PASS 5/5

设备 `192.168.30.177` 恢复连通后完成实测。部署：ftp 上传 rtdbd + harness + 5 个 VSOA .so + `policy.conf`/`tokens.txt` 到 `/root/indurtdb_g2`；telnet 双会话（会话 1 启动 rtdbd，会话 2 跑 harness）。

**设备环境适配（非代码问题，如实记录）**：
- telnet 登录**未自动加载** `/etc/profile` 的 `LD_LIBRARY_PATH`，导致外部命令报缺 `libvpmpdm.so`；在会话内设置 profile 里的值后恢复。
- 初次带 `--config points.yaml` 启动 rtdbd 报 `point type out of range (field=5)`——这是**既存配置校验问题**（与 G2 无关）；按变更卡"最小闭环"（config 非必需）**去掉 `--config`** 后 rtdbd 正常启动。
- VSOA 评估版 license 警告（"will exit after 1 hour"）为许可提示，不影响 5/5 断言。

rtdbd 启动日志（关键行）：
```
rtdbd listening on /tmp/gnc.sock (instance=gnc)
VSOA loaded 1 pre-shared tokens
VSOA listening on 127.0.0.1:18999 (dual-stack poll)
```

harness 输出（`./sylixos_vsoa_e2e 18999 tok-plc-1 plc-line-1`）：
```
[E2E 1] PASS : 3 clients hello + subscribe established
[E2E 2] PASS : subscriber subscribed to point 5
[E2E 3] PASS : point/write RPC accepted
[E2E 4] PASS : subscriber received directed NOTIFY
[E2E 5] PASS : non-subscriber did NOT receive NOTIFY
E2E_RESULT: PASS (5/5)
```

**结论**：`vsoa_server_start` 的 loopback bind 与 `cli_datagram` 收发在 SylixOS 3.6.5 上**实测可用**（G2.3 运行硬门达成，符号可用已升级为运行可用）；VSOA 写入 + 定向 NOTIFY 最短闭环端到端通过；非订阅者对照证明定向门控正确。**故障注入负例**：E2E 5（未订阅 client 不收 NOTIFY）即传输层定向门控的负例，已 PASS；变更卡"额外未订阅却发 NOTIFY"的独立负例因 vsoa_adapter 门控已由 E2E 5 覆盖，不再单列。

**清理确认**：rtdbd 进程终止；共享内存段 `indurtdb_gnc`/`indurtdb_g2ok` 删除、`/dev/shm` 复 `ls` 为空；socket 文件与 `/root/indurtdb_g2` 临时目录逐文件删除、复 `ls` 报不存在；设备 `echo CLEAN2_DONE` 正常。未碰 `/lib` 或系统配置。

## 4 配置实例（本次实测）

- policy.conf: `0:*:0:4294967295`（uid 0 放行所有点位）
- tokens.txt: `tok-plc-1 0 0 plc-line-1 plc`（token uid partition service_id role）
- rtdbd 启动: `LD_LIBRARY_PATH="/qt/qt5/lib:/usr/lib:/lib:/usr/local/lib:/root/indurtdb_g2" ./rtdbd --instance gnc --socket /tmp/gnc.sock --max-points 100 --policy <dir>/policy.conf --vsoa-port 18999 --vsoa-token-file <dir>/tokens.txt`（**不带 --config**，规避既存配置校验问题）
- harness: `./sylixos_vsoa_e2e 18999 tok-plc-1 plc-line-1`
- 库路径: 5 个 .so 上传到设备临时目录，telnet 会话内设置 `LD_LIBRARY_PATH`（SylixOS 无 `export`、无 `VAR=val cmd` 前缀语法，直接赋值变量）。
