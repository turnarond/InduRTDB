# S5 取证 JSON → B 段字段映射 schema（v3.12）

> 状态：工具 schema，非台账、非放行。执行者按本表回传 JSON，我核一致性，独立工程师复核签名。
> 硬规则：`on-site` 且值合法 → 可回填 fields；`logic-only`/`unavailable` → **永不回填**，B 段字段缺失、整项 `status=pending`；`null` 无 reason → 校验 FAIL。
> 字段来源标注由 `tests/sylixos/s5_capture.c` 纯函数生成（host 单测 `test_c_s5_capture` 覆盖），脚本 `scripts/check_s5_capture.py` 校验标注合法性。

## JSON 总体结构

`f2_capture.json` / `f3a_capture.json` / `f4_capture.json` 均由 `s5_capture_emit_json` 生成：

```json
{"mode":"f2|f3a|f4","node_id":"<板IP>","fields":{
  "<key>":{"value":<json value>,"_source":"on-site|logic-only|unavailable","reason":"<原因>"}
}}
```

## 附加字段（非 B 段，现场证据链）

- `stats_notify_reachable` / `health_reachable` / `peers_admin_reachable`（`on-site`，布尔 1/0）：双角色 RPC 可达性证据（PLC client 读前两者、sync_admin client 读后者）。
- `notify_latency_ns`（S5b 起 **on-site 真值**）：`/stats/notify` body（48B stats POD）回调内 memcpy，`count>0` 时取 `last_ns`；t1=cli_datagram 调用时刻（尝试发出、非确认送达）。S5 原简化程序仅记可达性、标 unavailable 的口径已由 S5b 取代。
- F3a `partition_duration_s` / `stale_epoch_rejected`：`unavailable` + reason "F3a 注入工具未建、注入手段由执行者现场记录，采集程序无注入能力"。

## 校验硬规则（`check_s5_capture.py`）

1. 每项 B 段字段必须有 JSON 条目；`_source` 三值合法。
2. `_source=="unavailable"` 必须有非空 `reason`；`value` 必须是 `null`。
3. P10 三字段 + P11 `machine_restart_pull_full` 的 `_source` 必须为 `unavailable`（纯函数 `s5_capture_validate` 同规则硬编码）。
4. 台账回填仅接受 `on-site` 且值合法字段；`logic-only`/`unavailable` 字段出现在台账 measured → FAIL。
5. 本脚本**不声称硬防手改**：手改 JSON/台账由执行者真实性声明 + 独立工程师签名链约束；核验报告交叉比对 telnet 回显原文 ↔ JSON 字段（回显日志一并回传）作为可追溯证据。
