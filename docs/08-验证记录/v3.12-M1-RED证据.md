## 6 M1.2 · session 投影接入 rtdbd（连接级状态搬迁）

### 6.1 做法（UDS 行为零变化前提下的机械搬迁）

- `rtdbd_conn_t` 由「连接级状态 + 传输细节混装」改为：`**fd** + **rtdbd_session_t session**（连接级状态真源）+ **outq / snap_outq_count**（UDS 出站传输细节）`。`snap_outq_count` 留在 conn（属出站预算，非会话语义）。
- 搬迁 54 处字段引用（两种变量形式：`c->…` 48 处、`cx->conn->…` 6 处），全部为**机械路径替换**，无逻辑改写；替换后 grep 复查确认无残留旧路径（仅剩同名局部变量/参数）。
- 三处订阅操作改为调用 session API，使 session 成为订阅状态**唯一真源**（两份视图不会漂移）：
  - `conn_has_sub` → `rtdbd_session_subs_contains`；
  - `conn_add_sub` → `rtdbd_session_subs_add`（**三态**映射：`OK`/`EXISTS`/`FAIL` → 0/0/-1，保持既有「已订阅是幂等成功、非失败」语义）；
  - `conn_del_sub` → `rtdbd_session_subs_remove`（末位交换法与快照分页顺序变化均与既有行为一致）；
  - `conn_install_subs` → `rtdbd_session_install_subs`（原子替换，失败时旧订阅集不变；统计口径与既有实现一致：一次失败计一次 `subs_alloc_fail`）。

## 11 M1.5 · `/point/get` 迁入 dispatch（UDS 侧闭环；VSOA 侧待 handle 注入）

## 13 M1.7 · 写路径（`/point/write`）拆分设计与 UDS 侧迁移

### 13.1 拆分设计（写路径的归属划分）

| 环节 | 归属 | 理由 / 依据 |
|---|---|---|
| 请求体解析（24B `rtdbd_write_req_t`） | **前端** | 读字节属传输层 |
| 凭据获取（pid/uid） | **前端** | UDS=`SO_PEERCRED`；VSOA=握手绑定（§8.3-4） |
| **鉴权**（策略 + 分区，deny-by-default） | **dispatch 共享语义** | §8.3-4 要求「与 UDS 同一函数、同一 deny-by-default」 |
| **落值**（meta / 量程位 / quality） | **dispatch 共享语义** | 写权威路径唯一（§8.3-1：VSOA loopback 为现场主写入口） |
| 统计计数（n_writes / write_rejected / write_error） | **dispatch** | 同一进程同一份 `g_stats` |
| **审计记录**（`irt_audit_record`） | **前端** | 审计对象属前端依赖；两侧各自注入 |
| **变更通知**（广播 / 定向） | **前端** | 投递机制传输特有：UDS 遍历 conns 广播；VSOA 须 `cli_datagram` 定向（§8.3-5，禁用 publish） |
| 响应编码 + 发送 | **前端** | 传输层 |

**partition 语义澄清（迁移前实测确认）**：既有 UDS 写路径的鉴权用的是**连接级默认分区**
（`OP_SELECT` 设置），**不是**点位所属分区 —— 与订阅路径（用点位分区）不同。迁移严格保持
该语义（`rtdbd_dispatch_write(..., uid, partition, ...)` 由前端传入连接分区）。

- UDS 侧 `write_one` 改为**薄包装**：调 dispatch + 成功后 `irt_audit_record`；

## 14 M1.8 · per-cli 会话地基 + `/select` + VSOA 侧 `/point/write`（含一个真实字节序缺陷）

### 14.1 落地

- **adapter per-cli 会话表**（`RTDBD_VSOA_MAX_CLI = 32`，与 §8.3-4 token 表上限对齐）：
  每连接一份 `rtdbd_session_t`（连接级分区、凭据等）；`vsoa_server_on_cli` 回调在
  **连接建立**时初始化会话、**断开**时释放（避免连接 id 复用导致状态串台）。
- **`/select`**：写入该连接的 session.partition；分区非法 → `DENIED` 且**不改**连接状态
  （与 UDS 侧 `op_select` 语义一致）。
- **`/point/write`**：走**共享**的 `rtdbd_dispatch_write()`（鉴权与 UDS 同一函数、同一
  deny-by-default，§8.3-4）+ 前端审计回调；未注入 policy/conf/handle → `NOT_IMPLEMENTED`
  （显式未实现，**绝不默认放行**）。
- **写路径依赖注入**：`set_policy` / `set_conf` / `set_audit` / `set_default_uid`。
- **共享通知语义**：dispatch 新增 `rtdbd_dispatch_notify()`（组装 `rtdbd_notify_t`，时间戳与
  质量取**当前点值**）+ `rtdbd_dispatch_notify_rbe()`（RBE 门控，复用 subtab 状态机）；
  UDS 侧 `notify_broadcast` 改为调用这两个共享函数（VSOA 侧须逐连接定向投递同一份帧，
  §8.3-5，禁用 publish ⇒ 帧内容与 RBE 状态机必须两端一致）。

### 14.2 一个真实缺陷：seqno/tunid 字节序（只在同连接第 2 个 RPC 暴露）

**现象**：新增的 `/select` + `/point/write` 连续两 RPC 用例中，`/select` 成功、
`/point/write` 的客户端收到 `hdr=NULL`（= 服务端未响应）→ 3s RPC 超时。

**定位过程（探针实测，如实记录）**：
1. 服务端侧探针显示：请求**确实到达**、`vsoa_server_cli_reply()` **返回成功**；
2. 客户端侧探针显示：第一个 RPC 收到 `status=128`（0x80）✓，第二个收到 `hdr=nil`；
3. 打印 `hdr->seqno` 得到：第一个请求 **0**、第二个请求 **16777216**（= 0x01000000，
   即**网络字节序**的 1 被当作主机序读出）—— SDK 头文件明示 `vsoa_header_t` 的多字节成员
   用 network byte order。

**根因**：cmd 回调的 `hdr->seqno` 是**网络字节序**，而 `vsoa_server_cli_reply()` 的
`seqno`/`tunid` 期望**主机字节序**（SDK 内部再转网络序）。我原样透传 → 客户端按网络序
匹配不上 reply → 超时。

**为何此前未暴露**：三个已通过用例（ping/caps/get）各自**独立建 client**，其第 1 个请求
`seqno=0` → 主机序与网络序相同 → 字节序错误被**掩盖**。只有「同一连接连续第 2 个 RPC」
才触发。

**修复**：`seqno = ntohl(hdr->seqno)`、`tunid = ntohs(hdr->tunid)`。修复后 4 个联调用例
全过（新增用例即覆盖同连接连续两 RPC）。

### 14.3 测试

- **单测**：`test_c_dispatch` **10 tests PASSED**（新增 `NotifyFrameAndRbeGateAreSharedSemantics`：
  通知帧字段正确、两次组装字节一致、RBE 首值必发且未启用死区时每次都发）。
- **联调**：`test_vsoa_e2e` **4 例全过**（ping 链路 / caps 字节等价 / get 字节等价+值正确 /
  **select→write 写权威路径**：VSOA 写入后经 `dispatch_get` 读回 4321 ✓）。
- **门禁**：ON 全量 **45/45**；默认 OFF **ALL GREEN**（44 ctest，证据
  `build/check-all-20261107-170932.log`）；探针已全部清除（`grep -c dbg` = 0/0）。

### 14.4 留白（重要缺口，不得掩盖）

1. **VSOA 侧变更通知尚未投递**：写路径只落库 + 审计，**未向订阅者发定向通知**

## 15 M1.9 · VSOA 侧变更通知**定向投递**（§8.3-5）+ 订阅鉴权共享语义

  策略 + 分区）。⚠ 分区语义**与写路径不同**：订阅用**点位所属分区**，写路径用**连接级

## 16 M1.10 · hello 握手 + 预共享 token 表（真实身份绑定，§8.3-4）

### 16.1 落地

- **token 表**：`rtdbd_vsoa_token_entry_t tokens[32]`（**定长、零动态分配**，§8.3-4）；
  条目含 token / uid / partition / service_id / role；重复登记同一 token → **更新**条目；
  表满返回 -1。
- **hello 握手**：`/indurtdb/v1/hello`（**VSOA 层专有 URL**，不属于 rtdbd opcode 表，
  须单独注册 listener），请求体 `rtdbd_vsoa_hello_req_t`（token[64]+service_id[64]，
  定长 POD、零序列化）。服务端：token 匹配 → **来源强校验**（plc 必须 loopback；
  sync_peer 需 `sync.peers` 表，未实现 → 显式 `NOT_IMPLEMENTED`）→ **service_id 必须与
  token 表登记一致**（防身份混淆）→ 写入连接 session（cred/role/partition/service_id）
  → `vsoa_server_cli_set_authed(true)`（挡 publish 订阅）。
- **握手强制**：写/订阅路径要求 `session.cred.cred_ok`（已握手），否则 `DENIED`；仅当显式
  `set_allow_unauthenticated(true)` 才允许 `default_uid` 直写（**默认关闭**）。
- **审计带 service_id**：`rtdbd_vsoa_audit_fn` 增 `service_id` 参数（§8.3-4）。

### 16.2 端到端验证（6 例全过）

新增 `HelloHandshakeEstablishesIdentity`：错误 token → `DENIED(0x82)`；service_id 不一致
→ `DENIED`；正确 token → `OK(0x80)`；握手后写入成功（读回 999）。ON **45/45**；默认 OFF
**ALL GREEN**（44 ctest，证据 `build/check-all-20261107-175119.log`）。

### 16.3 过程中的一个实测问题（如实记录）

首次实跑三次 hello 均返回 **status=3**（既非 0x82 也非 0x80）→ 定位为 **SDK 层「无对应
URL」错误码**：`/hello` 未注册 RPC listener（此前只注册 13 个 rtdbd 镜像能力）。补注册即通过。
教训：VSOA 专有 URL 必须单独注册 listener，否则错误码语义与 rtdbd status 完全不同，
易被误判为鉴权失败。

### 16.4 安全状态变更（重要）

改造前：任何能连上 loopback 的进程都能以 `default_uid` 写点（**等于无身份鉴别**）。
改造后：**默认必须 hello 握手**（token 表 + service_id + loopback 来源校验），
`allow_unauthenticated` 默认关闭 —— 这是 M1 阶段**最关键的安全闭环**。

### 16.5 留白（如实记录）

1. **token 明文比对**：线上应由 TLS/专线承载（§8.3-4 的 `vsoa_server_passwd` 只作链路
   准入，不承担按点鉴权）。
2. **`sync_peer` 角色未可用**：来源校验依赖 `sync.peers`（§8.3-6 未实现）→ hello 显式
   `NOT_IMPLEMENTED`；其「仅 /sync/* URL + 专用 applier 不进 op_write」亦未实现。
3. **token 表无热更新**（现场换证需重启）。
4. VSOA 重连后订阅重建、rtdbd 主循环合并 VSOA fd（`pollfd` 动态化）未做；
   `/point/batch_write`、`/point/batch_read`（VSOA 侧）、`/snapshot_done`、`/health`
   未迁移；`service_id`/`epoch` 已入 session 但未参与裁决（属 IR7）。

## 17 M2 · 6 节点编排 + 故障注入 harness（IR1–IR7 的基础设施）

### 17.1 交付范围（明确边界，勿夸大）

**交付**：**编排与故障注入地基**（永久脚手架，入库，§10.2 纪律：POC 临时码不入库、
IR fixture 永久脚手架须入库）。

- `tests/integration/vsoa_cluster_harness.{h,cpp}`：
  - `Harness::start(n)`：起 n 个节点（每节点 = fork 子进程跑一个 VSOA adapter，
    **端口由 OS 分配**，各节点独立）；
  - `inject(i, Fault::Crash)`：`SIGKILL`（进程崩溃）；
  - `inject(i, Fault::Pause)`：`SIGSTOP`（进程在但不通 → 模拟**断链 / 网络分区**，§8.3-7）；
  - `clear(i)`：`SIGCONT` 恢复；`restart(i)`：崩溃后重启（端口重新分配）；
  - `probe(i)`：经 VSOA RPC 调 `/ping` 做健康探测（成功判据 = status `0x80`）。
  - 节点的业务后端走**共享**的 `rtdbd_dispatch`（与 UDS 前端同一函数）。

**不交付**（明确留白）：**集群同步语义**（增量/全量同步、epoch 纪元隔离、分区收敛）
属 IR1–IR7 实现期工作，以本 harness 为载体后续补齐；`sync.peers` 成员表、重连后订阅
重建、rtdbd 主循环合并 VSOA fd 亦未做。

### 17.2 用例（4 例全过，1.15 s）

`tests/integration/test_vsoa_cluster.cpp`：
1. `SixNodesStartAndAreReachable`：起 6 节点 → 端口**互不相同**（否则拓扑是假的）→ 逐节点 ping 通；
2. `CrashOneNodeDoesNotAffectOthers`：`SIGKILL` 节点 2 → 该节点探测失败、**其余 5 个不受影响**；
3. `PauseNodeSimulatesLinkLossAndRecovers`：`SIGSTOP` 节点 1 → 探测失败（断链生效），
   节点 0/2 仍可服务 → `SIGCONT` 后节点 1 恢复可服务；
4. `RestartedNodeServesAgainOnNewPort`：崩溃 → 重启 → **端口变化**且重新可服务，其余节点不受影响。

ON 全量 **46/46**（45 → 46）；默认 OFF **ALL GREEN**（44 ctest，证据
`build/check-all-20261107-223147.log`）。

### 17.3 过程中的一个实测问题（如实记录）

首跑 4 例全失败，报「node failed to report port」→ 定位为 `rtdbd_vsoa_adapter_create()`
要求**非空 handler**（`if (!handler || !handler->handle) return NULL;`），而 harness 节点
传了 `nullptr` → 子进程 `_exit(2)`。修正：给节点配走共享 dispatch 的真实 handler。
（另修正一处回调签名笔误：审计回调返回 `int`，实际类型为 `void`。）
