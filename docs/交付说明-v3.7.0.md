## 二、能力达标清单

- **存储与性能**：x86 Release 实测 P99 0.04–1.4 μs，远优于设计目标 ≤10 μs；全类型读写（bool/int32/int64/uint32/float/double/string）+ 采集时刻 `_ts` + 质量。
- **工业语义**：quality / source_timestamp_ns / unit / access；v3.4 元数据区（每点 32B）；v3.7 EURange→量程位生效 + 死区/RBE 通知门控。
- **点位生命周期**：CRUD（create/delete/rename）+ 元数据读写 + `find_by_name`；**B4** 让运行时 CRUD 经 delta 日志跨重启存活（默认关闭，需 `--delta-file` 启用）。
- **并发与韧性**：全局 Seqlock 无锁读；owner 崩溃接管、奇数 `write_seq` 恢复、fork 安全；v3.3 `rtdbd` 写权威（UDS 串行写 + UID 鉴权 + 审计 + 背压 + 优雅退出）。
- **可集成/可观测**：v2 句柄 API（`indurtdb_h_*`）+ v1 单例 API（**B5** 已标 `INDURTDB_DEPRECATED`，未删除）；`RTDBD_OP_HEALTH`、SIGUSR1 dump、运行日志环形缓冲。

## 三、工程化成熟度（产品化门槛已关闭）

- **测试**：gtest 单测 + 多进程集成 + 原始字节布局回归（ABI 防线）；soak 长稳 + 故障注入（owner SIGKILL 自愈）。全量 `ctest` 绿。

- **契约稳定**：共享内存布局（128B/64B/16B、magic、shm version）与 v2.x 逐字节兼容，ABI 保持 v1；`IRT_STATIC_ASSERT` 编译期锁死。
- **文档**：白皮书 / 需求 / 设计 / 技术 / SDK 手册 / 开发规划齐备，版本号四处一致（见第五节）。

---

## 四、已知约束（交付前须向对接方声明）

1. `peek()` 为单拷贝（线程本地缓冲，下次 peek 覆盖），长期持有用 `read_point()`。
2. 单进程单例；不同 `instance_id` 跨进程隔离正常。
3. 写冲突不重试：`write_*` 遇 Seqlock 写中返回 `-2`（busy），调用方自行处理。
4. 超时检测 best-effort（真实采集周期下不触发，见 issue #19）。
5. 订阅为进程内回调，跨进程通知靠轮询/共享内存数据本身。
6. 本库不含鉴权/加密/持久化/北向协议（由 node-server 承担）。

## 六、本次交付明确不含（经评估不做，YAGNI）

- **分区（partitioning）**：隔离/分片已由多实例（独立 `instance_id` 段）提供；单实例内分区会引入布局与管理复杂度，边缘单节点场景无明确收益。
- **继续加点位操作**：现有 CRUD + 全类型读写 + 质量 + 批量 `range` + 元数据 + 订阅 + RBE 已完整，再加属过度设计。
- **持久化/历史库/集群**：既定边界，非本产品交付缺陷。
