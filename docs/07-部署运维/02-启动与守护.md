# 02 · 启动与守护

## 1. rtdbd 完整选项

选项定义见 `rtdbd/src/rtdbd.c` 的 `long_opts[]`。

| 短 | 长 | 参数 | 默认 | 说明 |
|---|---|---|---|---|
| `-s` | `--socket` | PATH | — | UDS socket 路径 |
| `-i` | `--instance` | NAME | — | 实例名，允许字符集 `[A-Za-z0-9_-]`，为空则退出码 1 |
| `-p` | `--policy` | FILE | NULL | **鉴权策略文件**。不给则拒绝所有写，见下文 |
| `-c` | `--config` | FILE | NULL | 点位语义配置 |
| `-m` | `--max-points` | N | 10000 | 点位容量上限，越界则退出码 1 |
| `-b` | `--max-subs` | N | 32 | 订阅者槽位上限 |
| `-S` | `--supervise` | — | 关 | 监管模式：fork 自身拉起 worker（拉起时剔除本选项） |
| `-P` | `--pidfile` | FILE | NULL | pid 文件路径（监管模式拉起时剔除） |
| `-F` | `--stats-file` | PATH | `/tmp/rtdbd.stats` | `SIGUSR1` dump 输出路径 |
| `-D` | `--delta-file` | PATH | NULL | 运行时注册表持久化，**不给即关闭** |

### 最小可用启动

```bash
rtdbd --instance hvac_ahu01 \
      --socket /run/rtdbd/hvac_ahu01.sock \
      --policy /etc/rtdbd/policy.conf \
      --config /etc/rtdbd/points.yaml \
      --max-points 10000 \
      --max-subs 32
```

> ⚠️ `--instance` 与 `--max-points` 决定共享内存段大小。**同一 instance_id 的多进程会挂载同一个段**，容量不一致会导致行为异常。

## 2. 鉴权：不配 policy 就等于关闭写入

`irt_policy_allows()` 末尾为 `return 0; /* deny by default */`。未传 `--policy` 时策略结构体被清零，`rules` 为空，循环不执行，直接返回拒绝。

**症状：rtdbd 启动正常、健康检查通过、GET 正常，但所有 WRITE 返回拒绝，且日志无明确报错。**

若确认要放开写，可给一条 root 通配规则：

```
0:0:4294967295
```

但生产环境应按 uid 精确授权，而非全开。

## 3. 退出码

| 码 | 含义 | 典型场景 |
|---|---|---|
| 0 | 正常退出 | SIGTERM 优雅退出后 |
| 1 | 通用 / 启动错误 | 参数非法、`--policy` 加载失败、socket 创建失败 |
| 2 | **配置校验失败** | `--config` 解析失败，或点位语义非法（`eur_min >= eur_max`、`deadband` 为负、百分比死区越界、`flags` 含未知位、type/access/名称非法） |
| 3 | **共享内存损坏 / 初始化失败** | `indurtdb_initialize` 失败（段头 magic/version 不符等） |
| 4 | **启动自检失败** | 段头自检未通过 |

> 退出码 2 / 4 属于**致命配置/环境错误**，外部 supervisor 应**停止重启**（`autorestart=false`），否则会陷入重启风暴并掩盖真实原因。

## 4. 监管与优雅退出

### 内建监管（`--supervise`）

rtdbd 以 `fork + execv` 自身方式拉起 worker，拉起时自动剔除 `--supervise` 与 `--pidfile`。worker 异常退出由 supervisor 重新拉起。

### 优雅退出

收到 `SIGTERM` / `SIGINT` 后，进入**限时排空**（上限 `RTDBD_SHUTDOWN_DELAY_SEC`）：

1. 排空所有连接的出站队列（`NOTIFY`）
2. 超时未排空则强制退出
3. 关闭 fd、`unlink` socket、退出

排空是为了避免订阅端丢失尾部通知。**部署时应给 SIGTERM 留出排空窗口**（见下节 `TimeoutStopSec`）。

### systemd unit（仓库未提供，需自建）

仓库**不提供** `.service` 文件。以下为参考骨架，请按实际路径调整：

```ini
[Unit]
Description=InduRTDB write-authority daemon
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/rtdbd \
    --instance hvac_ahu01 \
    --socket /run/rtdbd/hvac_ahu01.sock \
    --policy /etc/rtdbd/policy.conf \
    --config /etc/rtdbd/points.yaml
Restart=on-failure
RestartPreventExitStatus=2 4   # 配置/自检失败不重启
RuntimeDirectory=rtdbd
KillSignal=SIGTERM
TimeoutStopSec=30              # 须大于 rtdbd 的排空上限
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

关键两点：

- `RestartPreventExitStatus=2 4` —— 对应退出码 2（配置非法）与 4（自检失败），**重启只会掩盖问题**
- `TimeoutStopSec` 须大于 `RTDBD_SHUTDOWN_DELAY_SEC`，否则排空未完成就被 SIGKILL，订阅端会丢尾部通知

## 5. 接入 node-server / 上层应用

InduRTDB 的设计边界是**只做数据层**。南向设备接入、北向 OPC UA/MQTT、持久化、历史库、集群均由上层（node-server / BAS Edge Data Hub）承担。

典型部署形态：

```
┌─────────────────────────────────────────┐
│ 应用层  BAS驱动 / 控制逻辑 / HMI          │
├─────────────────────────────────────────┤
│ 上层桥接  node-server (OPC UA / 持久化)   │
├─────────────────────────────────────────┤
│ InduRTDB client  ──UDS──►  rtdbd         │
│                共享内存数据面 ◄──────────┤
└─────────────────────────────────────────┘
```

- **写**：经 `client` 连 rtdbd（UDS），由 rtdbd 串行化写并推送 `NOTIFY`
- **读**：直读共享内存，零拷贝路径（`read_point`）
- **通知**：订阅 `NOTIFY`；**绕过 rtdbd 直写共享内存的点位不会产生通知**（写权威唯一，见 `CODEBUDDY.md` 关键不变式）
