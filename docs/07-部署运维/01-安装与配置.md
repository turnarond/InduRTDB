# 01 · 安装与配置

## 1. 构建

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```

前置依赖：CMake ≥ 3.15、支持 C11 的 GCC/Clib、GTest（`find_package(GTest REQUIRED)`，缺失则构建失败）。

> 根 `CMakeLists.txt` 用 `file(GLOB_RECURSE)` 收集源码且**未启用 `CONFIGURE_DEPENDS`**——新增或重命名 `.cpp` 后必须重跑 `cmake` 配置步骤，否则新文件不参与编译。

### 产物位置

| 产物 | 路径 | 是否 install |
|---|---|---|
| 静态库 | `build/libindurtdb.a` | ✅ |
| 写权威守护进程 | `build/rtdbd/rtdbd` | ❌ |
| 客户端库 | `build/client/` | ❌ |
| 诊断工具 | `build/tools/irt_diag/irt_diag` | ❌ |
| 监控台（Web） | `tools/rtdb-monitor/web/`（需 Node 构建） | ❌ |

## 2. 安装库本体

```bash
cmake --install build --prefix /usr/local
```

安装布局：

```
<prefix>/lib/libindurtdb.a
<prefix>/include/indurtdb/indurtdb.h
<prefix>/lib/cmake/InduRTDB/InduRTDBConfig.cmake
<prefix>/lib/cmake/InduRTDB/InduRTDBConfigVersion.cmake
<prefix>/lib/cmake/InduRTDB/InduRTDBTargets.cmake
<prefix>/lib/pkgconfig/indurtdb.pc
```

三条消费路径（回归验证脚本 `scripts/verify_consume.sh`）：

```cmake
find_package(InduRTDB REQUIRED)      # 之后用 InduRTDB::indurtdb
```

```bash
pkg-config --cflags --libs indurtdb  # 注意 prefix 需一致
```

```cmake
FetchContent_Declare(indurtdb GIT_REPOSITORY <url>)
```

> **子项目隔离**：以 `add_subdirectory` / FetchContent 方式引入时，检测到 `INDURTDB_IS_TOP_LEVEL` 为假，**默认不构建 tests/examples 且不执行安装**，不会污染消费方构建。

## 3. 安装守护进程与工具（当前需手动）

`rtdbd`、`client`、`irt_diag`、`examples` **均无 install 规则**，需从构建目录拷贝：

```bash
install -m 0755 build/rtdbd/rtdbd        /usr/local/bin/
install -m 0755 build/tools/irt_diag/irt_diag /usr/local/bin/
install -m 0644 build/client/include/indurtdb/*.h /usr/local/include/indurtdb/ 2>/dev/null || true
```

> 开箱即用的 install 规则与打包产物属已知缺口，见 [`README.md` §已知部署缺口](./README.md)。

## 4. 配置文件：鉴权策略

rtdbd 通过 `--policy` 指定，格式极简（`rtdbd/src/policy.c` 手写解析，非 YAML）：

```
# 注释以 # 开头
# 格式：uid:min_point_id:max_point_id
1000:0:4999
1001:10000:10999
0:0:99
```

| 约束 | 值 |
|---|---|
| 每行格式 | `uid:min_id:max_id`，三个十进制无符号数 |
| 注释 | `#` 起始到行尾 |
| 空行 / 格式不符 | **静默跳过**，不报错 |
| 规则数上限 | **32**（`IRT_POLICY_MAX_RULES`），超出返回 `-3` 并使 rtdbd 退出码 1 |
| 单行长度上限 | 128 字节（`IRT_POLICY_LINE_MAX`） |
| 匹配语义 | 对端 `SO_PEERCRED` 取到的 uid 命中且 point_id 落在 `[min_id, max_id]` 闭区间则放行 |
| 未命中 | **拒绝（deny by default）** |

示例解读：`uid 1000` 可写点位 `0–4999`；`uid 1001` 可写 `10000–10999`；`uid 0`（root）可写 `0–99`。

> ⚠️ **不给 `--policy` 等于关闭所有写权限**（策略为空 → 全部落到 deny）。详见 [`README.md` §坑 1](./README.md)。
> ⚠️ 格式错误的行**被静默跳过**。若规则全部写错，行为等同"拒绝所有写"，且启动不报错——排查时请核对规则数是否真的生效。

## 5. 配置文件：点位语义

通过 `--config` 指定，由 `src/core/irt_config.c` 解析。

**全局字段**

| 键 | 说明 |
|---|---|
| `instance_id` | 实例名（对应共享内存段 `/indurtdb_<instance_id>`） |
| `max_points` | 点位容量上限 |
| `max_subscribers` | 订阅者槽位数上限 |

**点位字段**（`points:` 列表下）

| 键 | 说明 |
|---|---|
| `id` | 点位标识符 |
| `name` | 点位名，`char[64]` |
| `type` | `bool` / `int32` / `int64` / `uint32` / `float` / `double` / `string` |
| `unit` | 工程单位枚举（`0`=无，`1`=°C，`2`=Pa，`3`=% 等） |
| `access` | `1`=READ_ONLY，`3`=READ_WRITE |
| `eur_min` / `eur_max` | 工程量程下/上限；**启用时须 `eur_min < eur_max`**，否则启动 fail-fast（退出码 2） |
| `deadband` | 上报死区。`>= 0`；填 `0–100` 视为百分比死区，绝对值则填绝对量 |
| `flags` | 特性位；仅允许已知位，未知位导致配置校验失败 |

**结构示例**

```yaml
instance_id: hvac_ahu01
max_points: 10000
max_subscribers: 32

points:
  - id: 1001
    name: "AHU_01.Supply_Temp"
    type: double
    unit: 1          # DEGREES_CELSIUS
    access: 3        # READ_WRITE
    eur_min: -50.0
    eur_max: 150.0
    flags: 1         # 启用 EURange 量程位

  - id: 1002
    name: "AHU_01.Supply_Temp.Deadband"
    type: double
    access: 3
    deadband: 0.5    # 绝对死区

  - id: 2001
    name: "Pump_01.Start_CMD"
    type: bool
    access: 1        # READ_ONLY：write() 将被拒绝
```

> ⚠️ **`.gitignore` 屏蔽了 `*.yaml` / `*.yml` / `*.json`**（第 60–62 行）。配置样例入库必须 `git add -f`，或改用 `.conf` / `.txt` 后缀。
>
> ⚠️ 语义字段（`deadband` / `eur_*` / `flags`）**未声明时保持段内原值**，向后兼容。但也意味着配置遗漏不会被发现——详见 [`04-故障排查与升级.md`](./04-故障排查与升级.md)。

## 6. 运行时点位持久化（可选）

`--delta-file <path>` 开启运行时 CRUD 的跨重启存活。**默认关闭**，以保持既有语义（运行时创建的点位重启即丢）。

启用后 rtdbd 在 create/delete/rename 时向 delta 文件追加记录，启动时 `load_config(base)` 后回放 delta 重建运行时点位。base 配置保持不可变、可审计。
