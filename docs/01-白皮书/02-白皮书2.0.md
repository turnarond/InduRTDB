## 1. 执行摘要

**InduRTDB 是 PLC 控制器的实时数据中枢** —— 为驱动、控制逻辑、HMI 提供通过共享内存零拷贝交换数据的统一存储层,并通过 rtdb_server 将数据以 VSOA RPC 对外暴露,支持多节点集群同步。

InduRTDB 之于 PLC 控制层,正如 Redis 之于 Web 应用层 —— 都是内存优先、高性能、简单 API 的数据中枢。核心区别:

- **嵌入式库**(`.a`),非独立进程 —— 直接链接进 `rtdb_server`,无网络开销
- **共享内存零拷贝** —— host 进程 `peek()` 返回共享内存指针,ns 级延迟,比 Redis 网络往返快 1000 倍
- **工业语义完备** —— 每个点位自带 quality(质量戳)、timestamp(纳秒时间戳)、unit(工程单位)、access(读写权限)
- **集群就绪** —— 多 PLC 节点通过 `/cluster/sync` 同步,启动拉全量,运行推增量,回环防护
- **纯 C11, MIT 许可** —— 零外部依赖,26 个 API 函数,~1072 行源码

## 3. 问题陈述

PLC 内部数据交换的三个痛点:

| 痛点 | 现状 | InduRTDB 方案 |
|------|------|--------------|
| **裸寄存器无语义** | Modbus 寄存器是裸 `uint16_t[]`,不知道哪个是温度、哪个已超时 | name/type/unit/quality/access 元数据,load_config 从 YAML 加载 |
| **进程间拷贝开销** | plc_manager → modbus_server 经 VSOA 序列化/反序列化,μs 级延迟 | host 进程 `peek()` 零拷贝直接读共享内存,ns 级 |
| **集群同步缺失** | modbus_server ClusterManager 耦合 Modbus 语义,不可复用 | rtdb_server 通用 `/cluster/sync`,点位级同步,回环防护 |

## 4. 架构全景

```
┌──────────────────────────────────────────────────────────┐
│  rtdb_server (VSOA RPC 服务, C++)                         │
│  /point/read | /point/write | /point/batch | /cluster/sync │
├──────────────────────────────────────────────────────────┤
│  InduRTDB Core (纯 C11 库, ~1072 行)                      │
│  ┌──────────┬───────────┬───────────────┬──────────────┐ │
│  │ PointMgr │ SubMgr    │ ConfigLoader  │ OSAL         │ │
│  │ seqlock  │ 256 slots │ key=value+    │ POSIX/SylixOS│ │
│  │ 4 types  │ zombie    │ YAML 元数据   │ shm/time     │ │
│  │ access   │ cleanup   │               │              │ │
│  │ check    │           │               │              │ │
│  │ timeouts │           │               │              │ │
│  └──────────┴───────────┴───────────────┴──────────────┘ │
├──────────────────────────────────────────────────────────┤
│  共享内存段                                               │
│  ┌────────────────┬────────────────┬───────────────────┐ │
│  │ Header (64B)   │ Points (N×128B)│ Subs (M×16B)      │ │
│  └────────────────┴────────────────┴───────────────────┘ │
│  段名: /indurtdb_<instance_id>                            │
└──────────────────────────────────────────────────────────┘
```

### 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 并发控制 | Seqlock (序列锁) | 多读少写最优,无锁,无死锁 |
| 内存模型 | 共享内存 mmap | 零拷贝跨进程,无序列化开销 |
| 数据类型 | bool/int32/double/string[32] | 覆盖 PLC 四态 |
| 存储布局 | 定长 128B 点位 | 无堆碎片,可预测,可 mmap |
| API 风格 | 单例 C 函数 | 最小依赖,无 C++ 运行时 |

## 5. 性能基准

### 5.1 访问延迟对比 (x86 参考)

| 操作 | InduRTDB (shm) | Redis (本地网络) | SQLite (文件) |
|------|---------------|-----------------|-------------|
| 单点写 | ~0.5 μs | ~50 μs | ~500 μs |
| 单点读 | ~0.3 μs | ~30 μs | ~100 μs |
| peek (零拷贝) | ~0.05 μs | N/A | N/A |
| 批量读 100 点 | ~30 μs | ~500 μs | ~2 ms |
| 并发读(多进程) | 零开销(shm) | 网络开销×N | 锁竞争×N |

> peek() 仅执行 `__atomic_load_n` + 返回指针(~50ns)。Redis 需 TCP + RESP 解析(~50μs)。**差了 1000 倍**。

## 6. 部署拓扑

### 6.1 单 PLC 内部

```
PLC 控制器
┌──────────────────────────────────────────┐
│  plc_mgr(VSOA写)    ecs_guard(peek读)    │
│       │                    │              │
│       ▼                    ▼              │
│  ┌─────────── rtdb_server ───────────┐   │
│  │  InduRTDB (共享内存 owner)         │   │
│  │  /indurtdb_rtdb_instance          │   │
│  └────────────────────────────────────┘   │
│       ▲              ▲                    │
│  容器A(VSOA读写)  容器B(VSOA读写)         │
└──────────────────────────────────────────┘
```

**规则**: 写必须经 VSOA(保证集群同步); 读可用 peek(host) 或 VSOA(容器)。

### 6.2 多节点集群

```
Node A ──VSOA /cluster/sync──► Node B
  │ 启动: 从主节点 pull 全量
  │ 运行: 增量推送变更
  │ 防回环: source_node 标记
```

## 7. 工业安全

| 维度 | Modbus TCP | InduRTDB + VSOA |
|------|-----------|----------------|
| 认证 | ❌ 无 | ✅ VSOA Password |
| 加密 | ❌ 明文 | ✅ VSOA 内置加密 |
| 授权粒度 | ❌ 能 ping 就能读写 | ✅ 点位级 access 控制 |
| 审计追踪 | ❌ 无 | ✅ timestamp + quality |

**数据面安全**: access 控制(READ_ONLY)在 seqlock 保护区内强制执行,无 TOCTOU 窗口。所有数据结构为定长值类型,无指针入共享内存。

## 8. 对外接口

### 8.1 C API (26 函数)

```c
indurtdb_initialize("my_instance", 50000, 32);
indurtdb_write_double(1001, 23.5);       // 写入温度
indurtdb_read_point(1001, &point);       // 完整读
const indurtdb_point_t* p = indurtdb_peek(1001); // 零拷贝
indurtdb_read_range(0, 100, buf, 100);   // 批量
indurtdb_subscribe(2001, cb, NULL);      // 订阅
indurtdb_check_timeouts(1000000);        // 超时 1ms
```

| 方案 | 延迟 | 工业语义 | 集群 | 嵌入式 | 许可 |
|------|------|---------|------|--------|------|

| SQLite | ms 级 | ❌ | ❌ | ✅ | Public Domain |
