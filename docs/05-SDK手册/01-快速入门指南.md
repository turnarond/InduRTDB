# InduRTDB 快速入门指南

**版本**: 3.1.0 | **更新日期**: 2026-08-09 | **变更**: 对齐 v3.1.0 (26 函数 API 不变, 集成产品化版本)

---

## 1. 前置要求

- 编译器: GCC >= 7.5 (C11 编译库, C++17 编译测试)
- 构建系统: CMake >= 3.15
- 系统库: pthread, rt (Linux 标配)
- 可选: Google Test (仅构建测试需要)

## 2. 构建 SDK

```bash
git clone <repo-url> && cd InduRTDB
mkdir build && cd build
cmake .. -DCMAKE_INSTALL_PREFIX=<你的安装前缀>
make -j$(nproc)
cmake --install .           # 安装 libindurtdb.a + 头文件 + cmake/pkg-config 支持
```

产物:
- `<prefix>/lib/libindurtdb.a` -- 静态库
- `<prefix>/include/indurtdb/indurtdb.h` -- 公共头
- `<prefix>/lib/cmake/InduRTDB/` -- CMake 包配置 (用于 `find_package`)
- `<prefix>/lib/pkgconfig/indurtdb.pc` -- pkg-config 支持
- `tests/unit/test_c_*` -- 单元测试
- `tests/integration/test_c_multi_process` -- 集成测试

## 3. 链接到你的项目

InduRTDB 支持三种集成方式，详见 [`04-集成指南`](./04-集成指南.md)。推荐使用 **find_package**（CMake）或 **pkg-config**（Makefile/命令行）：

**推荐: CMake find_package**（需先 `cmake --install` 到指定前缀）:

```cmake
find_package(InduRTDB REQUIRED)
target_link_libraries(your_app PRIVATE InduRTDB::indurtdb)
```

**推荐: 命令行 pkg-config**（安装后使用）:

```bash
gcc -std=c11 your_app.c $(pkg-config --cflags --libs indurtdb) -o your_app
```

**备选: 构建树直接引用**（无需安装，开发调试用）:

```bash
gcc -std=c11 your_app.c -I<repo>/include -L<repo>/build -lindurtdb -lpthread -lrt
```

cmake -S . -B build -DINDURTDB_ENABLE_VSOA=ON -DVSOA_SDK_ROOT=<libvsoa 树根>

./build/examples/vsoa_dualstack_example

### v3.12 M3.2：集群成员管控可运行示例（irtcli）

`examples/peers_example.c` 用 `irtcli_set_peers` / `irtcli_get_peers` 完成
「整组替换 → 读回 → 清空 → 确认 0 条」的完整往返。示例**自包含**：默认自己
fork/exec 一个真实 `rtdbd`（临时 socket / 策略 / 配置，退出时回收），因此无需

```bash
cd examples && make peers_example && ./peers_example
# 或 CMake 构建后：./build/examples/peers_example
```

实测输出（节选）：

```
=== InduRTDB 集群成员管控示例 (irtcli SDK, v3.12 M3.2) ===
[1] 连接 rtdbd (...) ...
[2] SET_PEERS 3 条（整组替换）...
[3] GET_PEERS（state=1 JOINING 由主循环循环尾延迟动作落地）...
    10.20.0.1    plc-a    state=1
    10.20.0.2    plc-b    state=1
    10.20.0.3    plc-c    state=1
[3.1] 尝试 SET_PEERS 含本节点地址 10.20.0.99（应被拒）...
    OK（拒绝且旧表 3 条不变）
[4] SET_PEERS 空表（清空）...
[5] GET_PEERS 确认 0 条...
=== 示例运行完成! ===
```

示例自启 `rtdbd` 时传入 `--sync-self-addr 10.20.0.99`，故 `[3.1]` 演示
「`SET_PEERS` 含本节点地址 → 服务端拒绝且旧表不变」（§8.3-6 / M3.3 接线）。

`state=1 (JOINING)` 是服务端把 `PEER_ADD` 入延迟动作队列、在主循环**循环尾**
统一执行后落地的状态（§8.3-3 / §8.3-6）；它不是客户端写死的值，因此该示例
同时可证伪「延迟队列是否已接入主循环」。Python 侧等价往返由
`tools/rtdb-monitor/run_smoke.sh` 的 `set_peers/get_peers` 段覆盖。

## 4. 第一个程序 (纯 C)

```c
#include <indurtdb/indurtdb.h>
#include <stdio.h>

int main() {
    // 初始化 (首个调用的进程创建共享内存)
    if (indurtdb_initialize("my_app", 4096, 10) != 0) {
        fprintf(stderr, "初始化失败: %s\n", indurtdb_get_last_error());
        return 1;
    }

    // 写入温度数据
    indurtdb_write_double(1, 23.5);

    // 读取
    double temp;
    if (indurtdb_read_double(1, &temp) == 0) {
        printf("温度: %.1f°C\n", temp);
    }

    // 清理 (仅 owner 进程需调用)
    indurtdb_shutdown();
    return 0;
}
```

编译并运行:
```bash
gcc -std=c11 -I<indurtdb>/include -L<indurtdb>/build first_app.c -lindurtdb -lpthread -lrt
./a.out
```

输出:
```
温度: 23.5°C
```

## 5. 写入数据

支持 4 种工业数据类型:

```c
indurtdb_write_double(1001, 23.5);      // double  -- 模拟量 (温度、压力、湿度)
indurtdb_write_int32(2001, 42);         // int32_t -- 计数器、档位
indurtdb_write_bool(3001, true);        // bool    -- 开关、启停
indurtdb_write_string(4001, "Pump_01"); // string  -- 设备名、状态文本 (<=31字符)
```

> **限制**: 字符串最大 31 字符 (含 '\0' 为 32 字节)。

## 6. 读取数据

**拷贝读取 `indurtdb_read_*`** -- 返回值拷贝，适合大多数场景:

```c
double val;
if (indurtdb_read_double(1001, &val) == 0) {
    printf("值: %.1f\n", val);
}

// 完整点位读取
indurtdb_point_t pt;
if (indurtdb_read_point(1001, &pt) == 0) {
    printf("值: %.1f, 时间戳: %lu, 质量: %d\n",
           pt.value.d, (unsigned long)pt.timestamp_ns, (int)pt.quality);
}
```

**快速读取 `indurtdb_peek()`** -- 适合高频读取，但**必须理解它是单拷贝**。

`peek()` 把点位经 Seqlock 拷贝到**线程本地缓冲**，返回该缓冲的指针。
**同线程的下一次 `peek()` 会覆盖上一次的结果** —— 不是「数据可能变化」，
而是**确定性地被下一次调用覆盖**。

⚠️ **典型错误：以为可以持有多个 peek 指针**

```c
const indurtdb_point_t* a = indurtdb_peek(1001);   /* 想留温度 */
const indurtdb_point_t* b = indurtdb_peek(1002);   /* 又读了湿度 */
printf("%.1f\n", a->value.d);                      /* ❌ 拿到的是点位 1002 的值！ */
```

`a` 和 `b` **指向同一块缓冲**。可运行的完整复现见
[`examples/peek_lifetime_example.c`](../../../examples/peek_lifetime_example.c)：

```
a 指针 = 0x73b22307a880, b 指针 = 0x73b22307a880  <-- 同一个缓冲
期望 a->value.d == 23.50（点位1）
实测 a->value.d == 88.80  <-- 已被 b 的 peek 覆盖
```

✅ **正确用法（二选一）**

```c
/* A. 单次 peek 后立即消费 */
const indurtdb_point_t* p = indurtdb_peek(1001);
if (p) printf("温度: %.1f\n", p->value.d);        /* 立即用，不要存指针 */

/* B. 需要长期持有 → 用 read_point 拷到自己的缓冲 */
indurtdb_point_t keep;
indurtdb_h_read_point(h, 1001, &keep);            /* 中途做任意 peek 都不影响 */

/* C. 批量遍历 → 逐个 peek 并立即累加，不存指针 */
double total = 0.0;
for (uint32_t id = 1001; id <= 1100; ++id) {
    const indurtdb_point_t* cur = indurtdb_h_peek(h, id);
    if (cur) total += cur->value.d;                /* 取到就用 */
}
```

| 方法 | 拷贝 | 延迟 | 适用场景 |
|------|------|------|---------|
| `indurtdb_read_*()` | 有 (128B) | ~50ns | 一般读取、**需要长期持有** |
| `indurtdb_peek()` | 单拷贝（线程本地缓冲） | ~10ns | 高频读取、批量遍历（**立即消费**） |

> 注：单拷贝语义**在 v1 与 v2 中相同**，迁移到句柄 API 不会改变这一点。

## 7. 批量读写

```c
// 批量写入
double temps[] = {23.5, 24.0, 24.5, 25.0};
indurtdb_write_range_double(1001, temps, 4);

// 批量读取
indurtdb_point_t buf[4];
int n = indurtdb_read_range(1001, 4, buf, 4);
printf("读取 %d 个点位\n", n);
```

## 8. 订阅数据变更

```c
// 1. 定义回调函数
static void on_temp_change(uint32_t id,
                           const indurtdb_point_t* data,
                           void* user_data) {
    (void)id;
    (void)user_data;
    printf("温度变化: %.1f°C\n", data->value.d);
}

// 2. 注册订阅
indurtdb_subscribe(1001, on_temp_change, NULL);

// 3. 写入时自动触发回调
indurtdb_write_double(1001, 26.0);  // --> 输出: "温度变化: 26.0°C"

// 4. 取消订阅
indurtdb_unsubscribe(1001);
```

> **限制**: 最多 256 个订阅槽位。回调在写入者的线程内执行, 不要在回调中做耗时操作。

## 9. 多进程场景

InduRTDB 的核心设计目标是多进程共享。场景示例:

```
进程A (驱动): initialize("hvac", 10000, 32) --> 创建共享内存 --> write_double(1001, 23.5)
进程B (控制): initialize("hvac", 10000, 32) --> 附加已有段   --> read_double(1001)
进程C (HMI):  initialize("hvac", 10000, 32) --> 附加已有段   --> subscribe(1001, callback)
```

- **首个调用 `initialize()` 的进程** 成为 owner, 创建共享内存段
- **后续进程** 通过相同 `instance_id` 附加到已有段, 校验 magic/version
- 段名格式: `/indurtdb_<instance_id>`
- **重要**: 子进程使用 `_exit()` 而非 `exit()` 退出, 避免触发 `shm_unlink` 导致其他进程的共享内存被错误删除

## 10. 关机与清理

```c
indurtdb_shutdown();
```

- 非 owner 进程: 仅解除 mmap 映射, 共享内存继续存在
- Owner 进程: 解除映射 + `shm_unlink` 删除共享内存段
- 不调用 `shutdown()` 直接退出, 共享内存会残留 (`/dev/shm/indurtdb_*`)
