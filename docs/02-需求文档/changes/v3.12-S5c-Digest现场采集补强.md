## 设计决策

1. **点集采集（零产品改动，修正 P0-3/P1-1/2/3/5）**：f4-before/after 分支用已握手 PLC client：
   - `/point/list`：`rtdbd_list_req_t{max=107, offset, partition=RTDBD_PARTITION_ALL}`（**max=107 = 满页**，`dispatch.c:389`；`max=0` 语义是 0 条或全部未定义，禁用）。返回 `rtdbd_point_info_t[76B]`（point_id/type/access/name[64]/partition，`protocol.h:238-246`）。**offset 是起始 id**（`protocol.h:232-236`、`dispatch.c:395-398`）：首轮 offset=0，后续 `offset = 上页最后一条 point_id + 1`（**非条数累加**）；终止 = 本页条数 < 107 或本页最大 id 到顶。无 total 字段可依赖，故以此终止条件闭区间覆盖。
   - 每条 `/point/get` → 64B `rtdbd_get_resp_t`（`protocol.h:219-229`）：**用 get 的 type 决定 value 分流并校验与 list 的 type 一致**（TOCTOU 防护）——数值类型从 `value_bits` 前 N 字节取，STRING 从 `value_str[32]` 取（`rtdbd_digest.c:28-40`）；`get.source_ts_ns` → `indurtdb_point_t.source_timestamp_ns`（`indurtdb.h:87`，digest 哈希此字段，**非** `timestamp_ns`）。
   - 装配 `indurtdb_point_t`（`indurtdb.h:69-90`）零初始化后按字段写（避免 union 尾部污染）。
2. **失败降级（fix P0-1）**：任一 listed 点 `/point/get` 失败、type 不一致、或分页终止条件未正常达成 → `s5_field_set_unavailable(&cap,"digest",精确 reason)`；全成功才 `rtdbd_digest_compute` → `s5_field_set_on_site(&cap,"digest","\"<hex>\"")`（带 JSON 引号）。附 `digest_n_points`（on-site u64 数值）。**`s5_f4_compare` 比对前必须校验两态 digest 字段 `_source=="on-site"`**：任一非 on-site（含 value=null 的 unavailable）→ `digest_match=false`（修首轮 P0-1：双侧 null 经 json_field_value 都读成 "null" 会假 true）。
3. **空表弱证据机检（fix P0-2）**：`s5_f4_compare` 输出增加 `digest_n_points`（两态点数）与 `evidence_strength`：`n_points>0` → `"normal"`；两态均 0 → `"weak:empty-set"`（空表 digest 恒 `fnv1a64-v1:0000000000000000:0000000000000000:0`，恒等是重言式、零证据力）；`check_s5_capture.py` 机检：若 JSON 含 `digest_match:true` 且 `evidence_strength:"weak:empty-set"`，核验报告必须显式标注弱证据（脚本对 before/after JSON 校验 `digest_n_points` 字段存在且值一致）。用户接受空表 on-site，但**产物级标记而非仅文字声明**防止被误读为收敛证据；P11 仍 pending。
4. **CMake/编译**：`CMakeLists.txt` 的 `s5_forensics` target 追加 `rtdbd/src/cluster/rtdbd_digest.c`（纯 C、仅 stdio/string + indurtdb.h）；交叉编译零警告 + AArch64 ELF；板上只重传 s5_forensics（rtdbd/.so 不变）。
5. **测试（fix P1-4/P2-1/2/5/6）**：

   - `check_s5_capture.py` 增坏样本：双侧 unavailable 映射 `digest_match=true` → FAIL；更新 mode/schema 允许 `digest`/`digest_n_points` 字段。
