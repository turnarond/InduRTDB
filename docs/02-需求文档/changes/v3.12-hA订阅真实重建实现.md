## 问题与影响

VSOA 写入 + 定向 NOTIFY 闭环已通过（G2 板上 5/5），但客户端断链重连后订阅不恢复：断链不入队、执行器只装空集。用户 s-0 裁决必须自动重建（推翻源码"装空集正确"注释 `rtdbd.c:2138-2139`）。不做则连接闪断后通知不可恢复、IR3 的 `sub_rebuild_ok` 永远占位。

**审查推翻的原设计**：25 号方案 §3.2 的"断链时 push REBUILD_SUBS + target_generation 指向新会话、靠循环尾 drain 恢复"经源码核对**不可行**：UDS 断链先 `conn_init`（`rtdbd.c:287-288`：fd=-1、generation++），同轮 drain 时 `defer_session_alive` 查 fd>=0 为 false → stale 丢弃（`rtdbd_defer_actions.c:34,71-75`）；重连 `conn_slot_acquire` 再 `conn_init`（`:324`）generation 再 ++ → target_generation 永久失配。VSOA 断链回调在 `adapter_input`（`rtdbd.c:2863`）内、drain 在其后，此刻客户端未重连未 hello → 同样 stale。既有 stale 机制是"同一连接内延迟动作防槽位复用"，**不适合跨重连**。

## 设计决策

> v2 机制修正 + v3 s-A′=α 定稿，见下方各决策标注。

1. **快照持久驻留**（新增 `rtdbd/src/cluster/rtdbd_sub_snapshot.c/.h`）：断链时不清除，保存点集 + **稳定身份键 session_id**（s-A′=α，见决策 5），供新会话就绪时查表恢复。**只存点集 + session_id，不存 uid/partition/role 凭据**（s-A；session_id 是服务端生成的重连标识、非鉴权凭据）。容量按实际 n 受控分配（非定长 `128×10000≈4.88MiB` 浪费），上限 `RTDBD_SUB_SNAP_MAX`（32 条）+ 每条最多 `RTDBD_SUB_MAX` 点，满则拒并计 dropped。
2. **触发时机改为"新会话就绪"**（fix P0-1）：不在断链时入队等 drain。UDS 在 `conn_slot_acquire`/accept 建立新连接后（`rtdbd.c:2777-2797,320`）、VSOA 在 `vsoa_hello` 成功写入 service_id 后（`vsoa_adapter.c:130-194`，:190），**直接查快照表并按身份键 `rtdbd_session_install_subs` 恢复**（同步、此时会话已 alive、身份已确定）。不复用 defer 的 stale 检查——它本就不是为跨重连设计。defer 队列仍服务既存 RECONNECT/CLOSE/peer 动作，本卡不改其语义。
3. **断链时只保存快照**（fix P1-1）：UDS 两条断链路径（outq_flush 失败 `rtdbd.c:2813-2821` + handle_request 失败 `:2842-2847`）与 VSOA disconnect（`vsoa_adapter.c:115-121`）在 close/session_free 前调用快照保存；**不入队 REBUILD_SUBS**（避免 P0-1 stale 丢弃）。入队/执行分离约束仍遵守（保存是纯内存写，不触发重建执行）。
4. **执行器与 generation**（fix P0-1 连带）：因恢复不走 defer drain，**无需给 defer 注入 VSOA generation/alive 回调**，也无需改 `rtdbd_defer_exec_t` 签名（`rtdbd_defer_actions.h:24-40`，无 transport 维度）——规避 P1-4 的 sid 命名空间冲突。UDS 既存 generation/stale 逻辑保持原样、零改动。这是比 v1"transport 分离执行器"更简单且更安全的路径。
5. **身份匹配（s-A′=α 已定稿，fix P0-2）**：服务端在 hello 成功响应中下发**稳定 session_id**（`uint64`、服务端生成单调递增非零），客户端重连回传，服务端按 session_id 精确匹配快照（A/B 同 service_id 也能区分）。落地三点：
   - **hello 响应体**（`vsoa_adapter.c:345-354` 当前空 body `hout`）：成功时填新 POD `rtdbd_vsoa_hello_resp_t{uint64 session_id}`，失败仍空；老客户端忽略 body、零影响。
   - **回传**：新增 VSOA 专有 URL `/indurtdb/v1/session/rebind`（不进 opcode 表，仿 `/sync/peers` 内联注册），请求 `rtdbd_vsoa_session_rebind_t{uint64 session_id}`；客户端重连 hello 后调 rebind 触发查快照恢复。独立 rebind URL 而非改 hello 请求严格 128B 校验（`:133`），零破坏现有 hello。
   - **session_id 归属**：服务端生成（`a->next_session_id++`）、存 `rtdbd_session_t` 新字段 `uint64 session_id`（`session.h:64-88`）；断链保存快照以 session_id 为键；重连 rebind 校验命中且未过期（上限 32、LRU 淘汰）才 `install_subs` 恢复。
   - **纵深防御（终验加固建议，实施期落实）**：rebind 除 session_id 命中外，另校验新 hello 重建的 `uid/partition/service_id` 与快照记录一致（session_id 单调递增可预测、非凭据，防持有他人 session_id 恢复其点集；恢复的虽是读侧订阅、仍按点 RBE 门控，风险可控非 P0）。不一致 no-op + 计拒绝。
   - **UDS 侧**：无 session_id 契约；UDS 断链快照按连接身份保存、同 slot 重连恢复（UDS 非 G2 主路径，范围小于 VSOA）；详见 §裁决落痕对 δ 的排除说明。
6. **测试**（fix P1-3）：IR3_DeferredQueue 实际载体 `tests/integration/IR3_DeferredQueue.cpp`（`tests/integration/CMakeLists.txt:306-319`，**不是** 13 号 §11.1:439 名义的 `test_vsoa_reconnect.cpp`）——其 target 只链 session/defer/subtab，适合纯逻辑单测（快照 save/restore 单元、身份键、负例）；**真实断链+重连恢复须 ON-only e2e**（复用 `test_vsoa_e2e.cpp` 载体扩一例：hello 取 session_id + 订阅→断链→重连 hello→rebind 回传 session_id→断言订阅按 session_id 恢复、写点再收 NOTIFY；负例：A/B 同 service_id、不同 session_id 的快照隔离不串台）。不改 ctest 名、不新建同名文件；`sub_rebuild_ok`（13 号 §11.1 的 P6 字段，B 段 JSON `fields:{}` 空）本卡只产可观测判据、不填数字。
7. **注释订正**：`rtdbd.c:2138-2139` 按 s-0 改为"重连自动重放点集（客户端重新 hello）"；`rtdbd.c:2192-2196` 同步更新（本卡不再走 defer 重建，注释据实说明恢复改在新会话就绪路径）。
8. **内存预算**（fix P1-2）：声明上限（32 服务 × 10000 点 × 4B ≈ 1.28MiB 上限，通常远小）、受控分配、dropped 计数可观测；Linux 实现但需在卡内明示预算供嵌入式评审。

### 裁决落痕：s-A′=α（2026-11-23）

用户以「h-A 身份匹配裁决」书面确认 **α：服务端下发稳定 session_id、客户端重连回传**（推荐值）。三候选 β/γ/δ 均否决：β 同 service_id 多连接串台、γ 推翻 s-0、δ 对 G2 主路径 VSOA 无效。

| 裁决 | 结论 | 执行边界 |
|---|---|---|
| s-A′ | **α session_id** | VSOA hello 成功响应带 session_id；新 URL `/indurtdb/v1/session/rebind` 回传；按 session_id 精确匹配快照；A/B 同 service_id 也区分；不改 UDS opcode/ABI |
| 与被否 s-A 关系 | s-A（客户端仍 hello、不存凭据）**保持** | session_id 是服务端生成的重连标识、非鉴权凭据；uid/partition/role 仍每次 hello 重建 |
| 前端契约 | hello 响应体扩展 + rebind URL（VSOA 专有，不进 opcode 表） | 老客户端忽略响应 body、零影响；须在评审中核对 VSOA hello 前端契约变更 |

## 验收判据

1. 断链快照：UDS 两条路径 + VSOA disconnect 均保存点集快照（以 session_id 为键）；不产生 REBUILD_SUBS 入队、不被 stale 丢弃。
2. 新会话恢复：VSOA rebind 按 session_id 查快照并 `install_subs` 恢复；UDS 同 slot 重连恢复；"缺快照/session_id 不符"不误装订阅。
3. 安全：session_id 不符不重放、负例断言（含 A/B 同 service_id 但不同 session_id 的隔离断言），不串台、不误伤其他连接。
4. s-A 保持：客户端仍 hello；不存 uid/partition/role 凭据（session_id 非凭据）；每次重连身份由 hello 重建。
5. RED→GREEN：IR3 纯逻辑断言先 RED 后 GREEN；ON-only e2e 真实 hello+订阅→断链→重连 hello+rebind→订阅恢复断言绿。
6. Linux 零回归：OFF ALL GREEN（9 守卫）、ON ctest 全绿；不改 UDS opcode/ABI/对外口径/发布门 FAIL 8/B 段数字（VSOA hello 响应体与 rebind URL 为前端契约扩展，不属 UDS opcode）。
7. 独立评审通过（fresh context + 源码行号回核 + session_id 精确匹配可证伪核对）。
