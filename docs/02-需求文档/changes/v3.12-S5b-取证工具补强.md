## 问题与影响

S5 工具 6 板预检全 PASS，但 `call_rpc` 不捕获 reply body（s5_forensics.c:80-83），B 段字段全 MISSING/unavailable。本卡补强工具使可真取字段产出 on-site 真值。

## 设计决策

> v2 返工：修首轮 2 P0（F4 板上持久无证据 / body 尺寸截断）+ 4 P1；F4 改主机侧两态、body 缓冲 4224B/VALUE_LEN 8192/超长报错。

1. **body 捕获 + 尺寸硬约束**（fix P0-2）：`on_rpc` arg 从 `int *done` 改为 `rpc_reply_t{int done; uint8_t status; uint8_t body[4224]; size_t body_len;}`（4224 ≥ 4104 peers POD + 余量；参照 `test_vsoa_e2e.cpp:192-215` RpcResult），回调内 `status=hdr->status`、`memcpy(body, payload->data/param, clamp(len, sizeof(body)))`（SDK `vsoa_client.h:98-100` 回调返回即失效）。`call_rpc` 返回整结构。**尺寸**：`s5_capture.h` 的 `VALUE_LEN` 128→8192（承载 peers 摘要，`count=2` 串约 100B 但留余量）、emit buf 16384→65536；`set_raw` 超长**返回 false 并报错**（不再静默截断——触"不填假值"红线）。unit 覆盖超长拒绝。
2. **四类 client**（argv 扩展，token/service_id 运行时传入不写真值）：
   - PLC client：`/stats/notify` body（48B）→`notify_latency_ns`（count>0 取 last_ns）、`/point/write` 正向写 1 点触发 NOTIFY（全授权）、错 token hello→`deny_bad_token`。
   - sync_admin client（loopback）：`/sync/peers/get` body（4104B）→peers 真值；`/sync/peers/set` 幂等（当前表原样 set）+ get 回读→`set_peers_idempotent`/`admin_set_peers_ok`；四类拒绝负例（self/invalid/over_limit/旧表不变）→P8 字段。`reject_self` 的 self_addr argv **必须与 rtdbd 启动的 `--sync-self-addr <板IP>` 同值**（现场指令 :20 已带该参数，服务端 `rtdbd_peer_table.c:35-37` 才拒自地址）——卡内写明，避免 argv 用错值测不出（fix P1-1）。
   - sync_peer client（新增，token 运行时传）：hello + 订阅 + datagram onmsg 负向窗→`peer_notify_leak`（正向写由 PLC client）；`/point/write` 应 DENIED→`deny_peer_write`；127.0.0.1 临时成员预置后恢复（admin set）。
   - bad-token client：独立 client 用错 token hello→`deny_bad_token`。
3. **三模式采集**：
   - f2：P7 大部 + P8 大部 + S4 延迟真值 + 可达性。
   - f3a：仍只可达性；两字段 unavailable（无注入工具，裁决不变）。
   - f4：**主机侧两态比对**（fix P0-1）——板上不依赖 `/root` 跨重启持久（G2 报告:99 明确临时目录、全仓无跨重启持久证据）；`before` 态取证程序输出本态快照 JSON → ftp 回传主机 → **整机重启（用户单独授权）** → 起 rtdbd → `after` 态输出本态快照 JSON → ftp 回传 → **主机侧比对脚本**产出 `digest_match`（统一字段名，与 13 号:444/schema:49 一致，fix P1-3）、`peers_restored`；`epoch_before/after` 降级 unavailable（辅助字段非 B 段；sync_peer `/sync/hello` 门禁要求 127.0.0.1 在成员表，after 态重启后成员表由 peers-file 加载其他 5 板 IP、不含 127.0.0.1→DENIED，且为读 epoch 临时加 127.0.0.1 会污染 peers_restored——fix P1-2）；`subs_restored` unavailable。digest 用 S1 `rtdbd_digest.c` 纯函数独立重算（链入工具 target，不改产品）。
4. **不可得字段**（保持 unavailable + 精确 reason）：`deny_non_loopback`（server 仅绑 loopback，分支不可达）、`join_triggers_full`、`rbe_gate_hits/misses`、`snapshot_done_caps_only`、P10 三字段、`machine_restart_pull_full`、`epoch_before/after`、`subs_restored`、F3a 两字段、P3/P6 其余。**两处禁用集合同步**（fix P1-4）：`s5_forensics.c` 的 `ua[]` 与 `s5_capture.c` 的 `product_unavailable_field()` 必须一致（新增 `deny_non_loopback` 等），unit + grep 双向校验。
5. **纯函数/脚本/文档**：
   - `s5_capture.{c,h}`：VALUE_LEN=8192、emit buf=65536、`set_raw` 超长返回 false、增 status/body/F4 主机侧比对纯函数（`s5_f4_compare(before_json, after_json, out)`）。
   - `tests/unit/test_c_s5_capture.cpp` 增例（status 落值、body-derived on-site、超长拒绝、F4 一致/不一致、新禁用字段）RED→GREEN；RED 归档。
   - `scripts/check_s5_capture.py` 增坏样本（不可得字段映射 on-site）+ F4 两态比对坏样本，`--self-test` 全绿；不改门禁脚本。
   - `docs/08-验证记录/v3.12-S5-capture-schema.md` / 指令文档更新字段来源、`digest_match` 统一命名、argv、F4 主机侧两态流程；不写真凭证、不改 B 段 JSON 结构。
6. **边界**：不新增 UDS opcode、不改 UDS protocol.h POD/ABI/lib API/对外口径/B 段 JSON 结构/发布门/版本/tag/main；P10/P11 pending；凭证不入代码/文档；不填 measured、不代签、不放行；F4 重启单独授权。

## 验收判据

1. body 捕获：`rpc_reply_t` 缓冲 4224B、回调内 memcpy + clamp、status/body 正确；unit 验证（含 4104B peers POD 不截断、超长 VALUE_LEN 返回 false）；编译零警告；真机 `/stats/notify` 48B、peers 4104B 成功。
