## 问题与影响

S5b 取证后台账 P7 有 2/4、P8 有 3/6 字段，status pending（字段不全）。三字段可补：`deny_peer_write`（sync_peer 写被拒）、`set_peers_idempotent`（同表 set 两次身份摘要一致）、`old_table_unchanged`（拒绝负例前后旧表摘要一致）。本卡改动取证程序 f2 分支实现，不改产品。

## 设计决策

1. **loopback 成员预置/恢复（用户授权）**：f2 分支内先保存初始 4104B peers body 到 static 缓冲（非强制空表——现场可能预置其他 IP），用 admin set 预置 `{addr:"127.0.0.1", node_id:"s5-loopback-peer"}`（**非自地址**：rtdbd 带 `--sync-self-addr <板IP>`，127.0.0.1 不与板 IP 相同，`rtdbd_peer_table.c:32-40` 不拒；hello 不校验 node_id，仅 token/service_id + 来源，见 `vsoa_adapter.c:315-382`），取证尾 set 回初始表 + get 回读校验（摘要一致）。每模式独立 rtdbd 实例（S5b 批处理已如此），窗口期闭环、不残留。
2. **deny_peer_write**：预置后 sync_peer client 从 loopback hello 成功（来源 127.0.0.1 命中成员表，`rtdbd_authz.c:64-78`）→ 发 `/point/write`（非 `/sync/`）→ 通用门禁 DENIED（期望 status=130/0x82，`rtdbd_authz.c:57-58`）→ `s5_field_set_status` 落真实 status（与 deny_bad_token 同构）。若 hello/写异常 → unavailable+reason（不伪造）。
3. **set_peers_idempotent（摘要口径，非字节级）**：set A → get 摘要 S1（`peers_summary`，只含 addr|node_id，**不含 state**——第二次 set 会把 state 重置 0，raw 4104B 不逐字节相等，`rtdbd_peers_apply.c:31-47`）→ 再 set A（期望 OK）→ get 摘要 S2 → S1==S2 且两次 set 均 0x80 → `s5_field_set_u64("set_peers_idempotent",1,on-site)`；异常 → 0 或 unavailable+reason。写卡注明"幂等=成员身份集合相同，非字节级一致"。
4. **old_table_unchanged**：在 set A/get S1 之后跑现有 `reject_self`/`reject_invalid`/`reject_over_limit` 负例（三者均不改表：`peer_copy_checked` 拒绝或 count 超限在 apply 前返回）→ get 摘要 S2b → S1==S2b → 落 on-site 布尔 1；异常 → unavailable+reason。调整 f2 分支顺序（当前 :303-340 负例在初始 get 后但无合法 set 前置，无法比对）。
5. **现场指令修正（首轮 P1-1：三处不一致一次修正）**：`docs/08-验证记录/v3.12-S5-现场取证指令-F2-F3a-F4.md` 须同步修正：① rtdbd 启动参数 `--token-file` → `--vsoa-token-file`（`rtdbd.c:2051/2249` 实际名）；② `:12` tokens.txt "含双角色条目" → **必须含三角色**（plc + sync_admin + sync_peer，S5b 报告 :9 实证；否则 sync_peer hello 在 `vsoa_adapter.c:326-335` 命中 token 表失败）；③ `:29` 命令示例 8 参数 → **S5b/S5c 的 11 参数**（`s5_forensics.c:6-7` usage，argv 不足 f2 跑不起来）。卡内前置条件写明"现场 tokens.txt 三角色齐全、service_id 与工具 argv 一致"。
   **窗口期安全边界（首轮 P1-2）**：预置 127.0.0.1 后，f2 窗口期内本机任意持 sync_peer token 的进程均可握手成功（来源 127.0.0.1 命中成员表）——但权限已收敛：sync_peer 不能写点（`/point/write` DENIED）、不能改成员表（`/sync/peers/set` 要求 sync_admin+loopback）；窗口仅在单板单 f2 进程内、取证尾恢复初始表、每模式独立 rtdbd 实例，不残留。此项写入现场指令"安全提示"段。
6. **台账/文档**：`v3.12-B段数字落库.json` P7/P8 fields 补三字段（evidence 指向 S5d 核验报告），**status/verified_by/verified_at 不动**；schema 映射表注记三字段的摘要判据；核验报告新增 S5d 章节。S5d 只跑 f2（F4 已由 S5c 完成、不动），4 板重采 f2 + `check_s5_capture.py` 全绿。
