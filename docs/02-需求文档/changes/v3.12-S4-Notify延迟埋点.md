## 问题与影响

F2 取证需 `notify_latency_ns`（FAIL8 设计 F2 JSON 字段），全仓零埋点、`rtdbd_notify_t` 32B 冻结不可加时间戳。S4 用旁路环实现"VSOA 写生效 t0 → NOTIFY 发出 t1"外部打点，并通过只读 URL 供 S5 现场工具取证；不改任何冻结 POD/写路径字节。

## 设计决策

1. **旁路环模块** `rtdbd/src/rtdbd_notify_latency.{c,h}`（纯内存、单线程无锁、**纯追加无消费语义**，仿 h-B `hB_audit_sid.h:17-32` 的 256 项覆盖最旧）：
   - 条目 `{uint32_t point_id; uint64_t t0_ns; uint64_t write_seq; uint32_t sample_count;}`，容量 256；`CLOCK_MONOTONIC`（h-B `hB_audit_adapter.c:9-14`、rtdbd `now_ns()` 同口径，不用 RAW）。
   - `rtdbd_notify_latency_t0(uint32_t point_id)`：写成功后追加条目，`write_seq=全局单调++`，`sample_count=0`；覆盖最旧条目时若其 `sample_count==0` → `dropped_unpaired++`（修复 v1"静默丢样本"漏洞）。
   - `rtdbd_notify_latency_t1(uint32_t point_id) -> uint64_t ns`：**从最新向旧查同 point_id 的最新条目**（不判断消费状态——用户裁决"每客户端一份样本"，同一 t0 供 N 客户端各产一样本），`t1_ns - t0_ns`，该条目 `sample_count++`，聚合 `count++/max/last_ns`（t1 模块内取 `CLOCK_MONOTONIC`）。**可证伪配对证据**：stats 带 `last_write_seq`（最后一次配对所用的 write_seq）。
   - 全局单调 `write_seq` 仅作样本内标识（非 epoch、不参与 S1/S3 裁决）。
   - 聚合 `rtdbd_notify_latency_stats_t{ uint64_t count; uint64_t max_ns; uint64_t last_ns; uint64_t last_write_seq; uint64_t dropped_unpaired; char transport[8]; }`（`"vsoa"` 标识，避免 S5 误认两前端统一口径）+ getter `rtdbd_notify_latency_stats()`（**独立结构，不动 32B notify_counters / 72B health**）。`static_assert(sizeof(...)==常数)` 锁新 POD。
   - **假绿护栏**：无公开手工 setter；`count` 仅真实 t0+t1 配对 ++；单测断言初始 count=0；`last_ns=0` 合法（紧邻 clock_gettime 可能同 ns）——单测断言 `count==1 && max==last && last>=0`，仅 ON e2e 断言 >0（真实跨调用）。
2. **t0 打点位置**：VSOA 写成功处 `vsoa_adapter.c:1035`（`rtdbd_dispatch_write` 返回 OK 之后、NOTIFY 分发前）调 `rtdbd_notify_latency_t0(point_id)`。核实 VSOA 命令回调分支（`vsoa_adapter.c:781-920`）**无批量写/无 opcode 20**——本期 VSOA 无批量写，故无需逐点打点（删除 v1 空洞措辞）；UDS 路径零打点（grep 可证）。
3. **t1 打点位置**：`vsoa_notify_dispatch`（`vsoa_adapter.c:455-493`）中**两层 guard 之后**——RBE 门控 SKIP/MISS（`:478-481`）与发送点护栏 `rtdbd_session_notify_deliver_guard` 失败（`:483-486`）均 `continue`；仅在 `:491` `vsoa_server_cli_datagram` 实际调用之后打 t1。被过滤客户端无 NOTIFY 发出，不计样本（已有 rbe_gate_misses/leak 计数）。
4. **统计出口**（用户裁决）：
   - 进程内 getter `rtdbd_notify_latency_stats()`（独立结构）。
   - 新增只读 VSOA URL `/indurtdb/v1/stats/notify`（专有 URL 分派 + 独立 listener，仿 S2 四 URL；不进 13 镜像表、不加 opcode），返回新 POD 定长 body；`static_assert` 锁尺寸。**门禁精确判据**：专有 URL 不走通用门禁（`vsoa_adapter.c:817-820` 早退），handler 内自带 `cred_ok && role==RTDBD_ROLE_PLC` 判据——依据 `rtdbd_authz.c:47-63`：PLC 对非 `/sync/` 放行、SYNC_ADMIN 仅 `/sync/peers/*`、SYNC_PEER 仅 `/sync/*`、UNKNOWN deny；故只有 PLC 可读 stats（其他角色 DENIED）。未握手 DENIED、错长度 BAD_REQUEST。**S5 现场工具经此 RPC 直接读**，无需 mmap/进程内存。
5. **测试**：
   - unit（GLOB `test_c_*.cpp`，仿 S1/S3 `if(TARGET)` 接实现源）：`test_c_notify_latency.cpp`（初始 count=0；push 覆盖最旧 + sample_count==0 时 dropped_unpaired；同 point 最新 t0 配对；**一 t0 三 t1 产生三样本、last_write_seq 相同**；同点多写用最新 seq；不同 point 隔离；count/max/last 聚合；transport=="vsoa"）。
   - ON e2e：在 `tests/integration/test_vsoa_notify.cpp` 加 `NotifyLatencyNonZeroAfterWrite`——复用 IR5 PLC 订阅者 + datagram 捕获，写点收 NOTIFY 后以 **PLC client 经新 URL** 读 stats（非 IR5 mmap 探针；保留 mmap 仅作既有 IR5 用途），断言 count>0 且 last_ns>0；负例：写点前 count==0、sync_admin client 读 DENIED、错长度 BAD_REQUEST。CMake target 加链新模块（显式列源）。
   - RED→GREEN：先写测试（无实现 → 编译/链接失败 = RED，归档 `docs/08-验证记录/v3.12-S4-RED-baseline.log`），实现后 GREEN。
6. **边界**：不改 `rtdbd_notify_t` 32B / UDS protocol.h opcode / 32B notify_counters / 72B health POD / lib API/ABI/117 计数 / 对外口径 / B 段 / 发布门 FAIL 8 / 不打 tag/合 main；UDS 不覆盖；不伪造延迟值；不填 P3/P10 measured（S5 现场真值）。
