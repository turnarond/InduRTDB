## 设计决策

- **取证通道（用户裁决 q2，v3 §3.1）**：fork 前 `mmap(NULL, sizeof(notify_probe_t), PROT_READ|PROT_WRITE, MAP_SHARED|MAP_ANONYMOUS, -1, 0)`（内核清零）；共享页 `notify_probe_t{ magic, child_fail, seq, snap_seq, init_snap, last_snap }`。**只用 GCC `__atomic_*` builtins**（`__atomic_load_n` / `__atomic_store_n` / `__atomic_fetch_add`），**禁 `_Atomic` / `stdatomic.h`**（`CODEBUDDY.md` 红线：SylixOS 支持不完整）。测试 TU 补 `_Static_assert(sizeof(rtdbd_notify_counters_t) == 32, ...)` 防 padding 漂移。
  - 子进程 `run_server`：create adapter 后在 seqlock 写临界区写 `init_snap`，最后 `__atomic_store_n(&magic, 0x4E4F5449, __ATOMIC_RELEASE)` 发布「初始化完成」；循环内**仅当 `select` 返回 `r>0` 且 `vsoa_adapter_input()` 返回后**刷新（超时轮不刷新、不推进 `snap_seq`）：写端 seq 奇数(RELEASE) → 写 `last_snap` → `snap_seq++`(RELEASE) → seq 偶数(RELEASE) 发布。**落实实现期注意①**：getter 在写临界区**外**读入局部 `tmp`，区内只做纯内存拷贝（严格贴合「Seqlock 临界区内禁止调用外部回调」）。
  - 父进程稳定读：**落实实现期注意②**，自建重试循环命名 `probe_stable_read`（不与已移除的 `irt_seqlock_read()` 混淆）：`s0 = load(ACQUIRE)` → 奇数重试 → 读快照 → `__atomic_thread_fence(ACQUIRE)` → `s1 = load(ACQUIRE)` → `s0 != s1` 重试（对齐 `irt_seqlock.h:52-60`）。
  - **主屏障**：先等 `magic`（1ms 轮询 / 上限 2s / 超时 FAIL）→ 稳定读 `init_snap` → 发 write RPC 等 reply（`vsoa_adapter.c:496` dispatch 同步先于 `:518` reply，reply 到达即「门控已执行」）→ 等 A 收到 datagram → **原子轮询稳定读 `last_snap.hits >= expected`（1ms / 2s / 超时 FAIL）→ 断言 `== expected` 精确相等**。`snap_seq` 只作诊断、不承担屏障。**所有共享页读取在 `kill(SIGTERM)` 之前完成**，kill 后只取 `wstatus`。**落实实现期注意③**：`expected = init_snap.hits + 1`，死区用例看 `misses` 增量、M-5a 看 B 首写必收，各按自己 `init_snap` 计算，不硬编码 1。
- **用例隔离（v3 §3.1 M-2）**：`a->notify_counters` 是 adapter **全局累计**（`calloc` 全 0），四类用例（主判据 / 死区 / M-5a / 注入版）**每 `TEST` 独立 `fork()` + 独立 `mmap` 页 + 三类会话拓扑重建**，`init_snap` 取自各自 server，避免共用 server 使 `hits == 1` 恒红。
- **可证伪判据（v3 §3.2）**：`wstatus` 正常 = `WIFSIGNALED && WTERMSIG == SIGTERM`；**`WIFEXITED` 任意退出码（含 0）判 FAIL**；`CHILD_ASSERT(cond)` 失败 → `__atomic_fetch_add(&child_fail, 1, __ATOMIC_RELEASE)` + `_exit(2)`；`kill` 前多点 `waitpid(WNOHANG)` 提前退出即 FAIL；父进程稳定读后断言 `child_fail == 0`。`peer_notify_leak` 真实语义（`rtdbd_session.c:302`）是「非订阅者 / sync_peer 差点收包 → 记泄露并绝不外发」，`leak == 0` **降级为辅助观测、不独立证伪**。
  - **② 确定性负向观察窗**：同步点（write RPC reply + A 收到 datagram）之后，对 **B、C 各自**执行 `N >= 300` 轮 `select(10ms)` + `vsoa_client_input_fds`，**窗内持续 `ASSERT_FALSE(received)`**；三个 client 各有独立 `fd_set`，`pump_client` 只等 RPC reply 不能替代 datagram 泵。同步点之前对 B/C 的连接、`/notify` URL 订阅、hello、pump 成功逐项 `ASSERT`（正向保证）。
  - **两个中和点、两次 RED（精确到行）**：(a) 删 `vsoa_adapter.c:250-251` 的 `if (g != HIT) continue;` **且**短路 `:253-256` guard 恒 true → 预期**仅 ② B/C `received == true`** 变红（`hits` 不变、`leak` 不变）；(b) **只**删 `:250-251` continue、保留 guard → 预期**仅 ⑤ `leak > 0`** 变红（`hits` 不变、B/C 仍不收）。**(a) 注入 RED 必须在与 GREEN 主用例完全相同的 B/C 观察窗内变红，缺该 RED 即判步骤 5 不通过**。恢复源码后复跑全绿；两次 RED 的命令与输出分别写入 TDD 证据。
- **测试拓扑（v3 §3.3）**：A 订阅者（订 URL + 点位 5，plc，应收）；B 非订阅者（**订 URL 但不订点位**，plc，不收）；C sync_peer（订 URL + 点位但在 gate 被 ② 层先挡，不收）。**C 构造链（用户裁决 q3）**：在子进程 `run_server` 内（与 `test_vsoa_e2e.cpp:130-133` 同处）增登记 `tok-admin-1`(SYNC_ADMIN) / `tok-peer-1`(SYNC_PEER) → admin hello → `/sync/peers/set` 注入 `127.0.0.1`（请求体定长 `rtdbd_peers_resp_t`，参照 `test_vsoa_auth.cpp:236-245`）→ C 在 `allow_unauthenticated` 的 UNKNOWN 态先 `/subscription/add` 点位 5 + 订阅 `/notify` URL → 再 hello 成 sync_peer（`vsoa_adapter.c:186-192` 不清订阅）。**如实披露代表性局限**：依赖 `allow_unauthenticated` **非生产开关**，C 会话不等价于生产完整鉴权链，列为后续待办。
- **死区用例（必做）**：fork 前 `indurtdb_h_set_meta(handle, 5, ...)` 设 `INDURTDB_META_FLAG_DEADBAND` + deadband（父子共享 shm，`rtdbd_dispatch.c:86` 从 shm 读 meta）；A 订阅后首值必发（hits+1、A 收 1 帧）→ 同值二次写 → `rbe_gate_misses` 增量 == 1 且 A 不再收。B/C 在 gate 被 SKIP 不消耗 subtab 状态。该增量**不写进 B 段 `fields`**。
- **M-5a 顺序不变量**：B 先以未订阅态经历一次写 → 再订阅点位 5 → 下次首写 B **必须收到**（证明未消耗其 subtab RBE 状态）。subtab 内部状态逐字段观测无法覆盖，如实留白。
- **非定向通道零帧**：`on_datagram` 断言 `quick == false`；禁用 publish / quick_datagram 由既有静态守卫 + 本用例行为断言共同覆盖。
- **四层 + 故障注入（v3 §4，tdd:深）**：纯逻辑层（`IR4_RbeCounters` 15 用例既有，不依赖 adapter）/ 集成层（仅 `test_vsoa_notify.cpp` 实跑 ON getter 冒烟 + M-5a）/ 契约层（`ctest -N` 含 `IR5_NotifyDirection`、`--conditions` 仍 FAIL 8、B 段四字段仍 pending、两个台账 JSON 零 diff）/ 端到端层 / 故障注入层（门控两中和点 (a)(b) + 取证通道 5 类注入：① `magic` 未置 ② 终态快照不刷新 ③ getter 未调用 ④ server 提前崩溃 ⑤ `child_fail` 未置位 / 未 `_exit`），**每个注入后用例必须真 FAIL 并留 RED**。
- **不触碰**：共享内存布局、22 个 UDS opcode / 错误码契约、`include/indurtdb/indurtdb.h` 公开 API、`VERSION` / CMake `project(VERSION)` / `indurtdb.h` 版本宏、`build/ctest-v3.12-snapshot.txt`、B 段 7 项 `fields`、两个台账 JSON、设备级 IR ctest 名、T1–T5 数字；不新增运行时开关 / 线程；库代码零 malloc/free；发布门保持 FAIL 8；不自行 commit（q4）。

## 验收判据

- **① 正向**：A 收到 1 帧定向 NOTIFY（`cli_datagram`），`point_id == 5`、值正确、`quick == false`。
- **② 负向**：B、C 各自 `N >= 300` 轮负向观察窗内持续 `ASSERT_FALSE(received)`；同步点之前 B/C 连接 / `/notify` URL 订阅 / hello / pump 逐项 `ASSERT` 成功；(a) 注入在同一观察窗内使 B/C `received == true` 变红（兼作正向对照）。
- **③ 计数**：`init_snap` 全 0；`last_snap.rbe_gate_hits == expected`（`expected = init_snap.hits + 1`，精确相等，多发 / 少发均 FAIL）；getter 冒烟覆盖「初始全 0 / `NULL → 全 0` / 写后精确增量」（仅 `test_vsoa_notify.cpp` 实跑）。
- **④ 死区**：独立 TEST，`rbe_gate_misses` 增量 == 1 且 A 二次不再收。
- **⑤ 辅助 / 控制流**：`peer_notify_leak == 0`（辅助观测，不独立证伪）、`child_fail == 0`、`wstatus` 为 `WIFSIGNALED && SIGTERM`（`WIFEXITED` 任意码 FAIL）、`kill` 前 `waitpid(WNOHANG)` 无提前退出。
- **反向验证**：(a) / (b) 两次 RED 各自变红项精确符合上表，恢复源码后复跑全绿；5 类取证通道故障注入各自真 FAIL 并留 RED。
- **工程**：`cmake --build build-vsoa` 零警告（`-Wall -Wextra -Werror`）；`ctest --test-dir build-vsoa -N` 含 `IR5_NotifyDirection`（60 tests）；`ctest --test-dir build-vsoa -R IR5_NotifyDirection` **1/1 Passed**；ON 全量 `ctest --test-dir build-vsoa --output-on-failure` 不回归；OFF `bash scripts/check_all.sh`（full，**禁 `--quick`**）ALL GREEN；OFF `cmake --build build --target IR5_NotifyDirection` 明确「无此目标」（该目标只在 VSOA 块内注册，OFF 不编 adapter）。**禁止只靠 OFF 推断 ON**（切片 1 B1 教训）。
- **契约 / 命名**：`IR5_NotifyDirection` 放 `if(INDURTDB_ENABLE_VSOA)` 块**内**显式 `add_executable` + `add_test`；不注册 `IR1_FullSnapshot` / `IR6.machine_restart` / `IR7_PartitionConverge` / `IR4_NetworkPartition` / `IR5_StaleEpoch`；`release_gate.py --conditions` 仍机械 FAIL 8；两个台账 JSON 与 B 段 json 相对 HEAD 零 diff。
- **部分闭环边界**：`snapshot_done_caps_only` 恒 0 仅作可读出口；不得声称 SNAPSHOT_DONE 生产定向已验证、不得填 B 段数字、不得改两个台账 JSON、不得把 §11.2 判据说成已达成。
