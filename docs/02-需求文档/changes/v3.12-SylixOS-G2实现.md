## 问题与影响

SylixOS/ARM64 单台设备已通过 G0/G1 + atomic64 修复（核心库写路径 PASS），但 rtdbd 尚不能在 SylixOS 上构建/运行——CMake 把 rtdbd+VSOA 探测均排除在 Linux guard 内，rtdbd 主循环无条件编入 UDS/supervisor 的 Linux 专有调用。G2 目标：让 rtdbd 在单台上跑通 VSOA loopback 写入 + 定向 NOTIFY 最短闭环，Linux 侧行为零变化。G2 范围经 h-A~h-D 裁决收窄：订阅重建/审计-health/VSOA↔UDS 网关均排除、另立变更卡。

影响范围：① 顶层 `CMakeLists.txt`（VSOA 探测平台化、rtdbd 条件构建、SDK 符号硬门参数化）；② `scripts/check_vsoa_sdk.py`（平台/架构/nm 参数化 + 符号集扩展 + pool_config 精确匹配修复）；③ `rtdbd/CMakeLists.txt`（平台守卫 + SylixOS 库/rpath）；④ `rtdbd/src/rtdbd.c`（UDS/supervisor 逐块条件编译）；⑤ 新增 SylixOS-only e2e harness 与 .so 部署。不影响 Linux 默认构建/ctest/对外口径/发布门/B 段数字/ABI/opcode。

## 设计决策

1. **CMake 接入**（22 号 §2.4）：`CMakeLists.txt:68` 探测块条件 `AND CMAKE_SYSTEM_NAME STREQUAL "Linux"` → `AND (Linux OR SylixOS)`；`:66-67` 平台化 `VSOA_LIB_SUBDIR`（Linux `lib/linux/x86_64`、SylixOS `lib/sylixos/aarch64`）；`:76-83` 透传 `--lib-subdir`、`--nm`、SylixOS 追加 `--check-symbols`、保留 `--expect-version 1.9.1`；`:109-119` rtdbd 在 SylixOS 顶层可 `add_subdirectory(rtdbd)`（client/diag/tests/examples 保持 Linux-only）；`:103-105` 的 `rt/pthread` 仅 Linux 链接不变，SylixOS 侧依赖 toolchain 默认库（纳入 G2.1 交叉链接实测）。复用 `INDURTDB_OS_LINUX`/`INDURTDB_OS_SYLIXOS`（顶层 `:17/20`），不新增平台宏。
2. **SDK 硬门修复与固化**（评审 P0-3 / P1-1 / P1-2）：
   - **P0-3 必修**：`check_vsoa_sdk.py:21` 的 `POOL_CONFIG_SYMBOL="pool_config"` 在 `:63` 用子串匹配 `if POOL_CONFIG_SYMBOL in out`——SylixOS 库导出 `vsoa_mem_pool_config`/`vsoa_server_pool_config`/`vsoa_client_pool_config`（已实跑确认），会误判 `pool_config_exported=True` → `:68-69` finding → CMake FATAL。改为与 `:61` 一致的**精确符号匹配** `re.search(r"\s[TW]\s+pool_config$", out, re.M)`。Linux 库无精确 `pool_config`，行为不变（既有 T0 取证结论保持）。
   - `--lib-subdir`（默认沿用 linux/x86_64）、`--nm`（默认 `nm`）参数化；CMake 侧用 `${CMAKE_NM}` 派生交叉 nm（**不硬编码** `aarch64-sylixos-elf-nm`，评审 P1-2），SylixOS 传 `--check-symbols`。
   - 符号集扩展为 adapter+harness 实际调用全集：**server 11**（`create/on_cli/add_listener/close/start/cli_address/cli_datagram/cli_reply/cli_set_authed/fds/input_fds`）+ **client 8**（`create/connect/call/on_datagram/subscribe/fds/input_fds/close`，补订阅者所需 5 个，评审 P1-1）；`REQUIRED_LIBS` 增加 parser/json。已实跑确认 Linux 与 SylixOS 两平台库均导出这些符号，扩展不会让 Linux 默认门禁失败。
3. **rtdbd 条件编译 — 逐块隔离策略**（评审 P0-1/P0-2 修正）：**不采用脆弱的行区间整段 `#ifdef`**（UDS listener `:2596-2617` 与 VSOA 创建/start `:2630-2678`、pollfd 构造 `:2680-2691` 深度交错，整段包掉会编掉 VSOA 主路径）。改为：
   - **原则**：SylixOS 下 `#ifdef INDURTDB_OS_LINUX` 只包"UDS 专属函数/变量/语句"，VSOA 段（创建/start/URL 注册/fd 合并/input/drain）一律保留；用**编译错误驱动**逐点补齐隔离点（交叉编译报未定义/unused 即定位下一个 UDS 引用），不预设一份可能遗漏的行号清单。
   - **已识别的隔离点（起点，非全集）**：UDS 连接层函数 `conn_init..outq_flush/notify_broadcast/scan_timeouts`（`rtdbd.c:285-695`）、`peer_cred/conn_peer_cred`（`:795-810`）、UDS `op_*` 与 `kOps[]`/`handle_request`（`:820-1887`，其中 `conn_peer_cred` 调用随 UDS 一并隔离以避 unused）、supervisor 全段（`:1889-2054`，**含尾部 :2051-2054**）+ 调用点（`:2387-2389`）、UDS accept/请求处理（`:2596-2628`、`:2765-2836`）、`sock_path` 校验（`:2381-2385`）、`getopt_long` 长选项结构/循环（`:2227-2255`，见决策 5）、Linux 专有头（`getopt.h`/`poll.h`/`sys/socket.h`/`sys/stat.h`/`sys/un.h`/`sys/wait.h`/`unistd.h`）。
   - **保留点的依赖修正**：VSOA 段使用的 `uds_nfds`（原定义 `:2720`）在 SylixOS 下改为 0 常量；`poll()` 依赖的 `poll.h` 不整段裁掉（SylixOS 需 poll 做 VSOA fd 合并），改由 toolchain/系统头提供（纳入 G2.1 实测）；`g_conns`/`conns` 传入的纯函数（notify gate/scan）保留但 SylixOS 侧传空集或由 VSOA 会话替代。
   - **验证方式**：SylixOS 交叉编译零 `-Werror` 警告即视为隔离完整（unused/未定义都会暴露）；编译失败时按错误逐点补 `#ifdef`，不放宽 `-Werror`。
4. **端到端 harness**（22 号 §3.4，评审 P1-4/P1-6 修正）：新增 SylixOS-only harness（仿 `sylixos_smoke`，顶层 `CMakeLists.txt:158-163` 之后注册）。**拓扑明确为独立进程**：rtdbd 作为被测服务先启动（VSOA ON、loopback、token 表）；harness 作为独立可执行用 libvsoa client API 连 rtdbd——写入线程（`/hello` token+service_id → `/point/write` 24B POD）+ 订阅线程（`/subscription/add` → `/indurtdb/v1/notify` datagram 回调收 `rtdbd_notify_t`）+ 非订阅对照线程；客户端事件循环用 `vsoa_client_input_fds` 驱动（T0 已证单进程同步 connect 超时）。**故障注入**（tdd:深四层要求）：额外构造一个"未订阅却发 NOTIFY"的负例验证门控拦截；`peer_notify_leak`（`vsoa_adapter.h:70-74`，getter 无生产调用点、仅辅助观测）**不作为独立证伪判据**，仅作参考输出；主判据为"订阅者收到且非订阅者未收"。counters 读取：harness 通过 VSOA `/caps` 或新增只读 URL 获取（若跨进程不可读则改为设备日志解析，实施时定案并记入报告）。断言：写入值读回一致、定向 NOTIFY 仅订阅者收、退出码 0。
5. **.so 部署硬门**（评审 P1-5）：`rtdbd/CMakeLists.txt:50-54` 以 `-l:libX.so` 链接 4 个动态库，设备端必须部署 `libvsoa-{server,client,parser,json}.so`（SDK `lib/sylixos/aarch64/` 下，已确认存在）。G2 实施须：ftp 上传 4 个 .so 到设备 `/lib`（或临时目录 + `LD_LIBRARY_PATH`）；`:58-60` 的 GNU ld 专属 `--disable-new-dtags` 加 Linux 守卫，SylixOS rpath 策略开工前定案（toolchain rpath 或 LD_LIBRARY_PATH）；缺库导致 rtdbd 启动失败列为 G2.2/G2.3 阻塞项。
6. **getopt_long 降级具体方案**（评审 P1-3）：SylixOS 若缺 `getopt_long`，**在 `INDURTDB_OS_SYLIXOS` 分支用环境变量传入必要参数**（`RTDBD_VSOA_PORT`/`RTDBD_VSOA_PORT_FILE`/`RTDBD_TOKEN_FILE`/`RTDBD_INSTANCE`/`RTDBD_MAX_POINTS`），main 在 SylixOS 分支跳过 getopt_long 循环、直接读环境变量构造等效 cfg；不硬编码端口/token（安全），不降低 `--max-points` 强制校验语义。环境变量解析为 SylixOS 分支专属代码，Linux 分支保持 getopt_long 不变。
7. **q-B 契约落地**：仅 SylixOS 分支裁 UDS 写；Linux opcode/ABI/UDS 行为零变化（`protocol.h` 静态断言两平台编译期都跑）。不新增 opcode、不改 `libindurtdb.a` ABI。client/monitor 在 SylixOS 现场不可用是已知限制。
8. **跨进程 shm 边界**（评审 P2-3）：G2 **不验跨进程 shm 直连**（G1 只验单进程 + pthread）；rtdbd ↔ harness 的通信走 VSOA，shm 只在 rtdbd 进程内；跨进程 shm 由网关变更卡承接。
9. **不纳入**（h-A~h-D 裁决）：订阅真实重建、审计回调注入、health 镜像 URL、VSOA↔UDS 网关——均另立变更卡。
