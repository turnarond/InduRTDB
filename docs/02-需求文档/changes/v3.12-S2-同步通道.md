## 问题与影响

S1 已交付 epoch/digest 纯地基，节点间同步通道不存在（adapter 只有 server、无 `/sync/*`、无 POD/snapshot/delta/WAIT）。本卡实现 server 侧通道 + 两进程 loopback 验证，为 S3/S5 提供传输层。不做跨机 connector/bind/全量源裁决/真实 wal。

## 设计决策

> v2 返工：修首轮 3 P0 + 6 P1；用户裁决 server 侧+两进程 loopback，跨机留后续。

1. **同步专有 POD**（新增 `rtdbd/src/vsoa/vsoa_sync_protocol.h`，全部 `static_assert` 锁尺寸；放 VSOA 专有头、**不进 UDS protocol.h**、不新增 opcode）：
   - `rtdbd_sync_hello_req_t{ uint64_t epoch; uint64_t struct_hash; uint64_t value_digest; uint32_t n_points; char node_id[32]; }`——含 S1 epoch + digest 的 3 个数值字段（struct_hash/value_digest/n_points；**hex[96] 不传**，可由 3 数值确定，hex 仅日志用）+ node_id（fix P2-10 措辞）。
   - `rtdbd_sync_hello_resp_t` 同字段 + `uint8_t accepted`（本卡 accepted 恒 1，选源留 S3）。
   - `rtdbd_sync_delta_req_t{ uint64_t from_offset; uint32_t max_records; }`、`rtdbd_sync_delta_rec_t{ uint32_t point_id; uint64_t value_bits; uint8_t quality; uint8_t type; uint64_t source_timestamp_ns; uint64_t epoch; char node_id[32]; uint64_t boot_id; uint64_t offset; }`（定长，13 号:246 sync_rec 的 VSOA 专有形态）、`rtdbd_sync_delta_resp_t{ uint64_t applied_offset; uint32_t n_records; uint8_t has_more; }`。
   - `rtdbd_sync_snapshot_req_t{ uint32_t page_index; uint32_t page_size; }`、`rtdbd_sync_snapshot_resp_t{ uint32_t page_index; uint32_t total_pages; uint32_t n_points; }`——**header 经 `vsoa_payload_t.param` 传、点位数组经 `.data` 传**（SDK `vsoa_parser.h:176-181` 四段，不挤同一 buffer；fix P1-4）。页容量按 `min(page_size, (RTDBD_VSOA_RESP_MAX - sizeof(indurtdb_point_t))/sizeof(indurtdb_point_t))` 取整——连续 buffer 逐条 memcpy，**不用 aligned flexible-array**（避免 pad 116B 溢出，fix P1-4 off-by-one）；与 13 号 128KB 偏离已在卡内留痕（resp 8192B 约束，S2b 扩缓冲再对齐）。
   - `rtdbd_sync_wait_req_t{ uint64_t min_epoch; uint32_t required_acks; uint32_t timeout_ms; }`、`rtdbd_sync_wait_resp_t{ uint32_t acks; uint8_t ok; }`。
   - **契约定稿 7 项**：① node_id=`--sync-node-id`，未给取 service_id（S2 临时）；② bind 仍 loopback（跨机 S2b）；③ 出站 token 本卡不做（server 侧只校验入站 token 表，connector S2b）；④ hello 新增独立 URL `/sync/hello`（不扩旧 128B /hello）；⑤ WAIT N-1、超时不回滚（D5）；⑥ hello 不选全源（S3）；⑦ snapshot 页 8192B（偏离 13 号 128KB，S2b 对齐）。**新增**：128KB→8192B 偏离作为契约变更在本卡留痕（无独立用户裁决——上轮 S2 范围裁决已隐含接受"受现有缓冲约束"）。
2. **adapter 同步状态载体**（fix P0-3）：`cli[]` 每项加 `rtdbd_sync_peer_state_t sync_state{epoch, struct_hash, value_digest, n_points, node_id[32], valid}`；hello 成功时填、on_cli 断链分支（vsoa_adapter.c:252-254）清零 `valid=false`；不新增全局表、生命周期随连接。
3. **server 侧专有 URL 分派 + listener**（仿 `/sync/peers/*` :463-494 与 h-C 4 只读 URL）：
   - 专有区加 4 个 `/sync/{hello,snapshot,delta,wait}` 分派，统一 handler `vsoa_sync_handle(...kind)`；4 个 listener 单独注册（仿 admin_urls :848-864），失败即 adapter 创建失败；不进 13 表/opcode 表。
   - **门禁在 handler 内落地**（fix P1-5）：未握手（cred_ok=false）→ DENIED；sync_peer 角色 + `rtdbd_authz_sync_peer_source_allowed(rtdbd_peers_global(), srcbuf)` 来源校验（复用 :287-311 判据，取 `vsoa_server_cli_address`）；sync_admin/其他角色对这些 URL 也 DENIED（仅 sync_peer 可同步）。**错长度 → BAD_REQUEST**。
   - **两进程 loopback 成员表夹具**（fix P1-6）：测试 server 的 `--peers-file` 预置 `127.0.0.1 <node_id>`（**纯 IP、不含端口**，rtdbd_peer_table.h:6）、`sync_self_addr` **留空**（避开自地址拒绝 rtdbd_peer_table.c:35-37）；对端 client 以 sync_peer token hello，源地址 127.0.0.1 命中成员表即通过。不用 SET_PEERS（需 admin+loopback 另建会话）。
4. **server 侧原语**（纯逻辑优先、cluster 层，不进 dispatch——避免 fd/socket 边界）：
   - hello：取 req 的 epoch/digest/node_id 填 `cli[].sync_state`；回本机 epoch（S1 `rtdbd_epoch_current()`）+ digest（本机点集算，复用 S1 `rtdbd_digest_compute`）+ node_id。**不据 epoch 选源**（S3）。
   - delta：**applied_offset 定义为"扫描游标水位"**——从 `from_offset` 起按 id 升序遍历已注册点，每点生成一条 `rtdbd_sync_delta_rec_t`（value_bits/quality/source_ts/本机 epoch/node_id/boot_id，offset=扫描位置）；resp 的 `applied_offset` = 最后扫描 id+1、`has_more` = 是否还有后续点。**可证伪局部语义**：连续两次 delta 从上次 applied_offset 继续，记录不重不漏；**不宣称真实增量正确性**（无 wal，留 S3，fix P0-2 假绿）。
   - snapshot：按 page_index 从本地点集（id 升序枚举）取一页 `indurtdb_point_t[]`；header 经 param、数组经 data；total_pages 按页大小算——**点集动态变化导致 total_pages 漂移是已知简化**（13 号 §3.6 seqlock 边界向量留 S3，fix P1-7 留痕）。
   - **WAIT 延迟动作**（fix P0-1）：回调内**只登记** `wait_ctx{cli_id, seq, tun, min_epoch, required_acks, deadline_ns}` 到 adapter 的定长等待表（16 项、3s 超时），立即返回（不回包、不阻塞）；每轮主循环尾 `rtdbd_vsoa_adapter_wait_pump()` 非阻塞检查：统计 `sync_state.valid && epoch>=min_epoch` 的 peer 数，deadline 到或 acks 足 → `vsoa_server_cli_reply` 异步回写 `wait_resp{acks, ok}` 并释放表项。纯逻辑（阈值判定/超时）放 cluster 层单测。
5. **测试**：
   - unit（GLOB `test_c_*.cpp`，仿 S1 加 `if(TARGET ...)` 接实现源）：`test_c_sync_protocol.cpp`（POD 尺寸/编解码/字节序/页容量边界不溢出）、`test_c_sync_watermark.cpp`（wait ack 阈值含 required_acks>1、超时不回滚、delta 游标不重不漏、stale epoch）。
   - integration（显式 target 仿 test_vsoa_cluster + RTDBD_BIN）：`test_vsoa_sync.cpp`——fork server 子进程 + 外部 vsoa_client，真 hello（sync_peer token + 成员表 127.0.0.1）→ hello 交换 epoch/digest/node_id 一致、snapshot 多页收齐、delta 两次游标不重不漏、wait required_acks=1 成功且 >1 超时返回实际 ack；错长度 BAD_REQUEST、sync_admin DENIED、非成员来源 DENIED。**不做跨机**。
   - RED→GREEN：先写测试（无实现 → 编译/链接失败 = RED，归档），实现后 GREEN。
6. **边界**：不新增 UDS opcode、不改 UDS protocol.h/ABI/POD、不改对外口径/B 段/发布门、不打 tag/合 main；不做 connector/跨机 bind/全量源裁决/真实 wal/backlog/seqlock；server 仍只绑 loopback；quick channel 不承载同步（13 号 §8.3-2），全走 RPC call；dispatch 边界（fd/socket FORBIDDEN）不破——同步实现放 cluster/vsoa 层，不进 dispatch。
