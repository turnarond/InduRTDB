## 问题与影响

h-C u-A 裁决补只读 URL，`GET_PEERS(24)`→`/sync/peers/get` 已实现，但 `list(11)`/`find_by_name(7)`/`meta(8)`/`logs(15)` 的 opcode 虽定义（`protocol.h:41-57`）、UDS 前端有 op_*，**VSOA 前端未注册**——外部 PC 经 VSOA 无法读点位清单/按名查/元数据/日志，监控台"看"能力失效。28 号 §3.2 明确这是设备侧代理前置依赖。本卡只做 rtdbd 侧 4 URL 补齐（前置），代理/瘦网关另立。

## 设计决策

> v2 返工：fix 首轮 2 P0 + 7 P1，r-A 裁 β，见各决策标注。

1. **输入全注入纯函数**（`rtdbd_dispatch.c/.h`，仿 h-B `rtdbd_dispatch_health_fill`）：
   - `rtdbd_dispatch_find(indurtdb_t* h, const rtdbd_conf_t* conf, uint32_t partition, const char* name /*64B,已补NUL*/, uint32_t* out_id)` → status。封装 `indurtdb_h_find_by_name_in` + 分区白名单 + 错误码映射（UDS `op_find_by_name:1201-1239`）。
   - `rtdbd_dispatch_meta(indurtdb_t* h, uint32_t point_id, rtdbd_meta_payload_t* out)` → status。封装 `indurtdb_h_get_meta` + 错误码映射（`op_get_meta:1242-1275`）。
   - `rtdbd_dispatch_list_snapshot(indurtdb_t* h, const rtdbd_conf_t* conf, uint32_t partition, uint32_t max, uint32_t offset, uint32_t max_points, uint8_t* buf, size_t cap, size_t* out_len)` → status。**分区白名单 fail-closed 一并迁入**（UDS `rtdbd.c:1488-1494`：具体分区非法→OK+空 body；ALL 哨兵 `0xFFFFFFFF` 豁免不过滤）；`do_list` 逻辑迁入纯函数（不再调 static `do_list`），`max_points` 由参数注入（不偷用全局 `g_max_points`）；按 cap 截断 max 到 `min(max, cap/76)`。
   - `rtdbd_dispatch_log_snapshot(const irt_logbuf_t* lb, uint32_t max, uint8_t* buf, size_t cap, size_t* out_len)` → status。封装 `irt_logbuf_dump`（`logbuf.c:58-72`）；max 语义：`max==0`→全部、`max>RTDBD_LOG_CAPACITY(128)`→128（`rtdbd.c:1515`），再按 cap 截断到 `min(n, cap/128)`；**单页快照无游标**（与 UDS 一致，不做多轮分页）。
   - 纯函数体无 fd/socket/vsoa/rtdbd_conn_t（dispatch 边界 FORBIDDEN 已核：`h/conf/irt_logbuf_t*` 类型不在禁用表，`check_dispatch_boundary.py` 保持绿）。
2. **UDS op_* 改造**：4 个 op_* 函数体改调纯函数，**保留**原 fd 两阶段发送、12B 头、payload_len 校验（68/4/12/4B）、静态缓冲（`g_list_buf`/`g_log_out`）、错误码、UDS 原上限（list 1024、log 128）——UDS 字节不变、既有 `test_rtdbd_proto_v2/v3.cpp` 保持绿。find name 在纯函数入口补 `\0`（复制定长 buffer，对齐 UDS `rtdbd.c:1210`）。
3. **VSOA 内联只读分支 + listener 注册（fix P0-1）**：
   - 在 `vsoa_on_cmd` 的 `rtdbd_opcode_from_url`（`:515`）**之前的专有 URL 区**（仿 `/health` `:463-512` 的位置）加 4 个 URL 内联分支。**为什么不能放"门禁之后"**：4 URL 不在 13 表，`:514-517` 对非镜像 URL 直接 `return`，门禁 `:519-536` 之后的内联区对 4 URL **不可达**（终验新 P0）；故必须在 `:515` 前拦截。
   - **β 门禁在分支内显式执行**（fix 终验新 P0）：每个 4 URL 分支入口取 `cli_session(a,id)`，若 `cred_ok && role!=UNKNOWN && !rtdbd_authz_url_allowed(role, bare)` → 回 `RTDBD_ST_DENIED` 并 return（复用 `:524-535` 同一判据与 reply 形态，不复制逻辑可提小 helper `vsoa_gate_allowed(a,id,bare)`）；通过后才调纯函数。这样既可达、又保持 r-A=β（plc 放行、sync_admin/sync_peer 拒），不碰 `:514-517` early-return、不进 13 表、不改 authz 白名单（决策 7）。
   - **单独注册 4 个 listener**（仿 `/hello` `:677-694`、`/session/rebind` `:695-711`、`/sync/peers` `:712-729`）：`/point/find_by_name`、`/point/meta`、`/point/list`、`/logs` 各一次 `vsoa_server_add_listener(a->server, &u, vsoa_on_cmd, a)`，带 `RTDBD_VSOA_URL_PREFIX` 前缀。**漏注册则 SDK 回 status=3、分支不可达——这是 P0，实现必须逐条核对 4 个 listener 均注册成功（注册失败即 adapter 创建失败，不半实现）**。
   - 不进 13 镜像表（`VSOA_MIRROR_URLS:75-81` 不动）、不改 `rtdbd_dispatch()`（`test_c_dispatch.cpp:54-61,73-74` 反向断言锁死"不能加表"）、不新增 opcode/ABI。
4. **注入路径（fix P1-3）**：adapter 结构体（`vsoa_adapter.c:40-73`）新增 `const irt_logbuf_t* logbuf` 与 `uint32_t max_points` 字段 + setter `rtdbd_vsoa_adapter_set_logbuf/set_max_points`，由 rtdbd.c 启动时注入（`&g_logbuf`、`g_max_points`）。4 分支注入 `a->handle`/`a->conf`/`a->logbuf`/`a->max_points`。未注入时显式回 NOT_IMPLEMENTED（不糊弄）。
5. **VSOA resp 缓冲与截断（fix P0-2、P1-2/P2-2）**：
   - `a->resp[8192]`（`vsoa_adapter.c:38,72`）；截断职责统一为**纯函数按 cap 截断，handler 只传 `cap=sizeof(a->resp)`**。
   - list 阈值 `8192/76=107`、log 阈值 `8192/128=64`；超阈值请求按 cap 截断、status 0x80、`resp_len≤8192`，禁止静默丢 body（`vsoa_on_cmd:645` 对超限静默丢弃）。
   - **"两前端逐字节一致"判据限定为 `max≤阈值`（或实际条目数≤阈值）**；超阈值场景单列截断判据（VSOA 按 cap 截断、UDS 保持 1024/128 原上限），交付说明标注例外——这是 P0-2 的修正，不再要求不可能的"超阈值也一致"。
6. **VSOA 请求校验（fix P1-4/P1-5）**：4 分支显式校验 `req_len==sizeof(req)`（find 68B/meta 4B/list 12B/log 4B，对齐 UDS `rtdbd.c:1204/1245/1481/1509`），错长度回 BAD_REQUEST；find 在纯函数入口对 64B name 补 `\0`（全 0xFF 无 NUL 负例）。
7. **role 门禁 r-A=β 已裁决（fix P1-6/P2-1 + 终验新 P0）**：4 URL 分支置于 `:515` 前专有区（决策 3），**分支内显式调用 `rtdbd_authz_url_allowed` 做 β 门禁**——plc 放行（非 `/sync/*`，`rtdbd_authz.c:50-51`），sync_admin/sync_peer 回 DENIED。不得依赖 `:519-536` 的公共门禁（4 URL 在 `:516` 已 early-return，不可达）。与 u-D 单只读身份 + 28 号 d-B 双 token 聚合一致：代理用 plc 会话（`a->cli#1`）读 4 URL、sync_admin 会话（`cli#2`）读 peers。α（门禁前全角色可读，sync_peer 泄露面扩大）/γ（改 authz 白名单扩大授权面）**否决**。UDS"全角色可读"与 VSOA β 的差异在交付说明标注例外。

## 验收判据

1. **逐字节一致（限定阈值内）**：`max≤107`(list)/`≤64`(log) 且 find/meta 任意合法输入下，UDS/VSOA 产出 POD 逐字节一致（仿 `CapsPayloadIsByteIdenticalToSharedDispatch` memcmp 范式）；错误码映射一致。
2. **超阈值截断（单列）**：list max>107 / log max>64 时 VSOA 按 cap 截断、status 0x80、resp_len≤8192、无静默丢 body；UDS 保持原上限（1024/128）；例外写入交付说明。
3. listener 注册与可达性：4 URL 均有 `vsoa_server_add_listener`、注册失败即 adapter 创建失败；**且 4 URL 请求在分支内 β 门禁后可真正分派（非仅 listener 注册成功、非在 `:516` early-return 丢弃）——e2e 实发 4 URL 拿到非 status=3 响应证明可达**（终验新 P0 不复现）；不进 13 表、`rtdbd_dispatch()` 仍只 PING、`test_c_dispatch` 反向断言绿。
4. 注入与白名单：list 纯函数含 conf、非法具体分区→OK+空、ALL 哨兵全列出；logbuf/max_points 由 setter 注入、未注入回 NOT_IMPLEMENTED；`max_points` 变化输出随之变化（负例证明非偷用全局）。
5. 请求校验：4 URL 错长度回 BAD_REQUEST；find 全 0xFF name 补 NUL 不越界。
6. r-A=β：plc 会话可读 4 URL、sync_admin/sync_peer 会话被 DENIED（角色夹具扩展 token 表 + 各自 hello）。
7. Linux 零回归 + h-A/h-B 回归：OFF ALL GREEN（9 守卫）、ON ctest 全绿、`ReconnectRestoresSubscriptionsBySessionId`/IR3/h-B 用例保持绿；边界（opcode/POD/口径/发布门/B 段）零改。
