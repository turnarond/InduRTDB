## 问题与影响

目标现场设备 `192.168.30.177`（SylixOS 3.6.5 / ARM64 Cortex-A55，只读探测确认）需要能在单台上跑 InduRTDB 核心库的最小功能测试，作为平台适配第一步。当前障碍：仓内 CMake 的 SylixOS 分支只编静态库、无交叉测试入口、CI 从未交叉编译、核心库 OSAL 仅 POSIX 逐行拷贝从未上板验证（21 号 §2）。不做则 SylixOS 适配停在纸面，q-B/C/D 裁决无法落地，后续 G2（rtdbd 主路径）无从起步。

影响范围：① 新增 SylixOS 交叉测试 harness 源码（`tests/sylixos/` 下新增 C 文件，Linux 侧不构建）；② CMake 增一个 SylixOS 条件 target 产出 harness 可执行（不改核心库 `indurtdb` 的任何源）；③ 设备侧临时目录。不影响 Linux 侧任何产物/行为、不改共享内存布局/公开 API/协议 opcode。

## 设计决策

1. **工具链**（q-C 裁决）：采用 `/home/yanchaodong/work/acoinfo/eao_framework/script/sylixos_build/sylixos.toolchain.cmake`（与 `ecsm/backend` 版 md5 一致；接受 `CMAKE_SYLIXOS_BASE_PATH` + `CMAKE_SYLIXOS_PLATFORM`，从 base 的 `config.mk`/`platforms.mk` 自动解析 `TOOLCHAIN_PREFIX`/`CPU_TYPE`，自带 base 存在性校验）。**不采用** `ko_middleware/buildutils` 版——其 `TOOLCHAIN_PREFIX`/`SYLIXOS_BASE_PATH`/`CPU_TYPE` 均未定义、`CMAKE_C_COMPILER_WORKS 1` 会跳过检测退回宿主 gcc，不可复跑。本仓**不复制** vendor 文件入库。
2. **可复跑命令**（完整，无占位符）：
   ```
   BASE=/home/yanchaodong/work/acoinfo/base/base_ecs_multi/base
   TC=/home/yanchaodong/work/acoinfo/eao_framework/script/sylixos_build/sylixos.toolchain.cmake
   cmake -S . -B build-sylixos -DCMAKE_TOOLCHAIN_FILE="$TC" \
         -DCMAKE_SYLIXOS_BASE_PATH="$BASE" -DCMAKE_SYLIXOS_PLATFORM=ARM64_A55
   cmake --build build-sylixos --target indurtdb sylixos_smoke
   ```
   `platforms.mk:38` 定义 `ARM64_A55 := aarch64-sylixos-elf- cortex-a55`，与设备 Cortex-A55 匹配；`$BASE/{config.mk,libsylixos}` 均存在（已核）。
3. **新增源码与构建入口**（P0-2 澄清）：新增 `tests/sylixos/sylixos_smoke.c`（基于 `examples/basic_example.c` 的点位读写范式扩展：时间/OSAL 映射 + 读写 + 双进程 owner 语义 + 崩溃恢复探测），并在 CMake 加 SylixOS 条件 target `sylixos_smoke`（链核心库；instance id 由命令行传入，唯一化）。`basic_example.c` 因实例名固定且覆盖不足，不直接复用（仅作范式来源）。tests 既有 GTest 用例因依赖 CXX/GTest 不交叉复用。
4. **共享内存 ABI 验证**（21 号 §3.6）：交叉编译期确认 `src/internal/irt_types.h:59-105` 与 `protocol.h` 静态断言全过。已核：全为 packed + 定长类型、无 `size_t`/指针/`long`，ARM64 64 位下 sizeof/offsetof 与 x86_64 一致，**断言不会失败**；仍以编译实跑为准。
5. **设备侧操作边界**（P1-4 修正）：`/root` 可写、ftp/telnet 可用**是待验证假设，不是既定事实**——开工第一步先只读+写入探针验证（写一个临时文件再删），FAIL 即停并报告。通过后才 ftp 上传到 `/root/indurtdb_g0g1/`，telnet 执行，唯一 instance id；结束清理段与上传文件，**不碰生产数据、不改系统配置、不部署 rtdbd 守护**。
6. **明确证据规则**（P2-2）：PASS 必须由 harness 内断言 + `exit 0` 产生，纯字符串回显不算证据；每类用例记录断言输出与退出码。
7. **编译风险面**（P1-2）：全局 `-Wall -Wextra -Werror`（`CMakeLists.txt:13`）在 SylixOS 分支同样继承；`<time.h>`/`CLOCK_MONOTONIC`、`<sys/mman.h>`/`shm_open`、`signal.h`/`kill` 的隐式声明在 `-Werror` 下直接失败，头文件路径依赖 `$BASE/libsylixos`（已核存在）。任一编译失败如实记录、不绕过 `-Werror`。
8. **q-B 契约**：UDS 写裁撤实现属 G2，本卡不触碰；不改 Linux 侧 UDS 行为/opcode/ABI；监控台 UDS 链路限制标注为已知。

备选与不取理由：① `ko_middleware` 版 toolchain（变量未定义、不可复跑）；② 复制 toolchain 入库（vendor 维护负担、违反外部只读）；③ 复用 `basic_example.c` 直接跑（实例名固定、覆盖不足）；④ 设备装编译器（设备上无、违反最小变更）。
