## 问题与影响

u-0=设备侧代理：外部 PC 直连 rtdbd 在 hello 阶段被 `rtdbd_authz.c:19-26` loopback 约束 DENIED。设备上跑本地代理（来源 127/8、hello 合规），对外部 PC 暴露 VSOA server、自身 2 条 loopback client 连 rtdbd，把"外部来源"转为"设备本地来源"，不改核心鉴权模型。本卡实现**设备侧代理一跳**；外部 PC 瘦网关（d-F）另立。

## 设计决策

> v2 返工：fix 首轮 2 P0 + 9 P1，见各决策标注。

1. **新组件**（`rtdbd/src/agent/rtdbd_device_agent.c/.h`）：`rtdbd_device_agent_t` 持 VSOA server（对外）+ 2 条 VSOA client（#1 plc、#2 sync_admin）+ 单线程 poll + pending 表 + 延迟队列 + RBE 适配层。不复用 vsoa_adapter（职责不同）。**CMake（fix P2）**：顶层 `CMakeLists.txt` 新增条件块（Linux `INDURTDB_BUILD_AGENT=ON` 默认 / SylixOS 显式 ON），**不照抄** `sylixos_vsoa_e2e`（其仅 SylixOS、:179-188）；源文件在 `rtdbd/src/agent/`、target 注册顶层，include 与链接显式配置。
2. **对外 server（d-A/d-C）**：`--agent-bind <ip>` 指定管理网卡、拒绝 `0.0.0.0`；`--agent-port 0` 自动 + 独立 `RTDBD_AGENT_PORT_FILE`（模式仿 `vsoa_dualstack_example.c:190-203` 回读）；`vsoa_server_passwd` 连接级准入（d-C）。**口令经文件/环境变量注入，不经命令行（fix P2 passwd 泄漏）**；不传口令 fail-closed 拒绝启动（联调传测试口令即可，不放宽生产口径）。**符号门禁（fix P1-3）**：`scripts/check_vsoa_sdk.py` 的 `REQUIRED_SYMBOLS` 增加 `vsoa_server_passwd` 并在 SylixOS 交叉库做符号探测，缺项构建期 FATAL（不静默降级）。
3. **双 token loopback client（d-B，fix P1-4）**：client#1 plc 读 4 只读 URL + 13 镜像只读子集 + **订阅管理 URL**；client#2 sync_admin 仅 `/sync/peers/get`。**token 来源定死**：rtdbd 侧须用 `--vsoa-token-file` 预置 `tok-agent-ro`(plc) 与 `tok-agent-admin`(sync_admin) 两个 token（`rtdbd.c:2051`、`vsoa_adapter.h:156-158`），代理用这两个 token 分别 hello；缺 token 则代理启动即报明确错误（不静默 DENIED）。rtdbd 不新增 token 机制，复用既有文件加载。
4. **并发 pending 表（fix P0-1、P1-1、P1-2）**：server 回调收到请求 → **拷贝** `vsoa_hdr`/`url`/`payload` 到自有缓冲（SDK 回调指针返回即失效，`vsoa_server.h:115-119`）→ `ntohl(hdr->seqno)/ntohs(hdr->tunid)` 转主机序（`vsoa_adapter.c:783-795` 教训：不转第 2 个请求起超时）→ 登记 `pending_t{cli_id, seq, tun, kind, copied_body, deadline}` 到**定长 16 项 pending 表**（键=cli_id+seq+tun；超时 3s 清理）→ 异步 `vsoa_client_call` → client rpc 回调按 cli_id+seq+tun **精确查表** → `vsoa_server_cli_reply` 回写后释放表项。并发两请求互不覆盖（判据 1/5 加 RED→GREEN）。在途满 16 → 立即回 `RTDBD_ST_INTERNAL`（fix P1-5）。
5. **URL 白名单与订阅入口（fix P0-2）**：透传到上游的 URL 清单 = 4 只读 URL（`/point/find_by_name|meta|list`、`/logs` → client#1）+ **13 镜像只读子集**（`/ping,/point/get,/point/batch_read,/caps,/health,/subscription/add,/subscription/remove,/subscription/set` → client#1；注意 `/subscription/*` 在 13 表内、是合法透传）+ `/sync/peers/get`（→ client#2）。**`/subscription/add|remove|set` 是合法入口**：代理从请求 POD 提取 point_id 维护 per-listener 订阅集（见决策 6），同时原样透传给上游。写类（`/point/write|batch_write,create/delete/rename,set_meta`）、`/sync/peers/set`（u-C）、未注册 URL 回 NOT_IMPLEMENTED/DENIED。
6. **listener 标识与 RBE 适配（fix P0-2、P1-6、P2 首值缓存）**：**listener 标识 = 代理对外 server 的 `vsoa_cli_id_t`**（每个外部瘦网关连接即一个逻辑 listener；u-E≤16 归属为**代理 server 并发 cli 上限 16**，留余量给上游会话，第 17 个连接拒绝）。代理维护 per-cli_id 订阅集 + per-point 引用计数 + 首值缓存（缓存对象为 `rtdbd_notify_t` POD 原样 `protocol.h:170-175`，容量上界 = RTDBD_SUB_MAX=10000 条有界 LRU、满则淘汰最旧并计 evicted——吸收 28 号终验建议）。首个 listener 订阅点 P → 上游 `/subscription/add(P)`；最后 listener 退订 → 上游 remove；中间 listener 只改本地引用计数。`on_datagram` 收上游 NOTIFY → 按 per-cli_id 订阅集二次过滤 → `vsoa_server_cli_datagram` 扇出。新 listener 订阅已消耗 RBE 的点 → 主动推缓存首值（模拟 rtdbd per-session"重订阅首值必发"），不等下一次变化。不做二次 RBE 死区判定（避免与 rtdbd 双重抑制）。
7. **失败/超时/背压/重连（d-D，fix P1-7、P1-9）**：RPC 超时 3s（固定）、在途 16、满回 INTERNAL；NOTIFY 慢消费者 per-cli 有界队列（满即丢计 dropped）。**代理侧诊断计数出口**：`rtdbd_device_agent_stats_t{replied, dropped, evicted, pending_full, upstream_reconnect}` + getter `rtdbd_device_agent_get_stats()`（对齐 `vsoa_adapter.h:75` 的 notify_counters 出口），e2e 断言可读。**上游重连**：rtdbd 断连即释放会话（`vsoa_adapter.c:211-219`），代理检测到重连后对 client#1 重新 `/subscription/add` 当前所有活跃点（引用计数>0 的点集），并复用 h-A `/session/rebind`（`vsoa_adapter.h:110-117`）恢复订阅快照——确保 NOTIFY 不中断。
8. **启动与生命周期**：独立可执行 `rtdbd-device-agent`（Linux + SylixOS 双构建）；先 rtdbd 后代理（d-D）；代理崩溃/掉线由外部运维重启（SylixOS 无 systemd，G2 先例）；不碰设备、不改持久化数据。
9. **测试**：
   - Linux loopback 真 e2e（ON-only）：spike 三进程拓扑正式化——mock 外部 client → 代理对外 server → 代理 loopback client → **真实 rtdbd**（fork 真实 rtdbd 进程、预置 `tok-agent-ro`/`tok-agent-admin` token 文件 + 写点触发 NOTIFY）。断言：4 只读 URL + peers get 透传字节一致、**两并发请求回写正确不串台**（P0-1）、`/subscription/add` 可达且订阅集生效、RBE 三例（A/B 订阅同点/A 退订 B 仍订阅/B 新订阅收首值）、peers set 拒绝、无口令连接拒绝、3s 超时、统计计数出口可读。
   - 纯逻辑单测（OFF 可跑）：RBE 适配的 per-point 引用计数 + 首值缓存 + 二次扇出（仿 test_hB_health，无需真实 VSOA）。
   - Linux 零回归：OFF ALL GREEN、ON ctest 全绿、h-A/h-B/h-C 前置回归绿。
10. **边界**：不改 UDS opcode/ABI/对外口径/发布门 FAIL 8/B 段数字；不新增 rtdbd 业务能力；代理是传输中转、不改核心鉴权模型（13 号 §8.3-4）；不打 tag/合 main。

## 验收判据

1. **双角色 + 并发**：同进程 server+2 client 单 poll 可用（spike + e2e 复验）；**两并发请求回写正确、pending 不覆盖、无串台/丢 reply**（RED→GREEN）；回调指针已拷贝、seqno/tunid 主机序（第 2 请求不超时）。
2. **透传与鉴权**：4 只读 URL + 13 镜像只读子集 + `/sync/peers/get` 经代理透传成功、payload/status 逐字节一致；上游来源 127/8；`tok-agent-ro`/`tok-agent-admin` 预置；无口令连接被拒；`/sync/peers/set` 与写类 URL 被拒（u-C）。
3. **listener 与 RBE**：listener=cli_id、并发上限 16（第 17 拒）；per-point 引用计数 + 首值缓存（有界 LRU、evicted 计数）+ 二次扇出三例可证伪（A/B 三例）、无串扰、无双重抑制；缓存对象为 `rtdbd_notify_t` POD 原样。
4. **失败/背压/重连**：3s 超时回 INTERNAL、在途满 16 回 INTERNAL、NOTIFY 满即丢且 dropped 可读；d-A 拒绝 `0.0.0.0`、独立 port-file；上游重连后活跃点重新订阅/rebind、NOTIFY 不中断。
5. RED→GREEN：纯逻辑与 e2e 新断言先 RED 后 GREEN；负例（并发串台、订阅入口、peers set、无口令、重连丢订阅）可证伪。
6. Linux 零回归 + h-A/h-B/h-C 前置回归：OFF ALL GREEN（9 守卫）、ON ctest 全绿；不改 opcode/ABI/对外口径/发布门 FAIL 8/B 段数字；`vsoa_server_passwd` 符号门禁 + 交叉库探测通过。
7. 独立评审通过（fresh context + 源码行号回核 + spike 结论 + 并发/RBE/字节序可证伪核对）。
