## 问题与影响

v3.12 M3.3 的 VSOA 前端 `vsoa_notify_dispatch`（**HEAD `ac4b200` 改动前**位于 `rtdbd/src/vsoa/vsoa_adapter.c:196-234`：`:196` 函数签名～`:234` 闭合；本切片门控接线 + 第二签 M-2 同源不变量注释后，该函数位于当前工作区 `:225-263`；行号口径按 HEAD 与现状分别标注，且以函数名为准，避免行号随注释增删漂移而误读）已实现「逐连接定向 NOTIFY」的门控循环（空槽 / sync_peer / 未订阅 / RBE 死区 / 定向发送），但这四个门控分支的各个去向**没有任何可观测计数**：运维与 IR 验收无法区分「因 RBE 抑制而未发」与「因未订阅而未发」，也无法证明「非订阅者 / sync_peer 一次都没有收到 NOTIFY」。doc 13 §8.3-5 要求 NOTIFY 定向、禁用 publish、防回环，但缺少诊断量来证伪「回环泄露」与「门控误判」。

本切片（Task 4）只做**计数暴露**：新增 4 个诊断计数（`rbe_gate_hits` / `rbe_gate_misses` / `snapshot_done_caps_only` / `peer_notify_leak`）及其可读出口、纯逻辑 record 函数与发送点护栏，并把门控循环接进计数。**不改**共享内存布局、公开 C API、协议 opcode、错误码契约，**不新增**线程 / 动态内存 / 原子操作。不做的后果：切片 5（IR5 NOTIFY 定向）与设备级 IR 无判据可读，门控回归无法被 ctest 拦住。

影响面：`rtdbd/src/session/rtdbd_session.{h,c}`（纯逻辑类型与函数）、`rtdbd/src/vsoa/vsoa_adapter.{h,c}`（实例字段、门控接线、getter）、`tests/integration/IR4_RbeCounters.cpp` + `tests/integration/CMakeLists.txt`（新增 OFF/ON 均编译的纯逻辑用例）。`build/`=OFF 与 `build-vsoa/`=ON 两种构建均须零警告。

## 设计决策

- **计数落点（Task 4.1 / 4.3）**：类型 `rtdbd_notify_counters_t`（4 个 `uint64_t` 纯标量）、门控枚举 / 回调 typedef、纯函数放 `rtdbd/src/session/rtdbd_session.{h,c}`；实例挂 `struct rtdbd_vsoa_adapter`（adapter 全局聚合，`calloc` 自动零初始化）；getter `rtdbd_vsoa_adapter_notify_counters()` 从 `vsoa_adapter.h` 暴露。理由：① 4 个计数是「整个 VSOA 前端的投递诊断量」，非 per-session 属性，放 adapter 全局使连接断开不丢历史、getter 无需遍历 32 槽；② **不放进 `rtdbd_session_t`**，故不改会话布局 / 共享内存布局（更安全）；③ 门控 + 计数抽成传输无关纯函数后，OFF `build/` 可直接测 —— OFF 不编译 `vsoa_adapter.c`（依赖 VSOA SDK）且 `vsoa_notify_dispatch` 是 `static`，这是 Task 4.1 能在 OFF 跑绿的唯一可行路径；④ 类型定义在 session 层满足 Task 4.3「挂计数结构」且受传输无关约束保护（纯标量 + 函数指针，无 fd/socket/poll/vsoa 类型）。
- **RBE 判定副作用、顺序不可提前**：`rtdbd_dispatch_notify_rbe`（`rtdbd/src/dispatch/rtdbd_dispatch.h:136`）内部调 `rtdbd_subtab_decide` 推进 RBE 状态（有副作用），UDS 侧 `rtdbd/src/rtdbd.c:637` 亦是「先过滤订阅再调 RBE」。纯函数 `rtdbd_session_notify_gate` 严格保持「空槽 → sync_peer → 未订阅 → 才调 RBE」的顺序，SKIP 类在返回前**绝不**触碰 RBE 回调；否则未订阅 / sync_peer 连接会消耗 RBE 状态（回归）。测试用 `RbeCallbackNotInvokedForSkipped` 断言 SKIP 类 `calls==0` 锁住该顺序。
- **`peer_notify_leak` 语义**：= 「实际发给非订阅者 / sync_peer 的次数」，正常实现**恒 0**（判据 `==0`），不是「被遍历到的未订阅连接数」（那样必然 >0）。用发送点护栏 `rtdbd_session_notify_deliver_guard` 使其可观测：HIT 会话若实为 sync_peer / 未订阅则记一次泄露并拒发。
- **单线程普通 `++`（doc 13 §8.3-3）**：单线程统一 poll、零线程零锁；与 `rtdbd_session.c:198/209/231` 既有 `dropped++`（`:198`）/ `enqueued++`（`:209`）/ `executed++`（`:231`）同范式，用普通 `++`，**不引入原子操作**（全库 `__atomic_` / `__sync_` / stdatomic 零命中）。注：`:205` 是 `a->seq = q->enqueued` 赋值、非计数自增，不计入本范式引用（第二签 M-8 更正）。
- **`snapshot_done_caps_only` 生产路径留白（YAGNI）**：doc 13 §7.2 / §8.3-5 规定 SNAPSHOT_DONE 仅对 `caps_negotiated` 会话定向发，但 VSOA 侧 `/snapshot_done` 只在 `VSOA_MIRROR_URLS`（`vsoa_adapter.c:72`）注册，`vsoa_on_cmd`（HEAD `ac4b200` 版 :286-491；门控接线后当前工作区 :315 起，以函数名为准）**没有**对应 opcode 分支（会落到 `a->handler.handle`），即 VSOA 侧根本没有 SNAPSHOT_DONE 定向路径。本切片只暴露「恒 0 的可读出口 + 纯逻辑 record 函数」，**不顺带实现 SNAPSHOT_DONE 定向**（属切片 5 / IR1），并在「留白」节如实写明生产路径未接线、不假绿声称已验证。
- **测试落点（Task 4.1 RED 形态）**：新 API 未实现时，C++ 纯逻辑测试 `IR4_RbeCounters.cpp` 直接**编译 / 链接失败**，而非断言失败 —— 该 RED 形态经 controller 裁决接受，变更卡如实记录为编译失败。
- **不触碰**：共享内存布局、22 个 UDS opcode / 错误码契约、`include/indurtdb/indurtdb.h` 公开 API、`VERSION` / CMake `project(VERSION)` / 版本宏、B 段 7 项 `fields`、设备级 IR ctest 名、T1–T5 数字；库代码零 malloc/free（本次不新增）。

## 验收判据

- **4 个计数都有可读出口**：`rtdbd_vsoa_adapter_notify_counters(const rtdbd_vsoa_adapter_t *)` 返回 `rtdbd_notify_counters_t` 快照（NULL 输入返回全 0）——该 getter 本身**仅代码审查确认、未实跑**（全仓 `tests/` 零引用、OFF 不编译 `vsoa_adapter.c`、59/59 无用例执行它；ON 侧冒烟属切片 5 待办，见「留白」节）；纯逻辑 `rtdbd_notify_counters_snapshot` / `_reset` / `_record_snapshot_done_caps_only` 由用例覆盖、可独立取证（首轮 9 用例，评审修复后 15 用例，见 TDD 证据 §6）。其中 `snapshot_done_caps_only` 的 VSOA 生产路径未接线、当前恒 0、当前无生产调用点（属切片 5/IR1）。
- **4 个门控分支都计到**：SKIP（空槽 / sync_peer / 未订阅：计数不变且不触发 RBE）、MISS（`rbe_gate_misses++`）、HIT（`rbe_gate_hits++`）、护栏（`peer_notify_leak++` 且拒发）。
- **副作用顺序**：`RbeCallbackNotInvokedForSkipped` 断言 SKIP 类 RBE 回调 `calls==0`；`SyncPeerSkipsEvenIfSubscribed` 断言 role=SYNC_PEER + 已订阅 + rbe=true 仍 SKIP、3 个计数全 0 且 RBE 回调未调用（复验同步：M-3 修复后该用例不再含恒真 leak 断言）。
- **恒 0 出口**：由 `GateHitChainsToGuardWithNoLeak`（`IR4_RbeCounters.cpp:217-232`）在**串联 guard 之后**断言 `peer_notify_leak==0`（gate 本身从不写 leak，旧 `UnsubscribedSkipsAndNoLeak` 里的 leak 断言属恒真弱断言，按第二签 M-3 已移除）；`ResetYieldsZero` 断言 reset 后 4 项全 0；`snapshot_done_caps_only` 默认 0（生产路径留白）。
- **纯逻辑可测**：`SnapshotRoundtrip`（逐字段拷贝）、`RecordSnapshotDoneCapsOnly`（+1）、`DeliverGuardCatchesLeak`（非法会话 false + leak==1，合法 true + leak 不变）。
- **工程**：C11 `-Wall -Wextra -Werror` 零警告；`cmake -S . -B build`（OFF）与 `cmake -S . -B build-vsoa`（ON，`vsoa_adapter.c` 三个 TU 零警告）均编译；`ctest -R IR4_RbeCounters --output-on-failure` PASS；ON 全量 `ctest --test-dir build-vsoa --output-on-failure` 不回归；`bash scripts/check_all.sh`（OFF full，禁 `--quick`）全绿。
