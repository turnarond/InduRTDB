## 设计决策

> v2 返工：fix 首轮 3 P0 + 8 P1，见各决策标注。

1. **审计身份走纯内存环形通道（fix P0-1）**：新增 `hB_audit_sid.c/.h`（独立 TU），定义 `hB_audit_sid_entry_t{uint64 ts_ns; uint32 uid; uint32 partition; uint32 point_id; char service_id[64]}` 与定长环形 `hB_audit_sid_ring_t`（容量 256，与审计条目同量级），**纯内存写入、零 I/O、零阻塞**。生产回调只做 `irt_audit_record`（纯内存，`audit.c:11-27`）+ `hB_audit_sid_ring_push`（纯内存）两件事，**不碰 logbuf**（`logbuf.c:40-43` fprintf+fflush 阻塞）。
2. **生产回调/ctx 提取到可测 TU（fix P0-3）**：`hB_audit_adapter.c/.h` 导出 `void hB_audit_callback(void* ctx, uint32 pid, uint32 uid, uint32 partition, uint32 point_id, uint64 ts_ns, const char* service_id)` 与 `hB_audit_ctx_t{irt_audit_t* audit; hB_audit_sid_ring_t* sid_ring}`。生产 `rtdbd.c` 静态持 ctx（audit 是 `:2480` 栈局部，但其地址在 main 生命周期内有效——ctx 在 `set_audit` 前于 main 栈上初始化、main 全程不返回），`rtdbd.c:2708-2709` 注入 `set_audit(g_vsoa, hB_audit_callback, &hb_ctx)`。**单测直接 include `hB_audit_adapter.h` 测导出的生产回调**（非测试侧仿制品），覆盖参数顺序/ts 补位/service_id 落环。
3. **回调语义**：`ts_ns=0`（adapter :628-632 传 0）→ 回调内用 `now_ns()`（CLOCK_MONOTONIC，`stats.c:16-20`，与审计条目 ts 同源）补；**参数顺序** `irt_audit_record(ctx->audit, pid, uid, partition, point_id, now_ns())`（`audit.h:20-21`，partition 在 point_id 前）；service_id 写 sid 环（与审计条目按 uid/partition/point_id + 邻近 ts 关联，不依赖不同时钟基准）。pid 恒 0（hello 不赋）如实记录；deny 不触发（adapter :627 仅 `st==RTDBD_ST_OK` 才调，单测不含 deny 用例，由该门控保证）。
4. **health 共享纯函数（fix P0-2）**：`rtdbd_dispatch.c/.h` 新增 **真纯函数** `rtdbd_dispatch_health_fill(int health, const rtdbd_health_counts_t* c, uint32_t n_conns, bool conn_table_ok, rtdbd_health_t* out)`——health、8 个计数（含 `c->uptime_ns`）、n_conns、连接检查**全部由调用方注入**，函数体内无 now_ns、无 g_stats 写、无 self_check。`rtdbd_health_counts_t`（8 个 uint64 计数）定义在**内部头 `rtdbd_dispatch.h`**（不进 protocol.h，不碰冻结结构/静态断言）。填 72B POD（protocol.h:363-376 冻结），conn_table_ok=false → health 抬 UNHEALTHY。**判据改为"给定完全相同输入，两前端 72B 逐字节一致"**（可证伪），不再声称跨时刻真实采样一致。
5. **UDS op_health 改造**：`rtdbd.c:1536-1565` 调 `rtdbd_self_check_core(cx->h)`（得 health+写 g_stats.uptime_ns，读回 `g_stats.uptime_ns` 作 uptime 输入）+ `conn_table_check(cx->conns, g_max_clients)`（`:732-740`，连接表完整性布尔）+ 遍历 n_conns + 构造 counts → 调纯函数 → 72B 输出逐字节不变、免鉴权/空负载校验语义不变。
6. **VSOA /health 专有免鉴权分支（fix P1 门禁）**：在 `vsoa_on_cmd` 的 `rtdbd_opcode_from_url` **之前**（仿 hello/peers/:407-442）内联处理 `bare=="/health"`——避免经过 `:467-484` 的 role→URL 门禁（UDS health 免鉴权，两前端一致）。校验 `req_len==0`（对齐 UDS 空负载校验 `:1527-1533`，带负载回 BAD_REQUEST）。输入注入：health/uptime 取 `rtdbd_self_check_core(a->handle)`/`g_stats.uptime_ns`；n_conns 取 `a->cli[]` 活跃数；**t-E VSOA 等价连接检查**对齐 UDS `conn_table_check` 语义——不仅查 used 会话 nsubs<=RTDBD_SUB_MAX，还查**未使用槽是否残留订阅**（`!used && session.nsubs!=0` → 异常，对齐 `conn_table_check:738`），不引入 UDS 没有的 cred_ok 判据（避免误伤 allow_unauthenticated 联调）。response 72B POD 直放、status=0x80+OK。**不改 `rtdbd_dispatch()` 只 PING 现状**（health 走内联、不进 opcode 表）。
7. **两前端一致边界**：仅"相同输入"逐字节一致（纯函数保证）；真实运行态 uptime 因采样时刻不同必然有差异——判据据此重述（判据 3/7），不声称真实采样逐字节相同（这是评审 P0-2 的修正）。
8. **测试**：
   - 审计：新增 `tests/integration/test_hB_audit.cpp`（纯逻辑、默认构建），直接 include 生产 `hB_audit_adapter.h`：构造 `irt_audit_t`+sid 环+ctx → 调生产 `hB_audit_callback` → `irt_audit_dump` 读回 + sid 环读回，断言成功写增条数、pid=0/uid/partition/point_id/ts>0、service_id 落环、参数**相异值**断言（partition≠point_id 防写反）、NullCtx noop；deny 不审计由 adapter `st==OK` 门控保证（非本单测覆盖）。
   - health：新增纯逻辑单测 `test_hB_health.cpp`——固定一组输入（health/uptime/counts/n_conns/conn_table_ok）调 `rtdbd_dispatch_health_fill`，断言 72B 与**预计算期望字节**逐字段一致；conn_table_ok=false → health=UNHEALTHY；UDS/VSOA 两调用点在相同注入输入下产出字节一致（用注入桩，非真实采样）。VSOA `/health` e2e 复用 `test_vsoa_e2e.cpp`（call_rpc helper 提为文件内全局或在该 TEST 内扩例）：发空 payload、status=0x80、data_len=72、逐字段合理（health∈{0,1,2}、n_conns>=1）。UDS `test_rtdbd_health.cpp` 保持绿。
   - **h-A 回归点名**：`test_vsoa_e2e.cpp` 的 `ReconnectRestoresSubscriptionsBySessionId`（session_id/rebind/snapshot）、IR3 快照测必须保持绿。
9. **边界/注释**：不改 24B `rtdbd_audit_entry_t`（无 service_id）、不新增 opcode、`rtdbd_dispatch()` 只 PING 现状不变；service_id 64B 在 sid 环条目（≈84B）内完整存（容量 256 条，无 logbuf 116B msg 截断问题）。
