## 设计决策

> v2 返工：修 1 P0（P10 恒真假绿）+ 4 P1；字段名隔离、两独立摘要源、P10 measured 归 S5。

1. **裁决键归一化**（fix P1-1）：新增二段比较 `rtdbd_epoch_key_compare_epoch_node(a,b)`（只比 epoch → node_id，boot_id 第三级不参与；13 号:256 + 24 号:87）。**精确契约**：裁决采用**全量候选、不调用 `is_stale` 过滤**（`rtdbd_epoch.c:23-33` 的 `is_stale(e)=e<current` 只过滤低于本进程水位的项——理由不是"误删未来帧"，而是本机水位因本地写偏高时可能误删合法低-epoch peer 候选）；胜者选出后 `rtdbd_epoch_advance_to(winner.epoch)` 仅单向推进本机水位（非裁决依据）。
2. **纯逻辑选源模块** `rtdbd/src/cluster/rtdbd_select_source.{c,h}`（无 VSOA/SDK 依赖，独立 TU）：
   - 输入 `rtdbd_source_candidate_t{ uint64_t epoch; char node_id[32]; uint64_t boot_id /* 仅审计,不参与比较 */; uint64_t struct_hash, value_digest; uint32_t n_points; uint64_t offset /* 去重键第三元 */; bool valid; }` 数组 + count。
   - `rtdbd_select_source(const rtdbd_source_candidate_t *cands, uint32_t n, rtdbd_source_result_t *out)`：过滤 `valid=false`；按归一化键取最大；输出 `winner_epoch/winner_node_id`、`winner_digest_hex`（胜者 `rtdbd_digest_t.hex` 格式 `fnv1a64-v1:<struct>:<value>:<n>`）、`selected_source_digest_hex`（**语义 = 本节点按同一算法对本机点集的摘要**，由调用方注入 `local_digest_hex`；用于 S5 现场比对"本机终态 vs 选中源"，**本卡逻辑单测中它等于 winner_digest_hex 仅为构造输入、不是恒等断言**）、`valid_candidate_count`（uint32，参与选源的 valid 数，**不叫 nodes_converged**）、candidate_count/duplicate_dropped/truncated、`evidence_kind:"logic-only"`。
   - **字段名隔离硬约束**：禁止在 S3 产物中出现 `nodes_converged`/`terminal_hash`/`dict_max_snapshot_match` 三个 P10 字段名（grep 守卫）；S5 现场工具须独立采集这三字段并证明 `terminal_hash==dict_max_snapshot_match`（两个独立源），S3 的 `winner_digest_hex` 仅作审计辅助。
   - `rtdbd_select_source_json()` 输出 JSON：winner_epoch/winner_node_id/winner_digest_hex/selected_source_digest_hex/valid_candidate_count/candidate_count/duplicate_dropped/truncated/evidence_kind（**无 P10 字段名**）。
3. **有界去重候选累加器** `rtdbd/src/cluster/rtdbd_candidate_set.{c,h}`：键 `(epoch, offset, node_id)` 与 `rtdbd_source_candidate_t` 字段对齐（fix P1-2）；定长 64、重复计数 `duplicate_dropped`、满额 `truncated++`；`rtdbd_candidate_set_add()/snapshot()` 只整理选源候选并给计数证据——**不写 shm、不"重放到点位库"**（S2 delta 是扫描游标非 WAL，仓库无可重放点值流）。
4. **adapter 只读 accessor**（fix P1-3）：`rtdbd_vsoa_adapter_collect_source_candidates(a, out[], cap, const char *local_node_id, const rtdbd_digest_t *local_digest)` 把 `cli[].sync_state.valid` 投影为候选（epoch/digest/node_id 来自 S2 hello），并**显式注入本机候选**（local_node_id + local_digest，调用方必填；缺本机候选时 `winner` 可能非最大，accessor 返回 false 拒绝裁决）。`vsoa_adapter.h` 引入 `cluster/rtdbd_select_source.h`（单向依赖，无环；复跑 `check_arch_layers.py`）。不改 sync_state 生命周期（S2 on_cli 已清）。
5. **契约定稿**（其余 4 项）：① reachable = `cli[].sync_state.valid` 入站集 + 本机显式注入（不叠加成员表在线确认——S2 已校验来源）；② P10 字段**不在 S3 产出**（S5 独立采集）；③ backlog 命名 = "有界去重候选集（不应用）"；④ 证据级别 = unit 纯逻辑单测（S2 两进程 e2e 只有一个候选，不能改名充 IR7——`docs/08-验证记录/v3.12-M3-IR证据.md:853-856` 警告语义不等价），IR7 6 节点 fixture 留 S5。补引 13 号:198 "字典序只用于选源与审计排序、不做逐写合并"（fix P1-4）。开工前在 `docs/plans/2026-11-25-同步语义实施设计.md` §5 留痕本卡"纯逻辑选源"范围与用户裁决（fix P1-5）。

## 验收判据

1. 归一化比较器：同 epoch 不同 node_id → 字典序大者胜；不同 epoch → 大 epoch 胜；boot_id 反转不改变胜者（可证伪）。
2. 选源输出：valid 过滤正确；`winner_digest_hex` 为胜者摘要、`selected_source_digest_hex` 为注入的本机摘要（不同输入可不同，**非恒等式**）；`valid_candidate_count` 为参与选源的 valid 数（非收敛数）；winner 元数据齐全；JSON 含 `evidence_kind:"logic-only"` 且**无 P10 字段名**。
3. candidate_set：重复 `(epoch,offset,node_id)` 只入一次且 `duplicate_dropped` 正确；容量 64 满额 `truncated` 正确；重复项不改变选源胜者；**不写 shm**（代码可查无 indurtdb write 调用）。
4. accessor：显式注入本机候选（缺则 false 拒绝）；从 `cli[].sync_state.valid` 投影 peer 候选；断链后候选消失（S2 on_cli 已清；单测可构造 fake 验证投影逻辑）；`check_arch_layers.py` 绿。
5. RED→GREEN；Linux 零回归：OFF ALL GREEN（9 守卫）、ON ctest 全绿、S1/S2/阶段一 9 名/h-A/h-B/h-C 前置回归绿；dispatch 边界 ok；**P10 字段名隔离 grep 零命中**。
6. 独立评审通过（fresh context + 源码行号回核 + "逻辑选源≠数据收敛"边界与 P10 字段隔离核对）。
