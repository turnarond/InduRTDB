# v3.10 单站规模化实现计划

> 设计依据：`docs/superpowers/specs/2026-10-20-v3.10-single-station-scale-design.md`（已确认）
> 日期：2026-10-21
> 状态：**待批准**。本计划批准前不写产品代码。
> 目标场景：单站 ISCS/BAS，2 万点位、1 s 周期、50 客户端、每客户端只订阅当前画面可见 ≤500 点。

## 1. 目标与非目标

### 目标

1. `rtdbd` 增加连接级批量订阅 `SET_SUBS`，翻页时一次替换订阅集并回送当前值快照。
2. 订阅成员判断与 RBE 门控合并为一张 O(1) 开放寻址表，消除每写每连接两次线性扫描。
3. 每连接订阅上限 1024、出站队列 1024；50 客户端 × 500 订阅的翻页不丢帧。
4. 点位 YAML 支持 `timeout_ms`；`rtdbd` 每秒扫描一次，只推送 `Good → Timeout` 跃迁。
5. `NOTIFY.reserved[0]` 携带 quality；新监控台直接显示推送质量。
6. 监控台改为服务端分页 + 每个浏览器 WebSocket 独占 UDS 通知连接；旧 `rtdbd` 自动降级。
7. 新增 2 万点 / 50 客户端 / 10 分钟负载脚本与升级文档。

### 非目标

- 不改共享内存布局（段版本 3、点位 128 B、元数据 32 B）。
- 不新增公开 API（保持 117 = 62 + 55）。
- 不做多站聚合、历史库、跨站订阅。
- 不改造 `rtdbd` 为多线程；仍是单线程 `poll` 事件循环。
- 不扩展 `SET_META` 协议；`timeout_ms` 只从 YAML 进入。

**文件**

**接口**

```c
#define RTDBD_SUBTAB_CAP 2048u   /* roundup_pow2(2 * 1024) */

typedef struct {
    uint32_t point_id;
    double   last_reported;
    uint8_t  valid;   /* 0 = 首值未发 */
    uint8_t  used;    /* 0 = 空槽（支持 point_id == 0） */
    uint16_t pad;
} rtdbd_subtab_slot_t;

typedef struct {
    rtdbd_subtab_slot_t slots[RTDBD_SUBTAB_CAP];
    uint32_t count;
} rtdbd_subtab_t;

void rtdbd_subtab_init(rtdbd_subtab_t* t);
void rtdbd_subtab_clear(rtdbd_subtab_t* t);
bool rtdbd_subtab_has(const rtdbd_subtab_t* t, uint32_t point_id);
bool rtdbd_subtab_insert(rtdbd_subtab_t* t, uint32_t point_id);
void rtdbd_subtab_remove(rtdbd_subtab_t* t, uint32_t point_id);
bool rtdbd_subtab_decide(rtdbd_subtab_t* t, uint32_t point_id, double value,
                         const indurtdb_meta_t* meta);
```

- 哈希：FNV-1a 对 4 字节 id；线性探测；`index = hash & (CAP-1)`。
- `remove`：先删条目，再重建整个表（≤1024 条，O(n)，避免墓碑/探测链断裂）。设计里“删除只发生在整表清空”不成立——`UNSUBSCRIBE` 仍要删单点。
- `decide`：若条目不存在则插入并返回 `true`（首值必发）；否则复用 `rbe.c` 的死区/EURange 判定逻辑。

**TDD 步骤**

1. `test_rtdbd_core.cpp` 加直接编译 `subtab.c` 的纯逻辑用例（CMake 给该目标加 `${PROJECT_SOURCE_DIR}/rtdbd/src/subtab.c` 与 include 目录）：

   - `SubtabCollision`：插入 `1` 与 `1 + RTDBD_SUBTAB_CAP`（>max_points 但纯结构测试允许），都能命中。
   - `SubtabPointIdZero`：插入 0 不丢。
   - `SubtabClear`：清空后全部不命中、`count == 0`。
   - `SubtabFirstValueAndDeadband`：首值 true；死区内 false；越界 true。
2. 构建运行，期望红（文件不存在/符号未定义）。

### 任务 4：`SET_SUBS` 批量订阅与快照

**文件**

- `rtdbd/src/rtdbd.c`
- `tests/integration/test_rtdbd_notify.cpp`
- `tests/integration/test_rtdbd_backpressure.cpp`

**协议**

```
请求:  u32 count; u32 ids[count]      (payload_len == 4 + 4*count)
响应:  status=OK, 空负载
随后:  按 id 升序推送 count 帧 NOTIFY（当前值快照，含 quality）
```

**实现要点**

1. 新增 `do_set_subs(rtdbd_ctx_t* cx)`，加入 `kOps`（opcode 18）。
2. 静态缓冲：`static uint32_t g_set_subs_ids[RTDBD_SUB_MAX];`（4 KB BSS，单线程）。
3. 读取与边界：
   - `payload_len < 4` 或 `> 4 + 4*RTDBD_SUB_MAX` → 关闭连接（无法安全 drain）。
   - `count > cx->max_subs` → 读掉 payload（或直接关闭），返回 `BAD_REQUEST`。
   - 逐条读取到 `g_set_subs_ids`。
4. 整组校验（全部通过才生效）：
   - `id >= hdr->max_points` → `NOT_FOUND`；
   - `indurtdb_h_read_point(cx->h, id, &p)` 失败或 `p.name[0] == '\0'` → `NOT_FOUND`；
   - `!irt_policy_allows(cx->policy, cx->uid, p.partition, id)` → `DENIED`；
   - `!rtdbd_conf_partition_allowed(cx->conf, p.partition)` → `DENIED`；
   - 重复 id → `BAD_REQUEST`（O(n²)，n ≤1024，翻页频率下可接受）。
5. 生效：
   - `conn_discard_outq_soft(cx)`：只清 `outq_count/head/tail/sent`，**不**加 `notify_drop`、**不**调 `rtdbd_stats_note_error()`。
   - `cx->nsubs = 0; rtdbd_subtab_clear(&cx->sub);`
   - 对 ids 做升序排序（插入排序或 `qsort`），逐个 `conn_add_sub` + `rtdbd_subtab_insert`。
   - 逐个读点、构造 `rtdbd_notify_t`（`reserved[0]=quality`，数值类型填 `value_bits`，字符串类型 `value_bits=0`），`outq_push`。
6. `SUBSCRIBE` / `UNSUBSCRIBE`：
   - `SUBSCRIBE` 复用同一套 `sub_validate_one()` 校验；上限用 `cx->max_subs`。
   - `UNSUBSCRIBE` 同时删 `subs[]` 与 `subtab`。
7. 响应先于快照：`handle_request` 的 `send_all(resp)` 在 `outq_flush` 之前，无需额外处理。

**TDD 步骤**

1. `test_rtdbd_notify.cpp` 加：
   - `SetSubsSnapshotThree`：3 点，发 `{10,11,12}`，收到 3 帧、顺序升序、quality 与 GET 一致。
   - `SetSubsReplacesOldSet`：先 `{10,11}`，再 `{12}`，只收到 1 帧；写 10 不再通知。
   - `SetSubsRejectsUnregistered`：未注册 id → `NOT_FOUND`，旧订阅不变（旧点仍收通知）。
   - `SetSubsRejectsDenied`：policy 拒绝的 id → `DENIED`。
   - `SetSubsRejectsDuplicate`：`{10,10}` → `BAD_REQUEST`。
   - `SetSubsEmptyClears`：`{}` → OK，之后无通知。
   - `SetSubsSnapshot500Fits`：500 点快照全部收到，`health.notify_drop == 0`。
   - `SetSubsReplaceDoesNotCountDrop`：连续 20 次整页替换，`notify_drop` 不增长。
2. `test_rtdbd_backpressure.cpp` 保持原用例；确认 4000 写仍会 drop（队列 1024 + socket 缓冲）。
3. 运行，期望红。
4. 实现 handler、校验、快照；更新 `kOps`。
5. 重跑 `test_rtdbd_notify`、`test_rtdbd_backpressure`、`test_rtdbd_proto_v3` 与全套。
6. 提交：`feat(rtdbd): 新增 SET_SUBS 批量订阅与快照`。

**验收**：快照完整、顺序稳定、替换不产生 `notify_drop`；失败请求不改变旧订阅。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| `g_conns` BSS 增至 ~8.7 MB | 文档记录 RSS；SylixOS 部署前确认内存预算；不引入堆 |
| 500 快照 + 并发写超过 1024 队列 | 快照按 id 升序入队；仍满时靠 `notify_drop` 暴露，前端重同步 |
| 帧率估算错误（每客户端 500 帧/s） | 负载脚本按“每点 1 次/s”生成写，不制造 1M 帧/s 的假场景 |
| 超时测试墙钟抖动 | 断言留 3× 余量；扫描固定在 1 s 边界 |
| 旧段导致测试 attach 失败 | 任务 0 清理夹具；升级文档明确删段 |
| 分页响应形状变化 | 无分页参数保持旧数组；前端只走带参数路径 |
| `SET_SUBS` 恶意超大 payload | 超过 `4+4*1024` 直接断连；`count` 超限拒绝 |
| 字符串点位快照无 `value_str` | 快照 `value_bits=0`，前端对字符串仍走 `GET /api/points/{id}`（仅字符串，数量可控） |
