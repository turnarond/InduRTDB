当然可以。以下是为 **InduRTDB（Industrial Real-Time Database）** 项目量身定制的 **C++ 编码规范**，聚焦于**嵌入式、实时性、可靠性、可维护性**四大核心诉求，适用于 Linux/SylixOS 等工业边缘环境。

# **InduRTDB C++ 编码规范**  
**版本：1.0**  
**适用语言：C++17（禁用部分特性）**  
**目标平台：Linux / SylixOS（ARM Cortex-A）**

---

## 1. 总体原则

> **“确定性 > 抽象，可靠性 > 便利，简洁 > 智巧”**

- ✅ **零动态内存分配**：禁止 `new`/`delete`、`malloc`/`free`、STL 容器（`vector`, `map` 等）；
- ✅ **零异常**：编译选项 `-fno-exceptions -fno-rtti`；
- ✅ **零系统调用阻塞**：所有 IPC 必须非阻塞或带超时；
- ✅ **确定性执行时间**：避免虚函数、递归、复杂模板展开；
- ✅ **跨平台兼容**：不依赖 glibc 特有扩展。

---

## 2. 语言特性限制

| 特性 | 允许 | 说明 |
|------|------|------|
| **C++17 核心** | ✅ | `auto`, `constexpr`, `std::optional`（仅头文件） |
| **异常 (Exceptions)** | ❌ | 必须 `-fno-exceptions` |
| **RTTI** | ❌ | 必须 `-fno-rtti` |
| **动态内存** | ❌ | 禁止 `new`/`delete`、`std::make_shared` |
| **STL 容器** | ❌ | 禁止 `vector`, `map`, `string`（可用 `char[]`） |
| **虚函数** | ⚠️ 仅 OSAL 接口 | Core 层禁止 |
| **Lambda** | ✅ | 仅用于回调注册（不可捕获 `this` 跨线程） |
| **模板** | ✅ | 仅用于类型安全封装（如 `write<T>`） |

> 📌 **替代方案**：
> - 用 **定长数组 + 索引** 替代 `vector`；
> - 用 **C 风格字符串 (`char[64]`)** 替代 `std::string`；
> - 用 **返回 `bool` + 输出参数** 替代异常。

## 3. 命名规范

| 类型 | 规则 | 示例 |
|------|------|------|
| **类/结构体** | `UpperCamelCase` | `PointManager`, `InduRTDBHeader` |
| **函数/方法** | `lower_snake_case` | `write_point()`, `update_heartbeat()` |
| **变量** | `lower_snake_case` | `max_points`, `timestamp_ns` |
| **常量** | `UPPER_SNAKE_CASE` | `MAX_POINTS`, `QUALITY_GOOD` |
| **宏** | `UPPER_SNAKE_CASE` | `INDURTDB_VERSION`, `ALIGN_AS(x)` |
| **成员变量** | `trailing_underscore_` | `header_`, `points_`, `osal_` |

> ✅ **禁止匈牙利命名法**（如 `pszName`）。

## 4. 内存与资源管理

### 4.1 共享内存
- 所有共享内存结构体必须为 **POD（Plain Old Data）**；
- 禁止包含指针、虚表、引用；
- 使用 `static_assert` 验证大小与对齐：

```cpp
static_assert(std::is_pod_v<InduRTDBHeader>, "Header must be POD");
static_assert(sizeof(PointData) == 128, "PointData layout changed!");
```

### 4.2 RAII 封装
- 文件描述符、socket 必须用 RAII 包装：

```cpp
class unique_fd {
public:
    explicit unique_fd(int fd) : fd_(fd) {}
    ~unique_fd() { if (fd_ >= 0) ::close(fd_); }
    // ... 移动语义
private:
    int fd_;
};
```

### 4.3 对齐要求
- 共享内存结构体必须显式对齐：

```cpp
struct PointData {
    // ...
} __attribute__((packed, aligned(64)));
```

## 5. 并发与线程安全

### 5.1 原子操作
- 使用 `__atomic_*` 内建函数（GCC）或 `std::atomic`（仅简单 load/store）；
- Seqlock 序列号必须为 `uint64_t`，避免 ABA 问题。

### 5.2 锁策略
- **读路径无锁**（Seqlock 或只读）；
- **写路径**：优先 Seqlock，次选 robust mutex；
- 禁止在锁内调用外部回调。

### 5.3 线程亲和性
- 控制逻辑线程应绑定到特定 CPU 核（通过 OSAL）：

```cpp
osal->threading()->set_affinity(core_id);
```

## 6. 错误处理

### 6.1 返回码 vs 异常
- **全部使用返回码**（`bool` 或 `enum class Status`）；
- 错误信息通过日志输出，不通过返回值传递。

```cpp
enum class Status {
    OK,
    INVALID_ID,
    TIMEOUT,
    IO_ERROR
};

Status write(PointId id, double val);
```

### 6.2 日志规范
- 使用轻量级日志宏（非 syslog，除非部署要求）：

```cpp
#define INDURTDB_LOG(level, fmt, ...) \
    do { \
        if (g_log_level >= level) \
            fprintf(stderr, "[InduRTDB][%s] " fmt "\n", #level, ##__VA_ARGS__); \
    } while(0)

// 使用
INDURTDB_LOG(ERROR, "Point ID %u out of range", id);
```

- **发布版可关闭日志**（`-DINDURTDB_DISABLE_LOG`）。

## 7. 文件与目录结构

### 7.1 头文件
- 所有公共 API 放在 `include/indurtdb.hpp`；
- 内部头文件放 `src/core/` 下，不安装；
- 头文件必须自包含（可单独 include）。

### 7.2 源文件
- 每个 `.cpp` 文件 ≤ 500 行；
- 单一职责：`point_manager.cpp` 只实现 `PointManager`。

### 7.3 注释
- **Doxygen 风格**，覆盖所有 public API；
- 关键算法必须注释原理（如 Seqlock）；

```cpp
/**
 * @brief Write a value to a point (thread-safe)
 * @param id Point identifier (0 <= id < max_points)
 * @param value Value to write
 * @return true on success, false if id is invalid
 * @note Uses Seqlock for lock-free reads
 */
template<typename T>
bool write(PointId id, const T& value);
```

## 8. 构建与编译

### 8.1 编译选项（GCC）
```bash
-O2 -g -Wall -Wextra -Werror \
-fno-exceptions -fno-rtti \
-fno-asynchronous-unwind-tables \
-ffunction-sections -fdata-sections \
-march=armv7-a -mtune=cortex-a9 \
-D_GNU_SOURCE
```

### 8.2 链接
- 静态链接（默认），生成 `.a`；
- 动态链接需明确启用（`-DBUILD_SHARED_LIBS=ON`）。

### 8.3 依赖
- **零第三方依赖**（YAML 解析可选，通过 `-DWITH_YAML=OFF` 禁用）；
- 测试依赖：Google Test（仅测试构建）。

## 10. 禁止事项清单（红线）

❌ 禁止以下行为，代码审查直接拒绝：
- 使用 `std::vector`, `std::string`, `std::shared_ptr`；
- 在共享内存中存储指针或虚函数表；
- 在头文件中使用 `using namespace std;`；
- 使用 `printf`/`cout`（必须用日志宏）；
- 无 `static_assert` 验证共享内存布局；
- 未处理的系统调用返回值（如 `shm_open`）。
