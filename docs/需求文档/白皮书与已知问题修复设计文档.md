## 一、已知问题修复

### 1.1 版本号不一致(2.0.0 vs 2.1.0)

- **现状**: `include/indurtdb.hpp` 中 `INDURTDB_VERSION_MAJOR/MINOR/PATCH/STRING` 为 2.0.0;`CMakeLists.txt`、`README.md`、`VERSION` 文件均为 2.1.0
- **修复**: 头文件宏统一为 2.1.0
- **TDD**: 新增 `tests/unit/test_version.cpp`,断言四个版本宏为 2.1.0 → 变红 → 修宏 → 变绿

### 1.2 tests/ 子目录死代码(引用不存在的 target)

- **现状**: 根 `CMakeLists.txt` 用 `file(GLOB_RECURSE "tests/*.cpp")` 将全部测试合并为单一 `indurtdb_tests`;`tests/unit/CMakeLists.txt` 引用不存在的 target(`indurtdb_core`/`indurtdb_osal`),`tests/integration/` 与 `tests/performance/` 的 CMakeLists 为空壳 TODO;ctest 仅注册 1 条
- **修复(真正修复而非删除)**: 
  - 根 CMakeLists 移除 tests GLOB,`add_subdirectory(tests)`
  - `tests/unit/CMakeLists.txt` 用 foreach 为每个 `test_xxx.cpp` 生成独立 target(链接 `indurtdb` + GTest)
  - `tests/integration/CMakeLists.txt` 注册 `test_multi_process` 独立 target
  - `tests/performance/` 保留空壳注明 TODO
- **效果**: ctest 注册 8+ 条测试,支持 `make test_seqlock` 单独构建运行(开发者体验)

### 1.3 核心组件单元测试缺口

- **现状**: 编码规范要求"每个 .cpp 有对应 test_xxx.cpp",但 `PointManager`、`SharedMemorySegment`、`ConfigLoader` 无直接单元测试
- **修复**: 新增 `test_point_manager.cpp`、`test_shared_memory_segment.cpp`、`test_config_loader.cpp`
- **测试辅助**: `osal::ITime` 用 FakeTime 测试辅助(测试代码不受 Core 零虚约束);共享内存段用唯一名字(pid)避免冲突
- **TDD 验证**: 写测试 → 绿 → 临时注入 bug 验证变红 → 恢复 → 绿(证明测试真实有效)
